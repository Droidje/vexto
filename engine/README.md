# engine: локальный quality profile

Для успешно определённого русского языка действует [маршрут GigaAM без Whisper](../docs/architecture/russian-gigaam-only.md).


По умолчанию выбран **Авто**: после декодирования записи длиннее пяти минут получают быстрый профиль; остальные — качественный. Настройка фиксируется на всё задание.

- **QUALITY:** GTCRN-копия для ASR; GigaAM RNNT и/или Whisper Large по языку; Nemotron, ERes2Net, метаданные Emo.
- **FAST:** оригинал без GTCRN; GigaAM CTC и/или Whisper Small по языку; Nemotron и ERes2Net сохраняются. Основной диалог публикуется до фоновых эмоций. Автоматического RNNT/Large-уточнения нет.

Успешно определённый `ru` запускает только GigaAM; `be` и сбой LID — обе ASR; остальные определённые языки — Whisper-only. Короткий Whisper tiny LID остаётся отдельным этапом по первым 30 с оригинала. SDK проверяет целого доступного кандидата; Qwen сравнивает только различающиеся пары, а имена определяет лишь при свидетельствах. Поэтому `localLlmUsed` может быть false у готового текста. Резюме и название — отдельные LLM-операции, не перезапись стенограммы.

Стадии допускаются общим CPU/RAM-планировщиком, а не строго последовательно. Внутри стадии модель живёт на постоянном обработчике: FAST GigaAM — 1 × 2 потока, Whisper Small — 1 × 4; QUALITY GigaAM — до 2 × 2, Large — 1 × 4. Тяжёлые Large/Qwen эксклюзивны. Тайминги итоговых реплик задаёт Nemotron; `ChunkPlan` строится по его интервалам с контекстом и omittedRanges. Отдельный Silero VAD относится к прежнему движку, не обязательной стадии этого ядра. Длинные паузы перед Nemotron могут компактироваться с сохранением исходной шкалы. [Текущая архитектура](../docs/ARCHITECTURE.md), [очереди](../docs/architecture/queued-audio-modes.md).

Подготовка аудио пишет сразу в канонический WAV, пропускает ненужный ресэмплинг 16 кГц и использует пакетный SIMD FIR для остальных частот. Память ограничена буферами; временная шкала сохраняется. [Архитектура и короткие замеры](../docs/architecture/audio-preparation.md).

## Подготовка и сборка

Требуются JDK17, SDK35/BuildTools35.0.0, NDKr28c, CMake3.22.1+ и Ninja. Веса и native binaries не хранятся в Git. Базовый APK содержит код, лицензии и проверяемый manifest. В именованных релизах веса поставляются в подписанных split APK. Текущий manifest закрепляет **3 775 095 943 байта**. Уже установленный пакет `quality-508faa2fac36` определитель языка не содержит. Vexto материализует их в приватное хранилище перед первой расшифровкой. Команды ниже описывают отдельную подготовку весов для разработческих сборок.

```sh
bash scripts/fetch_models.sh --aar-only
python scripts/prepare_emotion_runtime.py
# Подготовленные pinned native sources, затем обе ABI; инструкции и source pins:
# tools/native/README.md; scripts/build_native_runtime.py --help
python scripts/prepare_quality_models.py --source-dir <готовые-модели> --download
bash ./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
# Один раз запустите установленное приложение, затем:
python scripts/install_quality_pack.py --serial <device> --pack-dir .agents/work/quality-pack/quality-370552aab094
```

`--source-dir` может содержать только готовые файлы (например, `nemotron/Nemotron-3-Diarization.f32.gguf`); при `--download` остальные веса берутся по закреплённым ссылкам. Определитель языка (`lid_encoder`, `lid_decoder`) ссылки не имеет: `python scripts/prepare_lid_models.py --work-dir <кеш-tiny> --output-dir <готовые-модели>/lid` скачивает закреплённую пару Whisper tiny, проверяет её SHA256, выполняет срез через `tools/benchmarks/distill_whisper_lid.py` и сверяет оба результата с manifest. Для существующих исходников есть `--source-dir <пара-tiny>`, исключающий скачивание. Это преобразование весов, без инференса.

На Linux x86_64 с CPython 3.12 `bash scripts/prepare_release_models.sh <новая-временная-папка>` готовит и Nemotron F32, и LID перед сборкой полного пакета. Зависимости установлены в отдельный venv и закреплены wheel-хэшами; файлы моделей не добавляются в Git. Происхождение LID записывается в `lid-preparation.json` рядом с преобразованными файлами.

F32 Nemotron собирается из оригинального pinned `.nemo` через `scripts/convert_nemotron_fullprecision.py`; его нельзя скачать по выдуманной ссылке или восстановить из Q8. См. [рецепт конвертации](../docs/research/nemotron-android.md). `--sources-json` provisioner принимает локальный JSON `model_id → filename`, который следует хранить в `.agents/local/`. Все файлы проверяются по размерам и SHA256 до установки и при подготовке сессии. Сам инференс работает без сети.

`-PvextoNdkPath=<path>` и `-PvextoCmakeVersion=<version>` позволяют использовать существующие инструменты без общих машинных путей. `-PvextoSkipNative=true` предназначен для JVM-тестов, а не поставки приложения. Обычная сборка останавливается, если отсутствуют обязательные native CLI для выбранных ABI.

## Поведение

Каждая тяжёлая стадия работает в свежем `:inference` процессе. После ответа клиент ждёт смерти конкретного Binder и только затем запускает следующую модель. Определитель языка этому правилу не следует: второй worker запустить нельзя, поэтому sherpa `SpokenLanguageIdentification` работает в процессе приложения, пока `:inference` считает Nemotron. Его ~22 МиБ весов входят в тот же UID RSS. Время языка пишется в `stageMs` отдельно и пересекается с диаризацией; на экране в этот момент остаётся этап «Разделяю голоса». Native CLI берутся исключительно из installer-extracted `nativeLibraryDir`; загруженные исполняемые файлы не запускаются. Поддерживаются ARM64 и x86_64; факт сборки ARM64 не равен запуску на телефоне.

Исходный mono PCM16/16k WAV сохраняется. GTCRN делает отдельную ASR-копию и восстанавливает её число отсчётов; `alignmentVerified=false` явно означает, что акустическая задержка не проверена. Nemotron и Emo получают оригинал. Общий план фрагментов до10с использует тихие границы, сохраняет каждый отсчёт ровно один раз и даёт обоим ASR одинаковый WAV/SHA. Whisper использует 512 кадров контекста (10,24 с) для общего плана до 10 с, чтобы сократить расход памяти при сравнении. Непрерывная речь на границе может пострадать; перекрывающиеся ASR-окна пока не реализованы.

Для выбора ASR Qwen возвращает только `select_asr_variant(chunk_id, source)`. Ядро проверяет schema, identity и SHA, затем копирует байты сохранённого кандидата. Оба оригинала, native tokens/timestamps и модельный manifest остаются в `filesDir/inference/jobs/<id>`. Решения имеют статусы `SELECTED_BY_LLM`, `ONE_AVAILABLE`, `UNRESOLVED`. При последнем GigaAM является только техническим вариантом отображения; это не победа в качестве, оба результата сохранены. Способность Qwen выбирать более точный текст без аудио ещё не доказана.

Базовый полный GigaAM-текст сохраняется до Whisper/LLM. Финальный текст заменяет только собственную неизменённую базовую копию; импорт и ручные изменения сохраняют приоритет. Приложение остаётся полностью локальным. Эмоции сохраняются в отдельном `emotion.json` и в вероятностях соответствующей реплики, не меняют текст и не являются достоверным определением чувств человека. Автоматического удаления архивов jobs пока нет: их жизненный цикл следует связать с удалением записи до длительного продуктового использования.

Наблюдаемый суммарный RSS UI+worker+native child плюс резерв128MiB ограничивается watchdog бюджетом2 000 000 000 байт. ОС Android исключена. Sampling100мс не является жёсткой гарантией для кратких всплесков аллокатора. При отказе сохраняются готовые оригиналы и явные предупреждения; модели не подменяются незаметно более лёгкими.

## API и проверки

Публичный `ReflectEngine.Listener` и экспорт `Transcript` сохранены. `DetailedListener.onCoreReady` позволяет сохранить ранний полный результат. В `ProcessingStats` добавлены `artifactDirectory`, `warnings`, `complete` (покрытие фрагментов), `fullProfileCompleted`, `selectionResolved`. Параметры `punctuation`/`speakerCount` оставлены ради совместимости: текст больше не переписывается пунктуатором, Nemotron считает спикеров автоматически (неподдержанный фиксированный count отмечается предупреждением).

При публикации промежуточного и финального результата в интерфейсе интервалы Nemotron без распознанного текста пропускаются: они не блокируют сохранение остальных реплик. Непустой текст, таймкоды, спикеры и эмоции переносятся без изменений; полные исходные интервалы остаются в артефактах движка и готовом чекпоинте. Если все интервалы пустые, приложение сообщает, что речь не распознана. Повторный запуск того же завершённого задания берёт результат из `finished.checkpoint.json`, без повторного инференса.

```sh
bash scripts/fetch_models.sh --aar-only
bash ./gradlew -PvextoSkipNative=true :engine:testDebugUnitTest
python -m unittest discover -s tools/benchmarks/tests -v
```

Debug-only `QualityEvalActivity`: положите WAV не длиннее 6 минут 40 секунд в `<app-external-files>/eval/input.wav`, запустите `adb shell am start -n com.vexto.reflect/com.vexto.engine.eval.QualityEvalActivity`; результаты появятся в `quality-eval/`, подробные артефакты — в приватном job. `--es mode native-help` проверяет упаковку CLI. Для сравнения точности используются фрагменты 20–40 с, а не длинные бенчмарки.

[Архитектурное решение](../docs/architecture/quality-engine.md), [исторические замеры старого движка](../docs/research/legacy-engine.md), [исследования моделей](../docs/research/pipeline-2gb.md).

Отдельный этап ERes2Net вычисляет голосовые признаки из оригинального аудио и интервалов Nemotron. Android сравнивает только признаки с совпадающими checkpoint, версией обработки и размерностью. При уверенном совпадении профили используют один глобальный UUID. Явное назначение пользователя сохраняется при замене промежуточного текста финальным. [Локальные профили и правило сопоставления](../docs/local-architecture.md).

Для voiceprint больше не создаётся полная временная PCM-копия. Энергии кадров считаются потоково буфером64KiB; короткие окна читаются из исходного WAV через заимствованный `PcmAudio`. Его закрытие сохраняет WAV. Прежние декодированные временные PCM остаются собственными файлами и удаляются при закрытии. AGC, координаты окон и fingerprint голосовых профилей сохранены.

## Проверяемые выходные данные и быстрые прогоны

После завершения Android сам сохраняет `transcript.json` по четырёхпольному образцу презентации, `transcript.metadata.json` с эмоциями и `completion.json` schemaVersion4. RAW GigaAM/Whisper и точная выбранная копия остаются отдельными файлами. Отчёт различает покрытие аудио, подтверждённый выбор LLM и успешность всей связки: fallback и пропущенные фрагменты больше не считаются полным успехом.

Прогресс приходит после каждого готового ASR/LLM фрагмента. Исправлены Unicode-пробелы и неверные/отсутствующие таймкоды при сборке, а также хвосты1–15samples у границы чанка. Время в миллисекундах ограничивается сверху округлением; исходные sample endpoints остаются точными.

CI запускает Python-тесты, Android JVM-тесты, lint и проверочную сборку. Для PR в `main` и публикаций CI также собирает полный нативный APK. Инференс и оценку качества запускают отдельно с офлайн-пакетом моделей.

Перед передачей единого офлайн-APK проверяйте весь комплект командой `python3 scripts/verify_android_apk.py <путь-к-apk> --require-models`. Она сверяет SHA256 и размер всех встроенных FAST/QUALITY-моделей, overlap и RUPunct, наличие нативного runtime обеих архитектур и целостность ZIP. Без флага проверяется базовый APK с overlap и RUPunct, до добавления большого комплекта моделей. Эта проверка состава не заменяет установку и запуск на устройстве.

Для SDK-пробы с полностью отключённой сетью (Python3.12+, установленный debug APK и офлайн-пакет):

```sh
python tools/benchmarks/probe_quality_apk.py --serial <device> --package <debug-application-id> --input <короткий-аудиофайл> --output-dir .agents/work/<новый-run>
python tools/benchmarks/verify_quality_job.py --job-dir .agents/work/<run>/<job-id> --output .agents/work/<run>/verification.json
```

Проба принимает запись до40с, создаёт отдельный каталог, восстанавливает прежнее состояние сети и забирает артефакты SDK. Проверка SHA/полноты файла не выполняет инференс на компьютере. Реальная оценка точности ASR/диаризации проводится отдельно с эталоном; прохождение структурной проверки не является WER/DER.

Для скорости повторная проверка3.3GBвесов кешируется только в памяти процесса, с точным манифестом и идентичностью/размером/временем изменения всех файлов. Первичная SHA256-проверка сохранена. DFT/mel таблицы Emo переиспользуются; Qwen не выполняет лишний стартовый warmup на каждом фрагменте. Эффект оценивается по `stageMs` и `modelVerificationReused` в отчёте, а не по размеру модели.

Qwen получает оба полных ASR-варианта и возвращает только JSON-строку `"gigaam"` или `"whisper"`. SDK связывает этот ответ с текущим фрагментом и сохраняет трёхпольный `bound-tool-call.json`; ядро проверяет идентичность и SHA и копирует исходный вариант целиком. `scoped_source_v1` сохраняет отдельные SHA stdout и вызова. `verify_quality_job.py` проверяет оба; старые результаты `tool_json_v1` также поддерживаются. Лимит ответа уменьшен до16токенов; текст кандидатов не усекается.


### WAV-фрагменты по требованию

`ChunkPlan` хранит координаты и SHA точного WAV, но не создаёт полную дополнительную копию записи. Каждый активный обработчик материализует свой фрагмент перед GigaAM/Whisper и освобождает его после завершения вызова. Существовавший корректный фрагмент после аварийного завершения можно переиспользовать без перезаписи и сохранить для диагностики. Неподходящий путь, symlink или неверный SHA отклоняются.

При успешно завершившейся обработке сохраняются исходный PCM WAV, ASR-копия и все исходные результаты моделей. В качественном режиме остаются оригинал и очищенная копия плюс до двух активных WAV-чанков по 30 секунд. В быстром режиме очищенная копия не создаётся. Малые внутренние окна Whisper временно сохраняются в собственном каталоге чанка. `chunk-storage.json` позволяет независимо проверить SHA отсутствующих чанков по исходной ASR-копии, без повторного инференса. Исходное аудио и распознанный текст сохраняются; исключённые из распознавания интервалы тишины явно перечислены в плане, sample endpoints не сдвигаются.


`transcript.json` и экспорт приложения показывают базовую запись фонетических пауз (`PhoneticSurface`): ə, ɐ, ɜ, ˀ → э, ɯ → м, отдельный (ɥ) → «вдох», `#пеньк-пеньк#` → «пеньк пеньк». `core.json`, метаданные и сохранённая расшифровка оставляют исходные знаки.

Таймкоды экспортируемых реплик опираются на непрерывные интервалы Nemotron: привязанные слова ограничиваются выбранным интервалом, а раздельные интервалы одного говорящего не объединяются через паузу. Когда словарные времена ASR непригодны, оценочные метки распределяются только по участкам обнаруженной речи (по всему фрагменту, если таких участков нет). Непривязанные слова сохраняются под `speaker_unknown`, исходный текст и времена ASR остаются в артефактах. Строки JSON с одним спикером на реплику не заменяют исходные интервалы диаризации с перекрытиями.

На 30-секундном Pears04 повторный импорт и экспорт через Android снизили DER строк JSON с 29,34% до 15,30% (без исключения границ, с учётом перекрытий). Исходный Nemotron: 11,15% в обоих прогонах. Экспортированный текст совпал посимвольно, WER остался 27,38%. Это сравнение одного размеченного фрагмента.

Автоимена спикеров включены в обоих режимах: максимум один дополнительный запрос к уже загруженной Qwen, до 10 секунд; без свидетельств в тексте запроса нет. Имена сохраняются как метаданные и не меняют строгий JSON задания. [Ограничения и архитектура](../docs/architecture/context-speaker-names.md).

В FAST готовность основного диалога отделена от фоновых эмоций: CoreReady(finalText=true) доступен до Emo, Done — после дополнения метаданных. [Архитектура фоновых эмоций](../docs/architecture/background-fast-emotions.md).

Оптимизированный путь: [адаптивное ядро и общий бюджет](../docs/architecture/adaptive-audio-core.md). ASR RAW сохраняются, итоговый текст берётся из выбранного целого кандидата. В режиме FAST сложные чанки проходят тяжёлые ASR; файлы моделей извлекаются из уже установленного офлайн-пакета, сетевых загрузок нет.

FAST выполняет один проход CTC + Whisper Small, затем Qwen выбирает исходный кандидат; автоматический RNNT/Large отключён. Whisper использует 4 CPU-потока и не делает temperature fallback. [Актуальная схема FAST](../docs/architecture/fast-pipeline.md).
