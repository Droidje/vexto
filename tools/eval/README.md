# Оценка качества расшифровки

`score.py` сравнивает JSON-экспорт Reflect с эталонной разметкой в том же формате, что требует заказчик. Зависимостей нет, нужен Python 3.9+.

```bash
python3 tools/eval/score.py eval/ref eval/hyp --json eval/metrics.json
```

Файлы сопоставляются по имени: `eval/ref/dialog1.json` и `eval/hyp/dialog1.json`. Если рядом с расшифровкой лежит `dialog1.stats.json` с полями `processing_ms` и `audio_ms`, в отчёт попадает RTF. Код выхода 1 означает, что хотя бы один файл не найден или не прошёл проверку схемы.

| Метрика | Что показывает | Какой критерий заказчика |
|---|---|---|
| WER | ошибки слов по всему тексту, без учёта спикеров | точность транскрибации, 40 |
| cpWER | ошибки слов при сопоставлении текста по спикерам | транскрибация и диаризация вместе |
| DER | доля времени с неверным спикером, пропуском или лишней речью, кадры по 10 мс | точность диаризации, 25 |
| границы | средняя ошибка начала и конца реплики в мс | точность временных меток, 10 |
| RTF | время обработки к длительности записи | скорость, 10 |

Нормализация перед WER: нижний регистр, «ё» заменяется на «е», пунктуация убирается. Как нормализует заказчик, пока неизвестно (вопрос в [hackathon-2026-11.md](../../docs/hackathon-2026-11.md)). Номера спикеров сопоставляются перебором по наибольшему совпадению, поэтому `speaker_1` в расшифровке не обязан совпадать с `speaker_1` в эталоне.
