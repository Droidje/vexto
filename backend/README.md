# Vexto API

FastAPI хранит исходные аудиофайлы и данные записей. SQLite хранит метаданные, версии расшифровок, справочник спикеров и связи локальных меток с глобальными спикерами. Обработка аудио выполняется отдельно. Готовую расшифровку можно загрузить через API или импортировать из Android.

## Запуск из корня репозитория

Требуется Python 3.11 или новее. Создайте окружение и установите зависимости.

```sh
python3 -m venv backend/.venv
. backend/.venv/bin/activate
python -m pip install -r backend/requirements.txt
```

Для первого локального запуска создайте токен рабочего пространства. Команда сохраняет его в закрытый файл `backend/.env`. При повторном запуске существующий файл сохраняется.

```sh
if [ ! -e backend/.env ]; then
  (umask 077; python - <<'PY' > backend/.env
import json
import secrets

print("VEXTO_WORKSPACES='" + json.dumps({"local": secrets.token_urlsafe(32)}) + "'")
PY
  )
fi

set -a
. ./backend/.env
set +a
python -m uvicorn backend.api:create_app --factory --host 127.0.0.1 --port 8000 --no-access-log
```

Откройте Swagger UI на `http://127.0.0.1:8000/docs`. В Android debug-сборке для эмулятора укажите `http://10.0.2.2:8000` и токен из `backend/.env` в меню «Настройки» → «Подключение к серверу».

| Переменная | Назначение |
| --- | --- |
| `VEXTO_WORKSPACES` | JSON-объект вида `{"workspace-id":"bearer-token"}`. ID стабильный, токен уникальный, от 24 до 256 символов. Используйте секреты, сгенерированные криптографическим генератором. |
| `VEXTO_DATA_DIR` | Каталог данных, по умолчанию `backend/data`. Хранит SQLite, аудиофайлы и промежуточные загрузки. |
| `VEXTO_MAX_AUDIO_BYTES` | Лимит одного аудиофайла, по умолчанию 256 МиБ. |

Для внешнего доступа поднимите HTTPS на прокси и передайте токены через окружение сервиса. Рабочее пространство определяется токеном. После ротации токена сохраните прежний ID пространства, чтобы сохранить доступ к данным. Хранилище рассчитано на один экземпляр API на локальной файловой системе. Для согласованной резервной копии остановите экземпляр и скопируйте весь `VEXTO_DATA_DIR`.

## Контракт API

Ресурсы в `/v1` требуют заголовок `Authorization: Bearer …`. `GET /healthz` служит для проверки запуска. Идентификаторы записей и глобальных спикеров имеют формат UUID.

| Метод и путь | Назначение |
| --- | --- |
| `PUT /v1/recordings/{id}/audio` | Загрузить исходные байты с `Content-Type: audio/…` или `application/octet-stream`. Повтор с теми же байтами безопасен, другое содержимое для того же UUID даёт `409`. |
| `GET /v1/recordings` и `GET /v1/recordings/{id}` | Получить список или карточку. Список поддерживает `limit` и `offset`. |
| `PUT /v1/recordings/{id}/metadata` | Обновить `title`, `duration_ms`, `recorded_at` в ISO 8601 с часовым поясом, `filename`, `mime_type` и необязательный объект `location` с `latitude` и `longitude`. |
| `GET /v1/recordings/{id}/audio` | Скачать исходный аудиофайл. |
| `DELETE /v1/recordings/{id}` | Удалить серверную запись, аудио, расшифровки и их связи. Поздняя повторная загрузка удалённого UUID получает `410`. |
| `PUT /v1/recordings/{id}/transcript` | Загрузить JSON с массивом реплик. Новое содержимое создаёт версию, повтор уже сохранённого содержимого возвращает его версию. |
| `POST /v1/recordings/{id}/transcript` | Сохранить автоматическую расшифровку, если запись ещё не расшифрована. При отличающейся текущей расшифровке API ответит `412`, повтор уже принятого результата вернёт текущую версию. У `PUT` с заголовком `If-None-Match: *` те же условия. |
| `GET /v1/recordings/{id}/transcript` | Прочитать текущую расшифровку или выбрать версию через `?revision=N`. |
| `GET /v1/recordings/{id}/transcript/revisions` | Получить список версий и отметку текущей версии. |
| `GET /v1/speakers`, `POST /v1/speakers` | Получить справочник или создать спикера с именем `name`. При создании можно передать свой `id` для безопасного повтора. |
| `PATCH /v1/speakers/{id}`, `DELETE /v1/speakers/{id}` | Переименовать или удалить спикера. Удаление связанного спикера возвращает `409`. |
| `GET /v1/recordings/{id}/speaker-links` | Получить связи текущей версии как `{"links":{"speaker_1":"глобальный-UUID"}}`. Можно выбрать версию через `?revision=N`. |
| `PUT /v1/recordings/{id}/speaker-links/{local_id}` | Связать локальную метку со спикером через `{"speaker_id":"глобальный-UUID"}` или снять связь через `{"speaker_id":null}`. Кодируйте метку как сегмент URL. Передайте `X-Transcript-Revision` из ответа чтения, чтобы получить `409`, если активная версия успела измениться. |

Формат расшифровки совпадает с форматом импорта Android. Таймкоды задаются в целых миллисекундах. При записи реплики упорядочиваются по времени начала.

Если реплика была обработана GigaAM-Emo, в ней есть `emotion_probabilities`: четыре числа от 0 до 1 в порядке **нейтральная, радость, грусть, злость**. Сумма равна 1 с допуском 0,001. В старых расшифровках поля нет.

```json
{
  "transcript": [
    {
      "speaker_id": "speaker_1",
      "start_ms": 0,
      "end_ms": 1450,
      "text": "Начинаем обсуждение.",
      "emotion_probabilities": [0.8, 0.1, 0.07, 0.03]
    }
  ]
}
```

## Docker и проверки

После загрузки переменных окружения из раздела запуска выполните из корня репозитория:

```sh
docker build -f backend/Dockerfile -t vexto-api .
docker run --rm --env VEXTO_WORKSPACES -p 127.0.0.1:8000:8000 \
  -v vexto-api-data:/data vexto-api
```

Запуск интеграционных тестов:

```sh
python -m pip install -r backend/requirements-dev.txt
python -m unittest discover -s backend/tests -v
```
