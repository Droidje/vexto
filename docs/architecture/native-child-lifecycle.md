# Жизненный цикл нативных процессов

## Сбой параллельной обработки длинных записей

В FAST для новой записи длиннее пяти минут распознавание начинается до завершения диаризации. Обычный запуск Nemotron и постоянный процесс Whisper при этом принадлежат разным сервисам `:inferenceN`.

На release APK воспроизведён сбой с собственным синтетическим WAV длиной 310 секунд: Nemotron завершался с кодом 137 примерно через три секунды, затем Whisper — с тем же кодом примерно через 75 мс. Ограничение времени и увеличение памяти не устраняют эту причину. Отдельная трассировка `signal_generate`, отфильтрованная по SIGKILL и нативным исполняемым файлам Vexto, показала: первый сигнал Nemotron отправлял поток приложения `vexto-native-session`; отмена Whisper была следствием.

Очистка зарегистрированных процессов принимала отсутствие родителя в полном снимке `/proc` за смерть родителя. Полный снимок может пропускать живой ART-процесс release приложения: чтение его `stat`/`cmdline` ограничено иначе, чем чтение исполняемого дочернего процесса. Поэтому полнота такого снимка не является доказательством жизни или смерти владельца.

## Правила очистки

- Обычные и постоянные нативные вызовы публикуют активную аренду до записи общего регистра. При завершении удаляют только собственные аренды.
- Очистка не завершает процесс с активной арендой или живым родителем. Для родителя проверяются доступный UID из `status` и `kill(pid, 0)`, независимо от полноты снимка. Только `ESRCH` подтверждает отсутствие PID; `EPERM` и другие неопределённые ошибки не дают права завершить процесс.
- Для настоящего сироты сохраняются проверки UID, разрешённого исполняемого файла, времени старта ядра и точного пути из регистра. Совпадения одного PID недостаточно.
- Обычный запуск регистрирует только ожидаемый исполняемый файл, а не любой новый нативный процесс того же UID.
- `PDEATHSIG` и явное завершение собственного дочернего процесса остаются включены. Исправление не сериализует весь конвейер и не повышает бюджет памяти или таймауты.

Регрессии политики покрывает `NativeReaperPolicyTest`: живой родитель, отсутствующий в полном снимке; активный обычный вызов; настоящий сирота; повторное использование PID; другой UID и исполняемый файл. Проверка на устройстве должна использовать release APK и запись длиннее пяти минут: короткий FAST-прогон не включает параллельную ветку. Тишина в длинном тесте может быть сжата до завершения диаризации и не обеспечить пересечение стадий.

После исправления тот же release-сценарий с 310 секундами повторённой собственной синтетической речи прошёл обе ранее падавшие стадии: Nemotron — 29,9 секунды, Whisper — 72,2 секунды, все 11 кандидатов сохранены. Процессы действительно работали одновременно; раннего SIGKILL больше нет, наблюдаемый общий RSS на этих стадиях не превысил 867 МБ. Это проверка жизненного цикла, а не оценка точности на размеченном корпусе.
