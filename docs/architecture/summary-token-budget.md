# Токенизация и возобновление ИИ-резюме

Реализовано в ветке `feat/summary-token-budget`; после сравнения пользователь разрешил публикацию в dev. Измерения и ограничения: [отчёт](../research/summary-token-budget.md).

`TokenSummaryPlan` использует словарь установленной Qwen через её persistent worker. Системный промпт, экранирование ChatML, assistant-prefix и резерв 192 токенов ответа входят в проверку контекста 2048 токенов. Сам контекст, модель, sampling и предел ответа 640 байт не увеличены.

Исходный текст делится на наиболее длинные помещающиеся префиксы по границам слов. Worker проверяет границы от длинных к коротким: BPE не гарантирует монотонный рост числа токенов. Для очень длинного слова предусмотрена граница UTF-8 codepoint. 32 КБ — предел транспорта одного запроса, а не оценка доступных токенов. Затем целые промежуточные результаты в хронологическом порядке объединяются максимально вместительными группами. Один оставшийся результат переносится без генерации; если даже два полных результата не помещаются, возвращается ошибка вместо обрезания фактов. Финальный запрос генерации повторно проверяет точный бюджет.

Число будущих merge-вызовов зависит от длины ещё не полученных ответов. Прогресс сначала использует верхнюю оценку числа шагов, затем уточняет её после упаковки каждого уровня. Время — оценка по выполненным вызовам, не обещание длительности.

UI передаёт каталог `transcripts/<recording>.summary-work`. В нём хранятся только завершённые ответы, атомарно после `fsync`, с ключами по точному входу. Namespace включает нормализованную расшифровку, промпт, версию алгоритма и SHA установленной модели из pinned manifest. Ошибка и отмена не сохраняются. Повтор создаёт новый native worker, заново планирует запросы токенизатором и читает готовые ответы вместо повторного inference. KV-cache и незавершённая генерация не восстанавливаются.

При новой версии источника прежний namespace удаляется. При открытии удаляются незавершённые файлы, ответы старше семи дней и сверх 1024 последних файлов. Удаление разговора, записи и инвалидирование резюме после редактирования очищают соответствующий каталог. Старые завершённые резюме UI имеют другой fingerprint и не подменяют результаты нового алгоритма. Автоматические названия сохраняют прежнюю выборку контекста; их политика не меняется.

Проверки: `./gradlew :engine:testDebugUnitTest :app:testDebugUnitTest :app:lintDebug :app:assembleRelease`. Для Android необходимо пересобрать `llama` native runtime для ARM64, x86_64 и AVX2 перед APK: Kotlin использует новые операции `--count-tokens` и `--fit-prefix`.
