# Адаптивная локальная обработка аудио

## Инварианты

Android выполняет все вычисления офлайн. Python служит подготовке сборки. Вычисления моделей — C/C++ (GGML, sherpa/ONNX Runtime), Java/Kotlin управляют процессами. Nemotron остаётся единственным источником интервалов спикеров. LLM выбирает полный неизменяемый ASR-кандидат; RAW обоих источников и обоих проходов сохраняются. Ни суммаризация, ни переписывание текста не являются частью ASR.

## Стратегии

AUTO сохраняет порог >300000 мс → FAST. FAST сначала запускает GigaAM CTC INT8 и Whisper Small Q5_1 на одинаковых PCM-чанках. `refinement-plan.json` содержит причины повторного прохода: пустой/отсутствующий ответ, >18% лексического расхождения, расхождение чисел, подозрительные повторы/скорость текста, пересечение голосов ≥200мс. Только эти чанки получают GigaAM RNNT и Whisper Large. Неславянский маршрут уточняет только Whisper. Чанки, sample clock и аудиовход не меняются; профили моделей не подменяются внутри загруженного worker. Более тяжёлые результаты замещают вариант того же источника только после проверки SHA и входной идентичности.

QUALITY сохраняет полный проход RNNT + Large и GTCRN. Итоговый JSON использует выбранный SDK/Qwen вариант, без прежнего принудительного RAW GigaAM. Буквально одинаковые тексты дают EQUIVALENT, не считаются ответом LLM и обходят генерацию. Отказ/непоместившийся prompt остаётся явным UNRESOLVED с целым доступным оригиналом.

Оценка сложности — инженерная эвристика, а не откалиброванная вероятность ошибки. Совпадающие лёгкие модели могут ошибаться одинаково. На трудном файле возможен повторный проход всей речи, поэтому каскад не обещает фиксированного ускорения или нулевой потери качества. Другие лёгкие модели и Turbo пока не входят в пакет.

## Планирование и ресурсы

Процесс приложения допускает стадии через общий CPU/RAM бюджет: 4 потока и 1.65GB резерва под native/model-стадии. Остальное оставляется UI, сервисам и RSS-резерву. Native watchdog по-прежнему ограничивает наблюдаемую сумму RSS UID с прежним порогом 2GB и резервом128MiB; это наблюдаемый предел, не cgroup. При ошибке памяти допускаются последовательные повторные попытки с проверенными частичными результатами.

Каждый слот имеет отдельный Android Service/process. Lease освобождается после смерти точного Binder. Дети живого соседнего слота не являются orphan-процессами; PID, start ticks и executable продолжают проверяться. При неподтверждённом завершении слот закрывается для повторного использования.

Подготовка звука и диаризация независимы. Для Nemotron добавлен пинованный CPU-thread override; 2 потока оставляют место шумодаву или определению языка. Лёгкие ASR используют по одному постоянному обработчику ×2 потока, одновременно. Large Whisper и Qwen резервируют весь native-бюджет. Полная диаризация пока заканчивается перед построением ASR-плана; выдача стабильного префикса следующей стадии — отдельный следующий шаг, не заявленная готовая возможность.

## CPU, признаки, хранение

CI сохраняет baseline x86_64 и дополнительно собирает AVX2-компаньоны, включая отдельные SONAME зависимостей Nemotron. Baseline JNI-детектор проверяет CPUID + OSXSAVE/XCR0 до запуска AVX2. ARM64 не использует x86-инструкции. `GGML_NATIVE=OFF` остаётся правильным для кросс-компиляции.

Emo использует mixed-radix FFT400 вместо прямого DFT, без смены окна, reflection padding, mel-фильтров и clipping/log-нормализации. Суммы mel считаются только по ненулевому диапазону фильтра. Численный результат проверяется относительно прежнего frontend с допуском 2e-4 в log-mel; побитовая идентичность после изменения порядка вычислений не обещается.

Временные PCM WAV защищены межпроцессным lock. Один чанк переиспользуется обоими ASR; очистка допускается после появления обоих durable candidate refs. После сбоя исходный файл повторно проверяется по SHA. Индексы стадий и эмоций сохраняются максимум через 4 результата или 1с, а также на финише; RAW остаются durable по чанкам. После внезапного завершения непроиндексированный хвост пересчитывается.

Голосовой профиль использует не более32 чистых окон на человека, равномерно по его появлению, без наложений голосов. Это ограничивает стоимость долгих записей; влияние на межфайловое сопоставление ещё не измерено.

## Проверка

Проверены Kotlin/Java-компиляция, адресные JVM-проверки FFT, выбора ASR, каскада, CPU admission, артефактов и возобновления. CPUID JNI скомпилирован NDK r28c для ARM64 и x86_64. Пинованный thread override проверен на исходнике и повторной подготовке. Длинных прогонов, измеренного выигрыша RTF или DER/WER нового пути пока нет. F32 Nemotron остаётся стандартом; понижение точности требует отдельной короткой пробы, не включается вслепую.
