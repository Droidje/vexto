# Адаптивная локальная обработка аудио

> Актуализировано 8 ноября 2026: FAST — один лёгкий проход, русский после успешного LID — GigaAM-only. [Текущие маршруты](../ARCHITECTURE.md#языковые-маршруты), [результаты](../TEST_RESULTS.md).

## Инварианты

Android выполняет все вычисления офлайн. Python служит подготовке сборки. Вычисления моделей — C/C++ (GGML, sherpa/ONNX Runtime), Java/Kotlin управляют процессами. Nemotron остаётся единственным источником интервалов спикеров. LLM выбирает полный неизменяемый ASR-кандидат; RAW всех реально запущенных источников сохраняются; второго тяжёлого прохода FAST нет. Ни суммаризация, ни переписывание текста не являются частью ASR.

Перед вызовом Nemotron проверяется CLI-контракт реально установленного executable; старый runtime получает только прежние аргументы. Падение диаризации останавливает задание и допускает повтор, вместо завершённого JSON со всеми репликами `speaker_unknown`. [Причина регрессии и исправление совместимости](nemotron-cli-compatibility.md).

## Стратегии

AUTO: >300000 мс → FAST; иначе QUALITY. FAST использует CTC и/или Small, QUALITY — RNNT и/или Large и отдельную GTCRN-копию. Языковой маршрут определяет, какие ASR действительно запускаются. При русском успешно определённом LID Whisper ASR исключён; при `be`/сбое LID остаются обе модели; другие языки идут через Whisper.

Автоматический каскад уточнения по расхождениям отключён: `refinement-plan.json` пустой, старые refined-артефакты не меняют новый выбор. Класс планировщика уточнения и прежние проверки в коде не означают его вызов текущим `TranscriptionEngine`. SDK сохраняет целый проверенный вариант, совпадения дают EQUIVALENT, единственный кандидат — ONE_AVAILABLE; Qwen нужна только различающейся паре или контекстным именам.

Qwen работает с контекстом 1024; токеновый бюджет проверяет native tokenizer, транспортный предел 8 КиБ не является размером контекста. Отказ остаётся UNRESOLVED, кандидаты не обрезаются. [Native-контракт](audio-followup.md).

Whisper Base/Tiny и другие ASR остаются кандидатами исследования; размер файла сам по себе не доказывает выигрыш WER или скорости русского на Android. CTC и RNNT GigaAM используют общий класс Conformer-энкодеров, поэтому облегчение декодера не равно уменьшению всего энкодера. [Происхождение весов](../research/fast-asr-models.md).

## Планирование и ресурсы

Процесс приложения допускает стадии через общий CPU/RAM бюджет: 4 потока и 1.65GB резерва под native/model-стадии. Остальное оставляется UI, сервисам и RSS-резерву. Native watchdog по-прежнему ограничивает наблюдаемую сумму RSS UID с прежним порогом 2GB и резервом128MiB; это наблюдаемый предел, не cgroup. При ошибке памяти допускаются последовательные повторные попытки с проверенными частичными результатами. Потоковая стадия не повторяется под serial admission, пока ASR может ожидать её префикс: сначала закрываются обе очереди, затем повторяется диаризация/ASR по окончательному плану. Пик неудачной попытки остаётся в итоговом наблюдаемом максимуме.

Каждый слот имеет отдельный Android Service/process. Lease освобождается после смерти точного Binder. Дети живого соседнего слота не являются orphan-процессами; PID, start ticks и executable продолжают проверяться. При неподтверждённом завершении слот закрывается для повторного использования.

Независимые подготовительные стадии допускаются общим бюджетом. Для Nemotron добавлен пинованный CPU-thread override: обычный полный проход резервирует4потока, потоковый FAST —2, оставляя2потока ASR или определению языка. Шумодав и определение языка могут пересекаться; в обычном режиме Nemotron использует все ядра после освобождения их бюджета. FAST GigaAM использует один постоянный обработчик ×2 потока; Whisper Small — один ×4 и ждёт полный CPU-бюджет. Во время потокового Nemotron с двумя потоками может продвигаться GigaAM. Общее ограничение проверяется при допуске каждой стадии. Large Whisper и Qwen резервируют весь native-бюджет. Тяжёлый GigaAM использует до двух обработчиков×2потока; если остался один чанк — загружает одну модель с4потоками. Число загружаемых обработчиков не превышает число задач. Два Large запрещены; повторного тяжёлого FAST-прохода нет.

На новом FAST-задании длиннее5мин Nemotron публикует атомарный стабильный префикс RTTM: только завершённые V3-чанки без preview-flush, с дополнительным запасом1с. Ядро добавляет ещё2с и выдаёт полностью созревшие PCM-чанки двум ASR-очередям. Модель Nemotron и её память продолжаются одной сессией; независимых диаризаций нет. Опубликованные интервалы, ID и SHA чанков менять запрещено. Итоговый план проверяется на точное совпадение префикса; несовпадение закрывает streaming-очереди и запускает обычное завершение по окончательному плану с перепроверкой частичных RAW. Возобновляемые задания используют окончательный план. Отдельные streaming/recovery-пробы имеют свои ограничения; [статус функциональных проверок и остановленных проб](audio-followup.md).

## CPU, признаки, хранение

CI сохраняет baseline x86_64 и дополнительно собирает AVX2-компаньоны, включая отдельные SONAME зависимостей Nemotron. Baseline JNI-детектор проверяет CPUID + OSXSAVE/XCR0 до запуска AVX2. ARM64 не использует x86-инструкции. `GGML_NATIVE=OFF` остаётся правильным для кросс-компиляции.

Emo использует mixed-radix FFT400 вместо прямого DFT, без смены окна, reflection padding, mel-фильтров и clipping/log-нормализации. Суммы mel считаются только по ненулевому диапазону фильтра. Численный результат проверяется относительно прежнего frontend с допуском 2e-4 в log-mel; побитовая идентичность после изменения порядка вычислений не обещается.

Временные PCM WAV защищены межпроцессным lock, shared read lease удерживается до конца native-чтения. Один чанк переиспользуется обоими ASR; очистка допускается после появления обоих durable candidate refs. Кеш восстанавливаемых WAV стремится к пределу64MiB: неиспользуемые старые файлы удаляются, даже если второй ASR ещё не дошёл до них; активные lease не удаляются. При необходимости WAV создаётся заново из неизменяемого оригинала. После сбоя исходный файл повторно проверяется по SHA. Индексы стадий и эмоций сохраняются максимум через4результата или1с, а также на финише; RAW остаются durable по чанкам. После внезапного завершения непроиндексированный хвост пересчитывается.

Голосовой профиль использует не более32 чистых окон на человека, равномерно по его появлению, без наложений голосов. ERes2Net обязателен и в FAST/AUTO: его отключение лишает междиалоговый matcher входных данных. Ограничение числа окон уменьшает стоимость долгих записей; влияние именно этого ограничения на качество ещё не измерено. См. также [проверки междиалоговых привязок из dev](../research/speaker-matching-quality.md).

## Проверка

Пройдены Linux CI JVM/app/lint, адресные проверки FFT, выбора ASR, каскада, CPU/RAM admission, завершения потоковых очередей, артефактов и возобновления. Baseline/AVX2 native APK собран для ARM64 и x86_64; текущий Nemotron frontend отдельно compile/link проверен для обеих ABI. На отдельном4GB AVD F32-префикс совпал с финальным RTTM на37с синтетическом входе. [Фактические результаты и незавершённая часть precision-пробы](../research/nemotron-precision-ci-2026-11-07.md). Время и RSS одного русского FAST опубликованы отдельно в [TEST_RESULTS](../TEST_RESULTS.md); WER/DER этого файла неизвестны, а результаты коротких precision-проб не заменяют их. F32 остаётся стандартом.

Ручной `ci.yml` с `optimization_probe=true` собирает обе ABI и AVX2-компаньоны, затем сравнивает F32/F16/Q8 на отдельном AVD4096MB с пятью публичными русскими RINCO-фрагментами ≤6с и синтетическим повтором≈37с через границу кеша30.4с. Метки — utterance envelopes, не покадровый VAD; синтетический повтор проверяет совпадение стабильного префикса с финалом, но не заменяет настоящий длинный разговор. При `native_base_run` используется артефакт успешной native-сборки: неизменность backend-рецептов проверяется, текущий Nemotron frontend пересобирается NDK28. Проба не измеряет пик RSS приложения или скорость всего конвейера и не повышает автоматически precision-вариант до стандартного.
