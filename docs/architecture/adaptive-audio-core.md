# Адаптивная локальная обработка аудио

> Обновление FAST: автоматический тяжёлый каскад отключён. Актуальное поведение — [один лёгкий проход](fast-pipeline.md#один-лёгкий-проход). Описание каскада ниже сохранено как история архитектуры до ускорения; оно больше не задаёт поведение FAST.

## Инварианты

Android выполняет все вычисления офлайн. Python служит подготовке сборки. Вычисления моделей — C/C++ (GGML, sherpa/ONNX Runtime), Java/Kotlin управляют процессами. Nemotron остаётся единственным источником интервалов спикеров. LLM выбирает полный неизменяемый ASR-кандидат; RAW обоих источников и обоих проходов сохраняются. Ни суммаризация, ни переписывание текста не являются частью ASR.

Перед вызовом Nemotron проверяется CLI-контракт реально установленного executable; старый runtime получает только прежние аргументы. Падение диаризации останавливает задание и допускает повтор, вместо завершённого JSON со всеми репликами `speaker_unknown`. [Причина регрессии и исправление совместимости](nemotron-cli-compatibility.md).

## Стратегии

AUTO сохраняет порог >300000 мс → FAST. FAST сначала запускает GigaAM CTC INT8 и Whisper Small Q5_1 на одинаковых PCM-чанках. `refinement-plan.json` содержит причины повторного прохода: пустой/отсутствующий ответ, >18% лексического расхождения, расхождение чисел, подозрительные повторы/скорость текста, пересечение голосов ≥200мс. Только эти чанки получают GigaAM RNNT и Whisper Large. Неславянский маршрут уточняет только Whisper. Чанки, sample clock и аудиовход не меняются; профили моделей не подменяются внутри загруженного worker. Более тяжёлые результаты замещают вариант того же источника только после проверки SHA и входной идентичности.

QUALITY сохраняет полный проход RNNT + Large и GTCRN. Итоговый JSON использует выбранный SDK/Qwen вариант, без прежнего принудительного RAW GigaAM. Буквально одинаковые тексты дают EQUIVALENT, не считаются ответом LLM и обходят генерацию. Отказ/непоместившийся prompt остаётся явным UNRESOLVED с целым доступным оригиналом. Сохраняется ограниченный контекст1024. Qwen использует2CPU-потока, совместимые со старым native frontend. Новый protocol2 разрешает2или4, но автоматический переход на4ожидает реальную пробу. Полный prompt проверяется native tokenizer в пределах прежнего контекста1024; транспортный предел8KiB не является токеновым бюджетом. Подробности: [доработки после PR37](audio-followup.md).

Оценка сложности — инженерная эвристика, а не откалиброванная вероятность ошибки. Совпадающие лёгкие модели могут ошибаться одинаково. На трудном файле возможен повторный проход всей речи, поэтому каскад не обещает фиксированного ускорения или нулевой потери качества. Другие лёгкие модели и Turbo пока не входят в пакет.

Следующие кандидаты первого прохода — multilingual Whisper Base74M и Tiny39M вместо Small244M ([размеры у автора](https://github.com/openai/whisper#available-models-and-languages)). Их опубликованные относительные скорости получены на английском/A100 и не являются прогнозом для русского/Android CPU. Перед заменой нужны короткие русские WER-пробы и доля повторных тяжёлых проходов: слишком слабый первый проход способен замедлить весь каскад. У GigaAM CTC/RNNT общий класс Conformer-энкодеров220M; смена декодера сама по себе не означает маленький энкодер ([архитектура GigaAM](https://github.com/salute-developers/GigaAM#GigaAM-overview)). Здесь используются уже имеющиеся APK-веса; неподтверждённые новые модели не подменяют их автоматически.

## Планирование и ресурсы

Процесс приложения допускает стадии через общий CPU/RAM бюджет: 4 потока и 1.65GB резерва под native/model-стадии. Остальное оставляется UI, сервисам и RSS-резерву. Native watchdog по-прежнему ограничивает наблюдаемую сумму RSS UID с прежним порогом 2GB и резервом128MiB; это наблюдаемый предел, не cgroup. При ошибке памяти допускаются последовательные повторные попытки с проверенными частичными результатами. Потоковая стадия не повторяется под serial admission, пока ASR может ожидать её префикс: сначала закрываются обе очереди, затем повторяется диаризация/ASR по окончательному плану. Пик неудачной попытки остаётся в итоговом наблюдаемом максимуме.

Каждый слот имеет отдельный Android Service/process. Lease освобождается после смерти точного Binder. Дети живого соседнего слота не являются orphan-процессами; PID, start ticks и executable продолжают проверяться. При неподтверждённом завершении слот закрывается для повторного использования.

Независимые подготовительные стадии допускаются общим бюджетом. Для Nemotron добавлен пинованный CPU-thread override: обычный полный проход резервирует4потока, потоковый FAST —2, оставляя2потока ASR или определению языка. Шумодав и определение языка могут пересекаться; в обычном режиме Nemotron использует все ядра после освобождения их бюджета. Лёгкие ASR используют по одному постоянному обработчику ×2 потока. Пока Nemotron занимает два потока, допускается один лёгкий ASR; после завершения диаризации оба ASR могут работать одновременно. Large Whisper и Qwen резервируют весь native-бюджет. Тяжёлый GigaAM использует до двух обработчиков×2потока; если остался один чанк — загружает одну модель с4потоками. Число загружаемых обработчиков не превышает число задач. Два Large запрещены и на повторном проходе FAST.

На новом FAST-задании длиннее5мин Nemotron публикует атомарный стабильный префикс RTTM: только завершённые V3-чанки без preview-flush, с дополнительным запасом1с. Ядро добавляет ещё2с и выдаёт полностью созревшие PCM-чанки двум ASR-очередям. Модель Nemotron и её память продолжаются одной сессией; независимых диаризаций нет. Опубликованные интервалы, ID и SHA чанков менять запрещено. Итоговый план проверяется на точное совпадение префикса; несовпадение закрывает streaming-очереди и запускает обычное завершение по окончательному плану с перепроверкой частичных RAW. Возобновляемые задания используют окончательный план. Сквозная проверка текущего APK не завершена; [статус функциональных проверок и остановленных проб](audio-followup.md).

## CPU, признаки, хранение

CI сохраняет baseline x86_64 и дополнительно собирает AVX2-компаньоны, включая отдельные SONAME зависимостей Nemotron. Baseline JNI-детектор проверяет CPUID + OSXSAVE/XCR0 до запуска AVX2. ARM64 не использует x86-инструкции. `GGML_NATIVE=OFF` остаётся правильным для кросс-компиляции.

Emo использует mixed-radix FFT400 вместо прямого DFT, без смены окна, reflection padding, mel-фильтров и clipping/log-нормализации. Суммы mel считаются только по ненулевому диапазону фильтра. Численный результат проверяется относительно прежнего frontend с допуском 2e-4 в log-mel; побитовая идентичность после изменения порядка вычислений не обещается.

Временные PCM WAV защищены межпроцессным lock, shared read lease удерживается до конца native-чтения. Один чанк переиспользуется обоими ASR; очистка допускается после появления обоих durable candidate refs. Кеш восстанавливаемых WAV стремится к пределу64MiB: неиспользуемые старые файлы удаляются, даже если второй ASR ещё не дошёл до них; активные lease не удаляются. При необходимости WAV создаётся заново из неизменяемого оригинала. После сбоя исходный файл повторно проверяется по SHA. Индексы стадий и эмоций сохраняются максимум через4результата или1с, а также на финише; RAW остаются durable по чанкам. После внезапного завершения непроиндексированный хвост пересчитывается.

Голосовой профиль использует не более32 чистых окон на человека, равномерно по его появлению, без наложений голосов. ERes2Net обязателен и в FAST/AUTO: его отключение лишает междиалоговый matcher входных данных. Ограничение числа окон уменьшает стоимость долгих записей; влияние именно этого ограничения на качество ещё не измерено. См. также [проверки междиалоговых привязок из dev](../research/speaker-matching-quality.md).

## Проверка

Пройдены Linux CI JVM/app/lint, адресные проверки FFT, выбора ASR, каскада, CPU/RAM admission, завершения потоковых очередей, артефактов и возобновления. Baseline/AVX2 native APK собран для ARM64 и x86_64; текущий Nemotron frontend отдельно compile/link проверен для обеих ABI. На отдельном4GB AVD F32-префикс совпал с финальным RTTM на37с синтетическом входе. [Фактические результаты и незавершённая часть precision-пробы](../research/nemotron-precision-ci-2026-11-07.md). Ускорение всего конвейера, его peak RSS и WER/DER на естественном длинном разговоре не измерялись. F32 остаётся стандартом.

Ручной `ci.yml` с `optimization_probe=true` собирает обе ABI и AVX2-компаньоны, затем сравнивает F32/F16/Q8 на отдельном AVD4096MB с пятью публичными русскими RINCO-фрагментами ≤6с и синтетическим повтором≈37с через границу кеша30.4с. Метки — utterance envelopes, не покадровый VAD; синтетический повтор проверяет совпадение стабильного префикса с финалом, но не заменяет настоящий длинный разговор. При `native_base_run` используется артефакт успешной native-сборки: неизменность backend-рецептов проверяется, текущий Nemotron frontend пересобирается NDK28. Проба не измеряет пик RSS приложения или скорость всего конвейера и не повышает автоматически precision-вариант до стандартного.
