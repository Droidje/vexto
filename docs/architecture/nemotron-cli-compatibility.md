# Регрессия запуска Nemotron при повторном использовании native runtime

7 ноября2026 на Vexto_3 обнаружены завершённые задания с пустым RTTM и ошибкой `libvexto_nemotron_exec.so exited with status 1`. Движок продолжал ASR и экспортировал все реплики как `speaker_unknown`; это выглядело как один спикер, хотя диаризация вообще не выполнилась.

Установленная диагностическая сборка0.5.1-dev-dbde47d содержит старый native frontend. Его фактический `--help` объявляет только `MODEL PCM16_WAV --gpu -1 --preset v3-offline --rttm ID`. Новое ядро безусловно передавало `--threads`, а в потоковом режиме ещё и `--progress`. Старый parser отвергает неизвестный аргумент с кодом1 до открытия аудио/модели, без stderr.

Веса не менялись: в старом успешном и новом неуспешном заданиях указан один и тот же Nemotron F32,395298848байт, SHA256 `3339eca67ba8c7bc4a67b68797b60f8956e3ba1a34d5f84b14a0157ca96185b2`. Пороговые параметры и preset `v3-offline` не изменены. Q8 не используется.

Исправление: перед запуском читается `--help` реально выбранного native executable. Дополнительные аргументы передаются только если объявлены бинарником. Старый runtime выполняет прежний полный проход; без поддержки progress ASR ожидает окончательную диаризацию. Новый сохраняет управление потоками и публикацию стабильного префикса. Помощник не загружает веса, результат сохраняется в `diarization/native-help.stdout`.

Ошибка стадии DIARIZE теперь останавливает задание с возможностью повтора. Ядро больше не выдаёт файл с одинаковым `speaker_unknown` как завершённую расшифровку при падении диаризации. Сохранённые RAW и исходное аудио остаются доступны для возобновления; безуспешные завершённые снимки уже исключаются из finished-кеша.

Проверка регрессии воспроизводит оба CLI-контракта, запрещает новые флаги для старого и проверяет сохранение двух разных RTTM-спикеров, а также callback префикса для нового. Проверки не измеряют скорость и не меняют модель. Пользовательский текущий прогон на эмуляторе не прерывается.
