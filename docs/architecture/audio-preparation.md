# Подготовка аудио без лишних преобразований

## Решение

До моделей `TranscriptionEngine` получает один канонический mono PCM16 WAV 16 кГц. Ранее путь строил временный PCM, считал неиспользуемую в инференсе энергию для волны предпросмотра, затем целиком копировал PCM в WAV. Ресэмплер фильтровал даже уже подходящие 16 кГц.

Теперь `AudioDecoder.decodeToWave` пишет непосредственно в `decoded.wav.pending`, используя фиксированный буфер 64 КиБ. После завершения обновляется заголовок, выполняется `fsync`, движок атомарно публикует `original.wav` и сохраняет контрольную сумму. Существующие корректные checkpoints переиспользуются. Ограничение четырёх часов проверяется по выходным отсчётам; отмена и ошибка удаляют незавершённый выход, исходный файл остаётся сохранным.

- Локальный `file://` WAV проходит проверку RIFF/fmt/data. Только mono PCM16/16 кГц копируется побайтно; другие форматы идут через MediaExtractor/MediaCodec. Файл целиком в RAM не загружается.
- Выход MediaCodec mono PCM16/16 кГц копируется без float и повторного квантования. Для остальных выходов остаются downmix и полифазный sinc/Blackman-фильтр с прежними коэффициентами. Ресэмплер одинаковых частот сразу передаёт отсчёты.
- MediaCodec получает до восьми доступных входных буферов, затем отдаёт готовые выходы. Ожидание используется, когда вход не был подан. Буфер кодека освобождается до FIR-вычислений над собственной mono-копией.
- FIR считается пакетами через небольшую `libvexto_resampler.so`: ARM64 NEON либо базовый x86_64 SSE2. История ограничена блоками; нативный код не хранит постоянных ресурсов. При недоступной библиотеке работает Kotlin. Коэффициенты и временная шкала прежние; SIMD меняет порядок сложения float.
- Прогресс декодера отправляется не чаще 10 раз в секунду плюс завершение. Стадия оставляет последние 2% для публикации файла и checkpoint.

API `decode` для предпросмотра сохраняет вычисление энергии. Модели, голосовые отпечатки, правила выбора ASR и JSON-контракт этой оптимизацией не меняются. Кеширование между независимыми заданиями и передача незаконченного файла в модели не добавлены.

## Короткая проверка 7 ноября 2026

Изолированный диагностический debug-пакет, Android AVD Vexto_3 x86_64, 4 ГБ RAM. Установленный пользовательский Vexto не обновлялся и не останавливался. База сравнения — декодер и scalar Kotlin-ресэмплер из `090e235`. Старый путь запускался первым; это одиночные короткие измерения с возможным влиянием прогрева и нагрузки хоста, не длительный бенчмарк.

| Вход | Прежний путь | Новый путь | Проверка |
|---|---:|---:|---|
| Test2.mp3, длительность контейнера 21,048 с, native SIMD загружен | 3688,5 мс | 2401,8 мс | 336192 отсчёта в обоих; максимальная разница PCM16 1; событий прогресса 878 → 24 |
| Синтетический WAV 16 кГц mono PCM16, 5 с | 458,4 мс | 13,3 мс | 80000 отсчётов в обоих; новый путь сохраняет исходный PCM без прежней ненужной фильтрации |

На MP3 ускорение подготовки составило около **1,54×**. Это не обещание такого же ускорения всей транскрибации: модели, проверка пакета и шумоподавление измерением не охвачены. WAV показывает преимущество специального прохода; старый и новый PCM здесь не обязаны совпадать, поскольку старый путь дополнительно фильтровал и квантовал уже готовый звук.

Короткие JVM-проверки покрывают точную длину, границы чанков, подавление частот выше Найквиста, неизменность PCM при прямом копировании, границы буфера, отклонение неподходящего/слишком длинного WAV. NDK r28c компилирует JNI для обеих ABI; на Android реально выполнен x86_64, ARM64 измерений пока нет. В основной CMake-сборке используется уже настроенный `c++_static`; отдельная диагностическая библиотека также связана статически. Восьми адресных JVM-проверок достаточно для этого шага; полный модельный прогон не выполнялся.

```sh
./gradlew :engine:testDebugUnitTest --tests com.vexto.engine.audio.ResamplerTest --tests com.vexto.engine.audio.DecodedWaveWriterTest --tests com.vexto.engine.audio.PreviewWaveformTest
```

Без подготовленных native-зависимостей JVM-проверки допускают `-PvextoSkipNative=true`. APK с этим флагом не заменяет полноценную офлайн-сборку.
