# Имена спикеров из контекста

После выбора ASR общий SELECT-обработчик делает не более одного дополнительного запроса к локальной Qwen3-1.7B. Это работает в FAST, QUALITY и AUTO, а также при Whisper-only языковом маршруте. Используется тот же persistent executor, модель, контекст 1024 и KV-тип, что для выбора ASR; KV очищается между запросами. Новых моделей, загрузок по сети и отдельной тяжёлой стадии нет.

Для скорости лёгкий планировщик ищет представления («меня зовут», «моё имя», «я Анна», «my name is») и обращения с соседней репликой другого участника. В запрос входят до четырёх кандидатов и небольшие фрагменты оригинальных реплик в пределах 864 UTF-8 байт. Приоритет у самопредставлений. Без подходящих свидетельств Qwen не вызывается. Произвольный вывод имени из биографии, дальних косвенных ссылок и поиск личности по интернету не выполняются.

Модель возвращает только массив чисел: индекс спикера или 0 («неясно»), максимум 16 выходных токенов. Само имя берётся из сохранённой реплики, а не генерируется. Для самопредставления допустим только его говорящий, для обращения — соседний другой участник с разрывом до пяти секунд и без пересечения речи. Противоречивые имена не применяются. Это консервативная эвристика, а не подтверждённая личность: ASR и LLM могут ошибаться, имя можно исправить вручную.

Дополнительный native-запрос ограничен 10 секундами, включая холодный старт, если предыдущие ASR-выборы обошлись без модели. При таймауте, ошибке, невалидном JSON или отсутствии свидетельств остаётся «Спикер N». Отмена задания распространяется обычным образом. Скорость на физическом телефоне не измерена; лимит — бюджет запроса, а не обещание измеренного ускорения.

Источник строится из проверенных кандидатов текущих `choices`, как и итоговая расшифровка (`SpeakerNamingInput`); принудительного выбора GigaAM вместо SDK-решения нет; текст размещается по тем же интервалам Nemotron. `speaker-names.json` хранит SHA256 локальных ID, таймингов и исходного текста, статус, строки-свидетельства и затраченное время. Параметры и stdout запроса сохраняются в `speaker-names/`. Результат также входит в checkpoint SELECT. Зависимости включают схему определения имён и хэш диаризации; устаревшие результаты не приклеиваются к изменённому тексту. Уже завершённые задания автоматически не пересчитываются.

Меняется только `Speaker.name`. RAW реально запущенных ASR, локальный speaker_id, реплики, слова и тайминги не переписываются. Внутренний JSON с метаданными содержит `speaker_name`; строгий JSON задания по-прежнему содержит только speaker_id/start_ms/end_ms/text. Приложение переносит имя в сохранённую расшифровку и новый автоматический профиль. У созданного ранним CoreReady профиля можно заменить только автоматическое имя «Спикер N»; ручное имя, существующее настоящее имя и профиль «Я» имеют приоритет. Одинаковые имена не объединяют людей и не используются для сопоставления голосов между записями.
