# Reflect: продукт

Рабочий документ команды: что делаем, для кого, в каком порядке и как поймём, что готово. Требования заказчика лежат в [hackathon-2026-11.md](hackathon-2026-11.md), выбор моделей в [research/](research/). Здесь только продуктовые решения поверх них.

## Одной фразой

Reflect превращает запись разговора в расшифровку по участникам с таймкодами прямо на телефоне. Без интернета, без аккаунта, без отправки голоса куда-либо.

## Для кого

Главный пользователь: человек, которому после разговора нужен точный текст «кто что сказал» и которому нельзя отдавать запись в облако.

- Журналист после интервью: найти цитату и проверить её по звуку.
- HR и рекрутер: собеседование, нужен протокол и честная запись ответов кандидата.
- Юрист, адвокат: консультация под тайной, облако исключено.
- Секретарь совещания: протокол с решениями и сроками.

Почему офлайн важен по закону: голос относится к персональным данным. С 01.07.2025 действует запрет хранить базы ПДн граждан РФ за рубежом (23-ФЗ), штрафы за утечки стали оборотными (420-ФЗ). Облачные Otter, Fireflies, Plaud для этих людей закрыты.

## Чем отличаемся

| | Reflect | Pixel Recorder | Samsung Transcript Assist | Otter, Fireflies | Scribbit (open source) |
|---|---|---|---|---|---|
| Работает без сети | да | да | частично | нет | да |
| Русский | да | только через облако | да | нет | да |
| Спикеры офлайн | да | только английский | да | облако | да |
| Любой Android | да | только Pixel | только флагманы Galaxy | да | да |
| Правка спикеров и текста | да | нет | только переименование | да | нет |
| Тап по реплике запускает звук | да | да | да | да | нет |
| Итоги и имена от локальной LLM | да | нет | через облако | облако | нет |
| Экспорт JSON, TXT, SRT, MD | да | TXT | TXT | облако | TXT |

Стек sherpa-onnx + GigaAM + pyannote уже есть в открытом коде, поэтому «офлайн и русский» сами по себе не победят. Отрываемся тремя вещами: измеренной точностью на эталоне, удобной правкой результата и стабильностью на 4 ГБ.

## Главный сценарий

1. Пользователь жмёт «+» → «Прикрепить файл» (или «Записать сейчас»), выбирает аудио любого формата: wav, m4a, mp3, ogg (голосовые Telegram), flac.
2. Экран обработки показывает этапы по очереди: декодирование, разделение голосов, распознавание, знаки препинания. У каждого этапа свой прогресс и оценка оставшегося времени. Экран можно свернуть, обработка продолжается.
3. Открывается разговор:
   - вверху участники с цветами и временем речи;
   - ниже реплики с таймкодом;
   - внизу плеер.
   Тап по реплике запускает звук с её начала, во время воспроизведения подсвечивается текущая реплика.
4. Правка в один жест:
   - переименовать спикера (имя применяется ко всем его репликам);
   - переназначить реплику другому спикеру;
   - слить двух спикеров в одного;
   - исправить текст;
   - «Перепроверить» фрагмент, то есть заново распознать только его.
5. Экспорт через кнопку «Поделиться»: JSON в формате проверки, TXT, SRT, Markdown. JSON содержит ровно поля контракта ТЗ: эмоции и имена в него сознательно не включаются ради строгой проверки по схеме и удобства жюри, а техническая возможность их выгрузки подтверждена MD-экспортом, который включает вероятности эмоций по каждой реплике. Файл уходит в любое приложение или сохраняется в «Загрузки».
6. Локальная LLM добавляет название разговора, итоги с таймкодами и предлагает имена спикеров, если люди представились в разговоре. Предложение имени пользователь подтверждает сам.

## Приоритеты

Порядок задан баллами заказчика: точность расшифровки 40, диаризация 25, тайминги 10, скорость 10, UX 10, защита 5.

### P0: без этого не сдаём

| Что | Критерий готовности | Кто |
|---|---|---|
| Импорт файла из памяти | открываются wav, m4a, mp3, ogg/opus; битый файл даёт понятную ошибку, а не падение | движок + UI |
| Расшифровка с диаризацией | на наших тестовых диалогах WER и DER не хуже замеров бенчмарка | движок |
| Таймкоды реплик | start_ms и end_ms реплики совпадают с границами речи в пределах 300 мс | движок |
| Экран разговора | реплики, участники, таймкоды по макету | UI |
| Экспорт JSON | файл проходит валидацию по схеме заказчика, speaker_id вида speaker_N | движок + UI |
| Локальная LLM | работает в режиме полёта, падение LLM не роняет приложение | LLM |
| Прогресс обработки | видно этап и процент, есть отмена | UI |
| Работа на 4 ГБ | 15-минутная запись обрабатывается без падения на эмуляторе 4 ГБ, x86_64 и arm64 | движок, проверка у Artem |

### P1: заметно поднимает UX и защиту

| Что | Критерий готовности | Кто |
|---|---|---|
| Плеер и тап по реплике | переход к звуку меньше чем за 300 мс, подсветка текущей реплики | UI |
| Правка спикеров | переименование, переназначение, слияние сохраняются и попадают в экспорт | UI + движок |
| Итоги и название от LLM | каждый пункт итогов содержит существующий таймкод, имя спикера встречается в тексте | LLM |
| Перепроверить фрагмент | повторное распознавание одной реплики без пересчёта всей записи | движок |
| Запись из приложения | запись с микрофона сразу уходит в обработку | UI |
| Поиск по записям | по тексту реплик и именам | UI |

### P2: если останется время

Подсветка слов с низкой уверенностью распознавания. Обезличенный экспорт (телефоны, СНИЛС, ИНН, номера карт). Статистика времени речи по участникам на экране «Спикеры».

### Сознательно не делаем

- Автоматическое назначение имени по сходству голоса без подтверждения пользователя. Локальные профили, сохранённые эмбеддинги и предложения сходства между записями поддерживаются; имя и привязку подтверждает пользователь.
- Переписывание расшифровки с помощью LLM. Модель на 1–2 млрд параметров меняет слова и ухудшает WER, а именно WER весит 40 баллов.
- Облачные функции любого вида, включая «пригласить друзей по ссылке».

## Как доказываем качество

- Свой тестовый набор: русские диалоги на 2–4 голоса с эталонной разметкой, перебиваниями, короткими «да», шумом и голосами со сдвигом высоты, похожими на «котиков».
- Фильтрация звуков-паразитов и шумов: короткие фонетические паузы («угу», «ага», «мгм») и посторонние шумы не попадают в расшифровку. Систему оптимизировали под это и провели серию экспериментов: фильтрация лишних звуков снижает число ошибок распознавания на тестовых записях.
- Таблица в `docs/TEST_RESULTS.md`: WER, DER, ошибка границ в мс, RTF и пиковая память на эмуляторе 4 ГБ x86_64 и arm64. Цифры берутся из прогона APK, а не с ноутбука.
- Демонстрация начинается с включения режима полёта.

## Отличия от макета

Макет Reflect принят за основу. Ниже места, где он расходится с заданием. Изменения вносятся после согласования с дизайнером.

1. Нет таймкодов у реплик и нет плеера в разговоре. Таймкоды обязательны по заданию.
2. Аватары спикеров сделаны фотографиями, а офлайн их взять негде. Предложение: цветной орб на спикера в стиле макета.
3. «Позови своих друзей / Отправить ссылку» и стрелка «отправить» читаются как облако. Предложение: пустое состояние «Спикеры появятся после первой расшифровки», кнопка «Расшифровать».
4. Нет экранов прогресса обработки, экспорта с выбором формата, переименования и слияния спикеров, итогов LLM, настроек.
5. DM Sans не содержит кириллицы, в макете русский текст рисуется запасным шрифтом. Нужен шрифт с кириллицей, например Onest или Manrope.
6. Статус-бар и клавиатура нарисованы под iOS.

## Демо на защите, 3 минуты

1. Режим полёта включён, это видно в шторке.
2. Импорт незнакомой записи, видно этапы обработки и время.
3. Разговор: тап по реплике, звук с нужного места.
4. Исправление: слить двух спикеров, переименовать, результат сразу в экспорте.
5. Итоги от LLM с таймкодами, тап по пункту ведёт к реплике.
6. Экспорт JSON, файл открывается и проходит проверку схемы.
7. Слайд с цифрами WER, DER, RTF на эмуляторе 4 ГБ и сравнение с конкурентами.

## Локальные профили

Справочник спикеров, UUID, привязки к версиям расшифровки и эмбеддинги хранятся только на устройстве. Серверной части и синхронизации нет. Один профиль объединяет подтверждённые пользователем реплики разных файлов; смена embedding-модели не смешивает старые и новые векторы. Подробности — [локальная архитектура](local-architecture.md).
