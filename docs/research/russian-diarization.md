# Русская диаризация: короткие проверки и полные конвейеры

7 ноября 2026. Три настоящих русских разговора по 30 секунд: 18 коротких native CLI запусков,
ещё 3 прогона production-диаризатора в APK на Android и отдельные запуски полных
конвейеров на ноутбуке. Точные измерения,
источники, контрольные суммы и оговорки: [JSON](results/russian-diarization-2026-11-07.json).
Запуски ноутбука не являются проверкой Android, готового APK или ARM-телефона.

## Данные и независимая разметка

Использованы демонстрационные записи корпуса
[«Рассказы и разговоры о грушах»](https://multidiscourse.ru/corpus/?en=1),
исследовательская группа «Русский мультиканальный дискурс», Институт языкознания РАН:

| Фрагмент | Исходный интервал, с | Длительность | Метки в reference |
| --- | ---: | ---: | --- |
| pears04 | 301–331 | 30 с | N, C, R |
| pears22 | 345–375 | 30 с | N, C, R |
| pears23 | 382–412 | 30 с | N, C, R |

Это непрерывные записи общего комнатного микрофона, не синтетическая склейка
монологов. Для каждого сеанса до инференса выбрано первое 30-секундное окно на
секундной сетке в первых 600 с с минимум 2 с размеченной активности каждого N/C/R.
Скачаны HTTP Range-фрагменты исходного stereo 48 kHz PCM16; затем выполнены
моно downmix и resampling 16 kHz PCM16. Границы reference сдвинуты на тот же offset.

Reference получен из **ручных нижних слоёв Words** трёх участников, а не из ответов
моделей и не из крупных EDU-интервалов. Слова и заполненные паузы сохранены;
пустые интервалы, явные `{nonverbal}` и вдохи `(ɥ)` исключены. Принципы разметки:
[руководство авторов](https://multidiscourse.ru/data/ann/pears_vocal%20annotation_eng.pdf).

Существенное ограничение: корпус предусматривает четвёртого участника Listener,
для которого отдельная vocal TextGrid не опубликована. Ранние окна выбраны до
позднего пересказа, но отсутствие дополнительного слышимого голоса независимо
не прослушано. **Полнота reference для всех слышимых звуков не подтверждена.**
Это диагностическая проба по трём аннотированным участникам, не готовый эталон
всей русской диаризации. Явная открытая лицензия на распространение аудио не
найдена: аудио и исходные аннотации остаются в локальном исследовательском кеше.
В Git — код загрузки, ссылки, хеши и измерения; WAV/TextGrid/RTTM не публикуются.

## Метод оценки

Одинаковые входы и reference для всех моделей. DER: **collar 0**, overlap учитывается,
UEM каждого файла `[0,30)`, глобальное взаимно однозначное сопоставление ID внутри
каждой записи. Суммарный DER — сумма ошибочных speaker-seconds / сумма эталонных
speaker-seconds, а не среднее процентов. Общий знаменатель: **83.0591 speaker-seconds**.
Пороги по этим фрагментам не подбирались; число спикеров моделям не задавалось.
Пересечение обучающих данных моделей с корпусом не проверялось. Границы Words,
исключённые неречевые звуки и неполнота Listener ограничивают
интерпретацию false alarms. С прежними AMI only_words цифрами напрямую не сравнивать.

## Проверено непосредственно на Android

Pixel 7 AVD, 4096 MB RAM, API 36, native x86_64, CPU. Nemotron/Sortformer —
4 потока; Sherpa segmentation и embedding — по 1 потоку, штатные параметры CLI.
Время ниже — полный native process wall, включая загрузку. Все 18 запусков
завершились за 1.1–6.9 с каждый и прошли guard бюджета 2 000 000 000 байт с резервом
134 217 728 байт внутри него. ОС исключена; sampling 150 ms + native MaxRSS,
не cgroup hard cap и не память готового приложения.

| Конфигурация | pears04 DER, % | pears22 DER, % | pears23 DER, % | Суммарный DER, % | Медиана времени, с |
| --- | ---: | ---: | ---: | ---: | ---: |
| Nemotron-3 F32-linear | 10.96 | 27.17 | 26.05 | **21.74** | 2.47 |
| Streaming Sortformer 4spk-v2 Q8 | 14.44 | 34.33 | 48.25 | 32.69 | 3.77 |
| pyannote segmentation-3.0 INT8 + TitaNet Small | 96.09 | 44.68 | 51.13 | 62.83 | 2.54 |
| pyannote segmentation-3.0 INT8 + TitaNet Large | 96.09 | 44.68 | 51.13 | 62.83 | 5.71 |
| pyannote segmentation-3.0 FP32 + TitaNet Small | 34.40 | **23.12** | 29.31 | 28.67 | 2.85 |

Для Sherpa использована кластеризация threshold 0.7 с автоматическим числом
голосов. Nemotron: NeMo-Speech.cpp, CPU `--gpu -1 --preset v3-offline`;
Sortformer v2: `--preset offline`, без подмены на Nemotron. Результат не означает,
что на любом русском разговоре Nemotron будет лучшим: например, на pears22
FP32-связка pyannote дала меньший DER.

### Почему нельзя обобщать плохой INT8-результат на весь pyannote

У TitaNet Small и Large с общей INT8 segmentation итоговые интервалы совпали:
главный провал оказался в пропусках речи. Замена только segmentation на FP32
снизила пропуски с 43.325 до 4.565 speaker-seconds и суммарный DER с 62.83 до 28.67%.
Это свидетельство проблемы проверенного INT8-экспорта на этих входах, а не
доказательство, что все модели pyannote плохо работают на русском.

Отдельная диагностическая проба усиливала сигнал по фиксированному правилу:
RMS target 0.1 с ограничением peak 0.95, без использования reference. С INT8
segmentation/TitaNet Small суммарный DER стал 62.12%: простое усиление не устранило
провал. Производственный конвейер из-за этой пробы не менялся; шумоподавление
для данных сравнений не применялось.

## NeMo MSDD: полный конвейер на ноутбуке

Официальный `diar_msdd_telephonic` 1.0.1, NeMo 2.4.0, CPU Torch/torchaudio 2.9.1,
4 потока. Выполнен весь `NeuralDiarizer.diarize()`:
MarbleNet VAD → пятишкальный TitaNet из checkpoint → NMESC clustering → MSDD.
Oracle VAD выключен; эталонный RTTM и число голосов в инференс не подавались.
Использован официальный telephonic config, с CPU/num_workers=0, batch/infer_batch=16,
локальными весами и `use_speaker_model_from_ckpt=true`; пороги не подбирались.
Это telephonic checkpoint на комнатных разговорах — домен не совпадает с названием
обученного профиля. Код NeMo не подменялся заглушками или собственной реализацией.

| Фрагмент | DER, % | Найдено ID / reference | Полное время процесса, с | Inference, с |
| --- | ---: | ---: | ---: | ---: |
| pears04 | 21.40 | 3 / 3 | 38.69 | 26.75 |
| pears22 | 30.71 | 1 / 3 | 17.27 | 7.55 |
| pears23 | 33.77 | 2 / 3 | 16.70 | 7.28 |

Суммарный DER **28.81%**; максимальный sampled host tree RSS — 1.268 GB,
максимальный OS peak одного процесса — 1.286 GB. Импорты, загрузка и первый
Numba/cache-прогрев входят в полное время. Эти времена и RAM относятся к
**Windows на ноутбуке**, их нельзя выдавать за скорость или бюджет Android.
Готовый официальный Android runtime полного MSDD-каскада не подтверждён;
наличие отдельного TitaNet/ONNX-декодера не решает перенос остальных этапов.

Источники: [модель NVIDIA](https://catalog.ngc.nvidia.com/orgs/nvidia/nemo/models/diar_msdd_telephonic),
[конфигурация NeMo v2.4.0](https://github.com/NVIDIA/NeMo/blob/v2.4.0/examples/speaker_tasks/diarization/conf/inference/diar_infer_telephonic.yaml),
[описание каскада](https://docs.nvidia.com/nemo-framework/user-guide/latest/nemotoolkit/asr/speaker_diarization/models.html).

## Community-1

Проверен **полный официальный** `pyannote/speaker-diarization-community-1`,
revision `3533c8cf8e369892e6b79ff1bf80f7b0286a54ee`, pyannote.audio 4.0.7,
CPU Torch/torchaudio 2.9.1. Все пять файлов официального snapshot проверены по
закреплённым размеру и хешам; веса не заменялись ONNX-экспортом или компонентами
Sherpa. Выполнены segmentation, embedding, PLDA/VBx и обе формы итоговой разметки.

После ручного принятия условий пользователем веса скачаны с Hugging Face;
инференс выполнялся локально, в offline mode, без отправки аудио и телеметрии.
WAV прочитан в waveform через Python, что использует поддержанный вход Pipeline
и не требует неработающего здесь TorchCodec/FFmpeg decoder. Для DER использован
обычный `speaker_diarization`, сохраняющий overlap; `exclusive_speaker_diarization`
оставлен отдельным артефактом и не подменяет его в оценке.

Штатный **batch 32** во всех трёх корректно измеренных попытках превысил
2 000 000 000 байт: наблюдаемый консервативный tree peak 2.030–2.052 GB,
процессы остановлены guard. Для рабочего профиля изменены **только публичные
размеры segmentation/embedding batch на 4**, readback обеих настроек проверен.
Веса, VBx threshold 0.6, Fa 0.07, Fb 0.8 и остальные параметры сохранены.
Число голосов и reference модели не передавались.

| Фрагмент | DER regular, % | Найдено regular ID / reference | Полное время, с | Inference, с | Наблюдаемый host tree peak, GB |
| --- | ---: | ---: | ---: | ---: | ---: |
| pears04 | 33.04 | 2 / 3 | 20.35 | 10.06 | 0.848 |
| pears22 | **22.86** | 2 / 3 | 17.84 | 10.28 | 0.838 |
| pears23 | 42.42 | 2 / 3 | 18.02 | 10.40 | 0.838 |

Суммарный DER **32.45%**. Максимум с резервом 128 MiB — **982 331 392 байта**.
Это наблюдение дерева **Windows host-процессов** с sampling 100 ms и суммой OS
high-water marks; supervisor исключён, не cgroup hard cap и не доказательство
Android RAM. Таймаут рабочего профиля — 60 с, фактически все прогоны короче 21 с.
Первый пробный запуск дал реальный RTTM, но первоначальный счётчик видел только
Windows venv launcher: его память признана недостоверной и исключена из aggregate.
Затем монитор исправлен на дерево launcher + interpreter, первый клип повторён;
регрессии проверяют учёт памяти потомка и остановку без orphan-процесса.
На pears04 DER batch 4 совпал с первоначальным результатом batch 32.

Community-1 на Android в этой серии **не запускался**. Есть сторонний полный порт
[cpp-annote](https://github.com/moonshine-ai/cpp-annote), но его Android-путь и
численное соответствие официальному Python pipeline нами не проверены.
Источники: [карточка модели](https://huggingface.co/pyannote/speaker-diarization-community-1),
[официальный snapshot](https://huggingface.co/pyannote/speaker-diarization-community-1/tree/3533c8cf8e369892e6b79ff1bf80f7b0286a54ee).

## Вывод для текущего прототипа

На этих трёх коротких русских фрагментах минимальный суммарный DER у Nemotron
F32-linear: 21.74%. Полный MSDD дал 28.81%, Community-1 batch 4 — 32.45%.
Однако на pears22 Community-1 лучше остальных: 22.86% против 23.12% у FP32
segmentation/TitaNet Small и 27.17% у Nemotron. Универсальный рейтинг из этого
не следует; reference и объём выборки имеют перечисленные выше ограничения.

Текущих данных недостаточно для замены основной Android-связки на Community-1
или MSDD. FP32 segmentation — полезный запасной вариант; результат INT8-экспорта
нельзя приписывать всему pyannote. Нативную скорость Nemotron и Python-время
ноутбука напрямую не сравнивать. Длинные записи и перенос двух полных host
конвейеров на Android остаются отдельными, ещё не выполненными проверками.

## Прямое сравнение с диаризатором из dev APK

Дополнительная серия 7 ноября: production-код из `dev` commit `cb5b7ca` вызван
непосредственно внутри Android APK. Отладочная Activity использует штатные
`ModelStore → AudioDecoder → VoiceDetector.Diarization → Diarizer.run` и сохраняет
raw RTTM до ASR. GigaAM, сборка слов в реплики и LLM в этот DER не входят.
Production-алгоритм не менялся. [Измерения и отпечатки исходников](results/dev-diarization-2026-11-07.json).

Штатные настройки `scripts/fetch_models.sh`: Silero VAD, АРУ при чтении аудио,
**ERes2Net BASE200k** (не ERes2NetV2), cosine threshold **0.35**, окна 1 с с шагом
0.5 с, агломеративная кластеризация, поглощение кластеров с весом меньше 5 с,
голосование по кадрам 10 мс. Автоопределение числа голосов, 4 потока. Точные WAV,
reference и протокол DER совпадают с прежними прогонами Nemotron; scorer проверяет
SHA256 каждого WAV, reference, результата и манифеста моделей.

| Фрагмент | Dev APK DER, % | Nemotron F32 DER, % | Dev ID / reference | Dev: декодирование + VAD + диаризация, с |
| --- | ---: | ---: | ---: | ---: |
| pears04 | 19.52 | **10.96** | 3 / 3 | 2.564 |
| pears22 | 36.76 | **27.17** | 2 / 3 | 2.720 |
| pears23 | 35.35 | **26.05** | 2 / 3 | 2.736 |
| Суммарный micro DER | **30.92** | **21.74** | — | — |

На этой выборке dev хуже по DER на **9.18 процентного пункта**. Пропуски:
13.008 против 1.562 speaker-seconds; false alarms: 8.589 против 14.199;
путаница голосов: 4.086 против 2.300. Это не означает, что ERes2Net как отдельная
embedding-модель хуже: сравниваются целые диаризационные конвейеры.

В production `SpeakerClustering.turns` выбирает только один голос на каждый кадр.
Разметка reference в этой серии дополнительно содержит 10.515 speaker-seconds
наложения, поэтому часть расхождения с разметкой заложена в самом протоколе
сравнения. Это свойство алгоритма, а не доказанная отдельным ablation причина
всей разницы DER. Также не проверялось, какой вклад отдельно даёт поглощение
коротких кластеров.

Наблюдаемый максимум VmHWM процесса APK — **280 489 984 байта**; с резервом
128 MiB — 414 707 712 байт. Это память диаризационного прогона с Android runtime,
**не полного ASR-конвейера** и не hard cap. Каждый файл обрабатывался в свежем
процессе; bootstrap-копирование моделей выполнено заранее. VmHWM сброшен перед
обработкой, что подтверждено stats. Времена/RSS APK и прежнего native CLI имеют
разный состав накладных расходов; сравнивать их как одинаковые memory benchmarks нельзя.

Сборка: отдельный debug package `com.vexto.reflect.diarprobe`, Gradle 8.9,
AGP 8.7.3, JDK 21, target SDK 35. Локальный init-script выставил установленный
compile SDK 36 вместо 35 и отдельный application ID; shared production Gradle
не менялся. Устройство — тот же x86_64 AVD с RAM 4096 MB. Debug APK собран,
24 JVM-теста движка и 94 Python-теста прошли. Новые APK/source hashes записаны в JSON.
Ограничения трёх коротких русских фрагментов и неполного Listener reference остаются
такими же, как в основной серии; универсального рейтинга этот результат не даёт.

## Воспроизведение

- [`prepare_russian_diarization.py`](../../tools/benchmarks/prepare_russian_diarization.py)
  скачивает закреплённые короткие PCM ranges и ручные TextGrid, проверяет хеши,
  формат WAV и границы; требует локально установленный miniaudio 1.71.
- [`bounded_android_pipeline.py`](../../tools/benchmarks/bounded_android_pipeline.py)
  исполняет планы native-проб с памятью и таймаутом; планы этой серии сохранены
  локально, команды/модели и настройки перечислены в JSON и этом отчёте.
- [`run_msdd_probe.py`](../../tools/benchmarks/run_msdd_probe.py) запускает полный
  NeMo-каскад на host CPU в отдельном процессе, с лимитом времени до 90 с,
  мониторингом дерева процессов, без oracle-данных и с запретом stale output.
- [`run_community1_probe.py`](../../tools/benchmarks/run_community1_probe.py)
  проверяет официальный snapshot и запускает полный pyannote pipeline локально;
  токен берётся только из локальной авторизации, не из CLI-аргументов.
- [`score_diarization.py`](../../tools/benchmarks/score_diarization.py) считает
  единый DER независимо от модели. Приватные записи пользователя не использованы.

ML-зависимости устанавливаются в отдельные кеши/окружения; глобальный Python не
меняется. Набор host unit-тестов — стандартная библиотека, без скачивания моделей:
`python -B -m unittest discover -s tools/benchmarks/tests -q`.
