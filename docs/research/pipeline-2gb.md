# Последовательный конвейер Android с бюджетом 2 ГБ

Дата экспериментов: 6 ноября 2026. Выбранный профиль качества этой серии — **Nemotron 3 Diarization с F32 linear weights + GigaAM v3 e2e RNNT + независимый Whisper Large v3 Q5_0 + Qwen3 1.7B Q4_K_M с выбором готовых фраз по ID**. На Android x86_64 с RAM 4096 MB завершён сквозной WAV-прогон всех семи этапов с наблюдаемым пиком **1 830 166 528 байт**, с резервом — **1 964 384 256 байт**. Основной пик дал Whisper.

Это лучший проверенный профиль в текущей серии прототипирования. Выбор опирается на две короткие записи, отдельные проверки голосов и синтетические стресс-пробы; универсальное превосходство и точность на независимом корпусе ещё не установлены. Готового APK и проверки длинного ASR этим результатом не получено.

## Состав профиля

| Этап | Конфигурация | Роль |
| --- | --- | --- |
| Диаризация | Nemotron 3, CPU, `v3-offline`, локально конвертированный F32-linear GGUF | Интервалы говорящих и устойчивые ID; полный end-to-end diarizer |
| Основной ASR | GigaAM v3 e2e RNNT, INT8 encoder, 64 mel, 2 потока | Исходный русский текст с пунктуацией и эмиссиями токенов |
| Независимый ASR | Whisper Large v3 Q5_0, beam 2, best-of 2, 4 потока, processors 1, flash attention | Отдельная альтернативная расшифровка для сравнения |
| Объединение | Java `app_process`, максимальное временное пересечение слова и голоса | JSON-контракт с исходными словами GigaAM, ID и временем |
| Локальная LLM | Qwen3 1.7B Q4_K_M, context 1024, batch 128, ubatch 64, 2 потока, no-repack | Выбор максимум трёх ID из дословного пула, temperature 0, output 64 tokens |
| Дополнительная обработка | GTCRN, выключен по умолчанию | Отдельный вариант для сравнения на шумных записях |

F32-linear GGUF получен из исходного NVIDIA checkpoint штатным конвертером: **359 тензоров F32 и один F16 Conv1D kernel**, файл 395 298 848 байт. Это не полностью F32 вычисление и не расширение уже квантизованного Q8 файла. На проверенных якорях F32 и Q8 дают одинаковую картину; улучшение DER от увеличения точности весов не доказано.

Все модельные этапы и постобработка в сквозном прогоне выполняются непосредственно на Android. ПК подготавливает тестовую PCM WAV-фикстуру, управляет ADB и извлекает готовые файлы. После каждого этапа процесс модели завершается. Whisper сохраняется отдельной альтернативой и автоматически не переписывает текст GigaAM. Полный процесс: диаризация → GigaAM → Whisper → построение prompt и пула на Android → Qwen → JSON-экспорт → проверка метаданных.

Исходники, пины, лицензии и воспроизводимые сборки описаны отдельно: [Nemotron на Android](nemotron-android.md), [нативный Whisper](whisper-android.md). Агрегаты и точные артефакты без приватных записей: [измерения](results/pipeline-2gb-measurements-2026-11-06.json), [манифест моделей и runtime](results/pipeline-2gb-artifacts-2026-11-06.json). Проверенные x86_64 сборки не являются проверкой ARM-телефона; вариант Nemotron требует AVX2/FMA/F16C/SSE4.2.

## Бюджет и измерение памяти

Бюджет составляет **2 000 000 000 байт**, около 1907.3 MiB. **Внутри него** оставляется резерв **128 MiB = 134 217 728 байт**:

```text
наблюдаемый консервативный пик дерева процессов + резерв <= 2 000 000 000 байт
```

Android, системные службы и посторонние приложения не входят в бюджет процессов конвейера. Резерв не является измеренной памятью будущего UI. Для готового приложения нужна проверка полного дерева, импорта, хранения, воспроизведения и жизненного цикла.

[`bounded_android_pipeline.py`](../../tools/benchmarks/bounded_android_pipeline.py) запускает отдельные процессы через `toybox time -v`. [`android_memory_guard.sh`](../../tools/benchmarks/android_memory_guard.sh) наблюдает модельное дерево и свой supervisor с целевым интервалом 150 мс. Собираются сумма RSS, PSS при доступности и VmHWM. Консервативная оценка учитывает максимум наблюдаемой суммы RSS, наблюдаемую сумму VmHWM и нативный MaxRSS с supervisor. Общие страницы могут учитываться несколько раз; полнота PSS записывается отдельно.

При превышении порога `budget - reserve` watchdog завершает только собственные процессы, сверяя PID и время старта. После завершения отдельно проверяется нативный MaxRSS с резервом. Sampling может пропустить краткий пик: **это наблюдаемая проверка, не cgroup hard cap**. Новый этап не начинается при неподтверждённом завершении предыдущего дерева.

Статусы `failed` и `memory_rejected`, отсутствующие замеры и неуспешные процессы не входят в принятые результаты. `accepted_pipeline_peak_bytes` заполняется только при принятии всех шагов плана. Успех отдельных моделей не заменяет сквозной запуск.

## Диаризация на коротких записях и стрессах

На записи с четырьмя объявленными репликами Nemotron сохраняет последовательность **1 → 2 → 1 → 2**. Привязка произвольных ID устанавливается по первым двум объявлениям, последующие проверяют возвращение голосов. На зашумлённой копии и четырёх повторах F32 и Q8 сохраняют такую же картину якорей. Это проверка согласованности в точках без ручной временной разметки, не DER.

| Немотрон и вход | Длительность, с | Время процесса, с | Наблюдаемый пик, байт |
| --- | ---: | ---: | ---: |
| Q8, исходная запись | 21.012 | 0.476 | 138 985 472 |
| Q8, синтетический шум SNR 10 dB | 21.012 | 0.506 | 144 408 576 |
| Q8, четыре повтора | 84.048 | 3.292 | 161 316 864 |
| Q8, 86 повторов | 1807.032 | 108.424 | 275 554 304 |
| F32-linear, исходная запись | 21.012 | 0.565 | 431 616 000 |
| F32-linear, синтетический шум SNR 10 dB | 21.012 | 0.614 | 432 111 616 |
| F32-linear, четыре повтора | 84.048 | 5.114 | 449 122 304 |
| F32-linear, другая короткая запись | 28.948 | 1.798 | 436 391 936 |

В 30-минутном Q8-стрессе получены два ID и **344 из 344 однозначных согласованных якорей** возвращения голосов. Это 86 повторов одной двухголосной записи: проверка памяти и сохранения ID, а не независимый речевой корпус. Она не проверяет длинный ASR, LLM, полный конвейер или F32 на 30 минутах. Пример native runtime читает WAV в память; память аудио и история результатов растут с длительностью, что описано в [ограничениях Nemotron](nemotron-android.md#running-and-memory-limits).

На второй короткой записи Q8 и F32 выдали три ID, что совпадает с известным от пользователя числом участников. Ручного эталона личности и границ нет, поэтому совпадение количества не доказывает правильность всех назначений. Авторская поддержка до восьми спикеров не означает, что восьмиголосный сценарий уже проверен в проекте.

Ранее pyannote INT8 + TitaNet Small и Large также сохраняли четыре объявления на исходном коротком файле. При этом Large занимал 7.813 с и 256.3 MiB нативного MaxRSS против медианы Small 1.808 с и максимума 199.1 MiB в трёх прогонах. На четырёх повторах появлялись дополнительные кластеры: Small — три, Large — пять; FP32 segmentation и порог 0.9 полностью не устранили нестабильность. ResNet293 LM при порогах 0.2/0.3/0.5/0.7 объединял разные первые голоса. Эти альтернативы сохранены для сравнения; выбранный Nemotron — другой end-to-end diarizer, а не просто более крупный embedding.

## ASR и отклонённые конфигурации

GigaAM v3 e2e RNNT INT8 на исходной записи распознал четыре объявления и пунктуацию за 1.690 с при нативном MaxRSS 350.3 MiB. Базовый v3 RNNT также сохранил четыре объявления; отдельный e2e CTC запуск был успешен, но объявления были менее полными. Без ручного текста-эталона эти наблюдения не являются WER.

Нативный Whisper Large v3 Q5_0 с **beam 2, best-of 2, 4 потоками, processors 1 и FA** отдельно прошёл бюджет: 46.592 с, пик 1 826 500 608 байт, с резервом 1 960 718 336. В сквозном прогоне этот же профиль имеет отдельные измерения выше. Turbo Q5_0 без FA с четырьмя потоками дал 32.31 с и 1 083 256 832 байт; FA с двумя потоками — 29.595 с и 842 313 728 байт. Тексты различались; одновременно менялись несколько параметров, поэтому эффект FA на качество здесь не изолирован.

Из принятого набора исключены конкретные превышения:

- **Whisper Medium ONNX INT8:** наблюдаемый пик 2 124 238 848 байт, с резервом 2 258 456 576; `memory_rejected`.
- **Native Whisper Large Q5 с beam 5:** наблюдаемый пик примерно 2.061 ГБ; `memory_rejected`.

Часть испытанных конфигураций превысила бюджет. Нативный Large с ограниченным beam принят по собственным замерам; успех не переносится на другой decoder, runtime, контекст или настройки.

## Шумоподавление и метаданные

GTCRN успешно обработал исходную запись и копию с искусственным шумом SNR 10 dB. Ясного выигрыша по полноте последующего GigaAM в этих пробах не установлено. Он остаётся опцией для отдельных сравнений. Спикеров сначала определяем по исходному сигналу, чтобы эффект фильтра проверялся отдельно.

[`VextoPostprocess.java`](../../tools/benchmarks/android/VextoPostprocess.java) объединяет эмиссии токенов с интервалами диаризации, в том числе RTTM. Прямое соединение токенов обязано точно совпадать с исходным текстом после удаления только внешних пробелов. Слово получает время первого/последнего токена и хвост 40 мс; назначение — по максимальному пересечению объединённых интервалов. ID перенумеровываются по акустическому порядку; отсутствие пересечения даёт `unknown`, разрыв более 0.7 с создаёт новую группу. Это оценки эмиссий, не forced alignment. [Python-реализация](../../tools/benchmarks/merge_transcript.py) служит переносимой проверкой алгоритма.

В первоначальном literal-режиме LLM предложила фразы с изменениями и проверка отклонила все. Теперь [`CandidateKeywords.java`](../../tools/benchmarks/android/CandidateKeywords.java) строит свежий пул из максимум 24 дословных окон по 2–4 слова, равномерно выбирая позиции по всей стенограмме. Дубликаты, чистая пунктуация и общие номерные метки говорящих исключаются эвристикой. Это ограниченный n-gram алгоритм, не семантическая модель выделения ключевых фраз.

Qwen выбирает только `candidate_ids`; Java проверяет SHA256 исходного ASR, ID и буквальное присутствие каждой строки и восстанавливает точные фразы. Свободно сгенерированный текст в `keywords` не попадает. Audit содержит `selection_only=true` и `raw_asr_rewritten=false`. Контекст LLM остаётся 1024 токена; длинный текст требует отдельной стратегии разбиения. Старый literal-режим сохранён для воспроизведения. [Шаблоны и политика](../../tools/benchmarks/templates/README.md).

## Воспроизведение

Нужны Python 3.10+, Android SDK/ADB, совместимый AVD и заранее размещённые на Android модели и runtime с проверенными SHA256. Сборки и модельные преобразования воспроизводятся по [Nemotron recipe](nemotron-android.md) и [Whisper recipe](whisper-android.md). DEX должен содержать оба Java-файла из `tools/benchmarks/android/` со всеми внутренними классами. Исходники компилируются с UTF-8. Candidate prompt/schema и закрывающий thinking Jinja размещаются под `pipeline2/llm/`.

Пример выбранного профиля для уже подготовленного Android WAV:

```text
python tools/benchmarks/run_quality_pipeline.py --adb adb --serial emulator-5554 --remote-root /data/local/tmp/vexto-model-research --input-wav input.wav --output-dir .agents/work/quality-001 --diarization-engine nemotron --nemotron-model pipeline2/nemotron/model.f32.gguf --whisper-model pipeline2/whisper-cpp/large-q5.bin --whisper-beam-size 2 --whisper-best-of 2 --whisper-threads 4 --whisper-flash-attn --metadata-mode candidates
```

[`run_quality_pipeline.py`](../../tools/benchmarks/run_quality_pipeline.py) создаёт уникальную удалённую рабочую папку, план и свежие prompt/pool. Для Nemotron фиксированы CPU `--gpu -1`, `--preset v3-offline` и RTTM; `--offline` не добавляется. CLI сохраняет default `pyannote` и `literal` для воспроизведения прежних проб: выбранный профиль включается явными параметрами выше. Для Whisper defaults beam/best-of/threads равны 2, FA выключен; выбранный Large-прогон требует четырёх потоков и FA. Processors всегда 1.

Полные приватные артефакты извлекаются только после принятия всех этапов: `artifacts/`, измерения — `measurements/results.json`, общий статус — `pipeline.json`. `--output-dir` должен быть новым. Настраиваются `--budget-bytes`, `--reserve-bytes`, `--sample-ms`, `--step-timeout-seconds`; повторения и условия надо измерять заново. Низкоуровневые планы произвольных моделей исполняет [`bounded_android_pipeline.py`](../../tools/benchmarks/bounded_android_pipeline.py).

```text
python -m unittest discover -s tools/benchmarks/tests -v
```

В этой серии выполнены 56 unit-тестов переносимых утилит. Веса, аудио, prompt, пул и полные логи хранятся локально в игнорируемых папках; в публичных результатах только агрегаты и модельные/runtime хеши. Следующая проверка качества — независимый размеченный корпус с короткими перебиваниями, похожими голосами, одновременной речью, разными устройствами и длительностями. Нужны WER/DER, точность времён и полный APK memory test.
