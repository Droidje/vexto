# Перебивания: Android и предупреждение в расшифровке

Детектор оценивает существенную одновременную речь по исходному звуку. Он не разделяет
слова двух людей и не определяет, кто кого перебил. Короткие подтверждения были
отрицательными примерами при обучении. Пересечение таймкодов не создаёт предупреждение.

## Модель и пределы качества

Замороженный WavLM Base+ (94,4 млн параметров) и обученная линейная голова используют
среднее и стандартное отклонение слоёв 6 и 12. Вход — mono PCM16/16000 Hz, ровно
64000 отсчётов, без дополнительной нормализации. Выход — вероятность класса.
Порог **0.9120559394359589** выбран до просмотра test и при переносе не менялся.

Предшествующий эксперимент: 406 реальных четырёхсекундных окон AMI, разбиение по
участникам train/selection/calibration/test = 214/55/55/82. На test обнаружены 18/26
наложений, ложные срабатывания 1/56, в том числе 1/27 коротких подтверждений.
Precision 18/19, recall 18/26. Это небольшой английский пилот, не гарантия качества
на русских разговорах. Независимые русские положительные примеры ещё не оценивались.

В Android проверяется **одно центральное окно 4 с на реплику**, полностью внутри её
границ. Несколько попыток с максимумом оценки не применяются:
такой способ повышает вероятность ложного значка на длинных репликах.

Голова хранится в `tools/models/overlap-head.json` (центрирование, масштаб, веса и bias),
полный экспорт ONNX — 378735841 байт. Маленькая голова не заменяет большой энкодер.
Источник энкодера: [TorchAudio WavLM Base+](https://docs.pytorch.org/audio/2.5.0/generated/torchaudio.pipelines.WAVLM_BASE_PLUS.html).
SHA-256 исходных весов: `136a3e720c04f2c77bf7a4dc6a3868b14d5a2c145a988114b733cb1a8428be98`.
Голова перенесена без переобучения из экспериментального checkpoint SHA-256
`6a6cd637ab6842c3eb79f198f83bb4bdc6eee2c208cec7c1aedd3c1a3d03e7ed`.

## Выполнение и данные

Стадия OVERLAP запускается после эмоций в отдельном inference worker с двумя потоками.
Используется уже поставляемый sherpa ONNX Runtime 1.28.2 через JNI; второго runtime нет.
Действуют общий RSS watchdog, timeout и ожидание завершения процесса перед освобождением
ресурсов. Ошибка детектора не отменяет текст ASR и не порождает положительные отметки.
Модель извлекается из APK и проверяется по SHA-256. Интернет в приложении не нужен.

Внутренний JSON содержит необязательный `overlap_detected`: true — обнаружено,
false — проверено без срабатывания, отсутствие — не проверено. Строгий JSON задания
и ревизия идентичности спикеров не содержат это поле. Checkpoint привязан к SHA модели,
политике `centered-4s-v1` и точным границам реплики. Изменение интервала при перепроверке
инвалидирует старую отметку; фоновое обновление эмоций её сохраняет.

Только true показывает красный исходный `alert-circle.svg` справа сверху аватара.
Нажатие открывает панель «Обнаружено перебивание» с пояснением возможного снижения
точности текста. Отрицательные и непроверенные реплики не получают значок.

## Подготовка и проверки

```sh
bash scripts/prepare_overlap_models.sh .agents/work/overlap-build
python3 scripts/verify_overlap_model.py
# Общая подготовка native runtime также подготавливает модель перебиваний.
bash scripts/prepare_android_runtime.sh "$ANDROID_HOME/ndk/28.2.13676358" /path/to/scratch
bash gradlew --no-daemon --max-workers=2 -PvextoSkipNative=true \
  :engine:testDebugUnitTest :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

Веса ONNX и окружение генерации игнорируются Git. Обычная native-сборка проверяет
наличие полного пакета; `vextoSkipNative` предназначен для JVM/UI-проверок и допускает
отсутствие модели. Скачивание/экспорт происходят при подготовке сборки, не на телефоне.

2026-11-07: экспорт проверен на всех 82 test-окнах: решений, отличных от PyTorch, **0**,
максимальное расхождение вероятности 0.000008911. На ARM64 AVD с RAM4096 MB,
786×1704/density320 isolated worker обработал восемь реальных окон (32 с): 3797 ms,
peak combined RSS 726372352 байт. Все восемь решений совпали с Python; выборка включает
известные FP и FN. Это проверка переноса, не новая независимая оценка качества и не
замер скорости физического телефона. Полный ASR-проход этим probe не проверяется.
Повтор с окончательной политикой `centered-4s-v1` и уже извлечённой моделью: 3206 ms,
697729024 байт, 0 изменённых решений, максимальное расхождение с Python 0.000004292.
[Сохранённые измерения](results/android-overlap-2026-11-07.json).

В реальном интерфейсе эмулятора проверены четыре отмеченные и четыре неотмеченные
строки, нажатие на значок и край его области, открытие/закрытие панели. Перепривязка
переработанных строк проверяется JVM-тестом; восемь строк помещались на экране.

Debug-only `OverlapEvalActivity` читает `overlap-eval/input.wav` из external files
приложения, вызывает настоящий StageClient и сохраняет результат. `OverlapFixtureActivity`
импортирует его в обычное хранилище и открывает приложение для проверки интерфейса.
Текст «Контрольный аудиофрагмент» обозначает тестовые окна, не результат распознавания.
Для установки рядом с пользовательским приложением: `-PvextoEvaluationIdSuffix=.overlap`.
Эти две Activity отсутствуют в release.
