# ИИ-резюме: точный бюджет токенов и широкое объединение

Дата: 8 ноября 2026. Ветка реализации: `feat/summary-token-budget`. После ознакомления с результатами пользователь разрешил отправить изменения в dev.

## Метод

Три реальные локальные расшифровки пользователя, без изменения текста источников и без отправки аудио/текста внешним сервисам. ARM64 Android AVD с 4 ГБ RAM, Qwen3-1.7B-Q4_K_M, CPU 2 threads, context 2048, output 192 tokens / 640 UTF-8 bytes. Системный промпт, sampling и модель одинаковые. Каждый разговор использует новый persistent worker с загрузкой модели, которая входит во время; отдельные запросы внутри разговора переиспользуют worker.

Baseline — исходные части до 1300 байт и попарное объединение. Candidate — точный подсчёт полного ChatML, максимально вместительные части и группы целых резюме. Измерены native worker и планировщик диагностического harness, а не полный пользовательский путь установленного приложения. Проверка Android UI и физического телефона в этот замер не входит. Host-нагрузка не изолировалась; результаты диагностические. Длинный пример повторён с обратным порядком candidate → baseline.

## Время

| Реальная расшифровка | Baseline | Candidate | Вызовы baseline → candidate |
|---|---:|---:|---:|
| Короткая 1, 444 байта текста | 6,13 с | 6,52 с | 1 → 1 |
| Короткая 2, 491 байт текста | 5,28 с | 5,75 с | 1 → 1 |
| Запись 5:46, 9583 байта, первый порядок | 143,36 с | 68,82 с | 15 → 3 |
| Та же длинная, обратный порядок | 139,27 с | 73,36 с | 15 → 3 |

Среднее двух длинных запусков: **141,31 → 71,09 с**, около **1,99×**, сокращение времени на 49,7%. Короткие результаты совпадают побайтно; их небольшой проигрыш — накладные расходы планирования без сокращения inference. Результаты каждой реализации на длинном примере также совпали между повторами.

Самый большой candidate prompt: 1855 токенов + 192 резерв = 2047/2048. Числа планирования и generation audit совпали для всех candidate запросов. Две исходные части и один merge вместо восьми частей и семи merge. Самый медленный candidate запрос — 58,19 с, меньше штатного таймаута 120 с. На этом реальном примере merge содержит два результата; объединение более двух проверяется отдельно тестами вместимости и планировщика.

## Смысл и решение о публикации

Короткие резюме не изменились, включая существующие ошибки малой LLM. На длинном примере baseline смешивает вставной вымышленный эпизод с основным разговором. Candidate связнее и отражает начало беседы о выставке, но упускает доминирующую тему путешествий и повторяет раннюю цифру, которую собеседник далее исправляет. Проверка по исходному тексту не позволяет считать качество готовым к публикации.

**Решение: по прямому разрешению пользователя опубликовать оптимизацию в dev с указанными ограничениями качества.** Ускорение подтверждено в указанном native-контуре; качество резюме и скорость полного UI-пути требуют дальнейшей проверки. Увеличение контекста само по себе не исправляет ошибки модели.

## Проверки реализации

Точное форматирование, повторная проверка токен-бюджета перед generation, широкая группировка, немонотонность BPE, сохранность Unicode, повтор после ошибки с переоткрытием checkpoint, смена источника/версии, удаление checkpoint только выбранной записи покрыты native-пробами и JVM-тестами. Реализация и формат хранения: [архитектура](../architecture/summary-token-budget.md). Приватные входы и выводы harness остаются в ignored `.agents/work/summary-token-benchmark/`, в репозиторий не включаются.

## Восстановление и нативные контракты

В диагностическом fault-прогоне после первого готового ответа процесс остановлен, файловый checkpoint переоткрыт. Первый шаг занял 49,84 с; повтор использовал один сохранённый ответ и выполнил только два оставшихся вызова за 15,06 с. Итог совпал с чистым запуском побайтно. Это проверка native harness с дисковым кешем; production-класс `SummaryCheckpoints` отдельно проверен JVM-тестом с ошибкой и переоткрытием, без утверждения о полном UI fault-e2e.

Переполненный prompt (4079 токенов) корректно вернул `accepted=false`, worker остался пригоден к следующим запросам. Подобранный префикс дал 1855 токенов, следующее слово — 1860, что уже не помещается с резервом 192. Генерация до и после операций токенизации совпала побайтно. В отдельной синтетической проверке вместимости из повторённых реальных промежуточных ответов поместились 27 целых элементов (1794 токена); 28 уже дали 1863 и были отклонены. Это проверка возможности широкого merge, не оценка качества резюме на повторённом тексте.
