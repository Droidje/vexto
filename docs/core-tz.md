# Как Vexto закрывает ТЗ

Сопоставление каждого требования [задания](hackathon-2026-11.md) с реализацией: что сделано и где это увидеть. Пути в UI — фактические подписи кнопок и вкладок; технические детали — [engine/README.md](../engine/README.md), полные конвейеры — [качественный](architecture/quality-pipeline.md) и [быстрый](architecture/fast-pipeline.md). Каждый пункт проверяется в приложении или в коде.

## Обязательная функциональность

| Требование | Как реализовано | Где проверить |
|---|---|---|
| Работает под управлением Android OS | Нативное Java-приложение (модуль `app`), движок на Kotlin + NDK. minSdk 28 (Android 9), targetSdk 35, arm64-v8a и x86_64 | APK устанавливается и работает как обычное Android-приложение |
| Использует локальную LLM | Qwen3-1.7B (Q4_K_M) внутри APK, работает без сети. Роли: на двух-ASR маршруте выбирает целый вариант (GigaAM или Whisper; ядро проверяет SHA). На русском после успешного LID сравнение пропущено; имена требуют свидетельств, а итоги/названия доступны отдельными операциями, предлагает контекстные имена спикеров, пишет итоги разговора и короткое название. Свободной перезаписи текста нет | Название и итоги — на экране разговора; автоматическое имя можно исправить в профиле; это не подтверждённая личность |
| Импортирует аудиозапись из памяти устройства | Меню «+» → «Прикрепить файл»: wav, m4a/aac, mp3, ogg/opus, flac, amr (до 1 ГиБ). Дальше предпросмотр с кнопкой «Расшифровать в фоне» | Кнопка «+» на «Главной» |
| Преобразует речь в текст | Русский после успешного LID: GigaAM CTC в FAST, RNNT в QUALITY. `be`/сбой LID: GigaAM + Whisper с SDK/Qwen-выбором; другие языки: Whisper-only. [Маршруты](ARCHITECTURE.md#языковые-маршруты) | Экран разговора: реплики с текстом |
| Автоматически определяет и разделяет говорящих | Диаризация Nemotron 3 F32 по полным интервалам; слова размещаются в интервалах Nemotron с сохранением их границ; безопасный fallback сохраняет последовательность слов; голосовые отпечатки ERes2Net держат профили участников | Экран разговора: участники с цветами и временем речи вверху |
| Формирует временные метки для реплик | `start_ms`/`end_ms` в целых миллисекундах, без обещания акустической точности 1 мс у каждой реплики | Таймкод на каждой реплике; тап запускает звук с её начала; те же поля в JSON |
| Отображает полученную расшифровку | Экран разговора: вверху участники, ниже реплики с таймкодами, внизу плеер | Вкладка «Главная» → карточка разговора; вкладка «Записи» → запись после расшифровки |
| Экспортирует результат в файл | Экран экспорта из разговора: JSON / MARKDOWN / ЗВУК, системная отправка или «Сохранить в файл» | Файл сохраняется в «Загрузки» или передаётся в любое приложение |

## Ограничения обработки

1. **Без внешних сервисов, облака и удалённых вычислений.** В манифесте приложения нет разрешения `INTERNET` — отсутствие проверяется автотестом. Полный конвейер выполняется в авиарежиме, что подтверждено офлайн-прогонами на устройствах.
2. **Все модели на устройстве к моменту проверки.** Веса входят в APK-комплект и проверяются по SHA256 при запуске.
3. **Модель не подменяется готовой расшифровкой.** Расшифровка выполняется движком на любой новой записи — при проверке можно дать незнакомый файл; полный сценарий зафиксирован в демо-видео.
4. **Готовые модели и библиотеки используются** (что допускается): sherpa-onnx, GigaAM, Whisper, Nemotron, Qwen, GTCRN и RUPunct. Silero VAD исследован и использовался в прежнем движке; текущий ASR-план строится по Nemotron.
5. **Ввод и вывод по ТЗ:** экспортируемый JSON содержит ровно поля контракта из условия — `speaker_id`, `start_ms`, `end_ms`, `text` — без дополнительных полей.

## Базовый уровень

- **Работающий Android APK** — есть; подписанный релиз [v0.5.1](https://github.com/Droidje/vexto/releases/tag/v0.5.1) содержит приложение и все модели.
- **Импорт аудиофайла** — «+» → «Прикрепить файл» (см. таблицу выше).
- **Локальная LLM** — Qwen3-1.7B: выбор варианта ASR, имена спикеров, итоги и название разговора.
- **Распознавание речи** — ASR-модели по языковому маршруту и режиму; общий план строится ядром по Nemotron. На двух-ASR маршруте SDK/Qwen выбирает целый кандидат, на одно-ASR — SDK проверяет единственный. Стенограмма не заменяется резюме.
- **Автоматическая диаризация** — Nemotron 3 F32, сборка реплик из слов и интервалов, профили спикеров на ERes2Net.
- **Временные метки реплик** — представление времени в миллисекундах; фактическая точность оценивается по размеченным границам отдельно.

## Средний уровень

- **Предварительная обработка аудиосигнала** — зачем: привести любую запись к единому входу моделей. Как: декодирование любого формата в mono PCM 16 кГц, план речи по интервалам Nemotron, отдельная GTCRN-копия для ASR в QUALITY; FAST не запускает шумоподавление.
- **Фильтрация пауз и неречевых фрагментов** — ASR-план исключает области вне интервалов Nemotron с защитным контекстом; перед диаризацией длинные паузы (от 2 с, суммарно от минуты при записи длиннее пяти минут) вырезаются по энергии кадров с сохранением шкалы времени; разрез длинных кусков проходит по самому тихому кадру; это не гарантирует удаления всех неречевых звуков или слов-паразитов и не заменяет проверку полноты текста.
- **Устойчивое определение участников при смене реплик** — диаризация по полным интервалам и склейка слов с перекрытием; локальные голосовые профили ERes2Net. Подтверждено тестами на разных записях, в разных условиях и на разных устройствах (Nothing Phone 3a, realme C21, эмулятор).
- **Восстановление пунктуации** — GigaAM и Whisper расставляют знаки при распознавании. Дополнительно в настройках («Корректор») доступен RUPunct_small INT8: режимы «Откл», «Для меня», «Все спикеры»; пунктуация и регистр применяются отдельным слоем, исходный текст и экспорт не переписываются.
- **Отображение прогресса обработки** — экран обработки показывает этапы с процентами: «Готовлю модели», «Декодирую аудио», «Убираю шум», «Разделяю голоса», «Определяю язык», «Сохраняю голоса», «Распознаю речь», «Распознаю Whisper», «Сравниваю варианты», «Собираю расшифровку», «Расставляю знаки», «Определяю эмоции реплик». Обработка продолжается свёрнутой и при выключенном экране; текущий этап виден в списках и уведомлении.
- **Воспроизведение аудио с переходом к реплике** — тап по реплике запускает звук с её начала, во время воспроизведения подсвечивается текущая реплика; перемотка касанием и перетаскиванием.
- **Отображение и экспорт результата** — см. строки «Отображает расшифровку» и «Экспортирует результат» в таблице выше.

## Ultra Pro Max

- **Обработка фонового шума и некачественных записей** — GTCRN (потоковая нейросеть подавления шума) готовит отдельную копию для распознавания с аудитом выравнивания отсчётов; оригинал остаётся входом диаризации и эмоций; планировщик чанков режет длинные области речи по тихому краю. Итог: чистый вход ASR на шумных и некачественных записях.
- **Распознавание коротких реплик и перебиваний** — короткие смысловые реплики («Да», «Нет», «ок» и подобные) распознаются: короткая речь попадает в интервалы Nemotron и ASR-план с контекстом. Перебивания обрабатываются: детектор одновременной речи (замороженный WavLM Base+ с компактной головой, обученной командой на реальных записях встреч) находит существенные наложения голосов на окнах записи в режиме приоритета точности — на отложенной выборке 94,7% верных срабатываний при одной ложной тревоге на 56 окон; короткие «угу»-подтверждения были отрицательным классом обучения. Оценка выполнена на английских встречах AMI (см. [проверки](research/android-overlap.md)). Если на реплике обнаружено перебивание, на её аватаре-эмоции появляется отдельный значок, тап по нему открывает пояснение.
- **Обработка одновременной речи нескольких участников** — в работе.
- **Устойчивое распознавание при различиях в тембре и манере речи** — реализовано. Вручную проверено на 5 людях и 15+ интернет-записях в разных условиях. Две независимые ASR доступны на двух-ASR маршруте; русский после успешного LID использует один GigaAM.
- **Оптимизация использования оперативной памяти** — каждая тяжёлая стадия работает в свежем процессе `:inference`; Large и Qwen допускаются эксклюзивно, совместимые стадии могут пересекаться по CPU/RAM-бюджету; модель освобождается после своего этапа. Общий план фрагментов до 30 с строится по тихим границам (Whisper внутри видит окна до 10 с), чанки и явно пропущенные области покрывают шкалу без дыр и дублей; Whisper при сравнении использует 512 кадров контекста. Длинные записи автоматически получают быстрый профиль (без GTCRN, Whisper Small вместо Large, GigaAM CTC). Внутри ASR-стадий работают ограниченные очереди чанков. Проверка весов кешируется в памяти процесса при совпадении digest манифеста и атрибутов файлов, DFT/mel-таблицы Emo переиспользуются, у Qwen нет warmup на каждый фрагмент. Наблюдаемый бюджет приложения 2 ГБ с резервом проверен на отдельных AVD-прогонах и не включает Android OS. [Измерения](TEST_RESULTS.md).
- **Ускорение инференса за счёт аппаратных возможностей** — попытка NNAPI-backend для GigaAM-Emo при совместимом Qualcomm/MediaTek-драйвере: граф назначается ускорителю с проверкой назначения, при отсутствии совместимого устройства — автоматический fallback на CPU. Аппаратное ускорение дополняет параллельность: определитель языка работает одновременно с диаризацией, постоянные ASR-обработчики допускаются по общему CPU/RAM-бюджету, эмоции считаются фоном после публикации диалога.
- **Редактирование и повторная обработка отдельных фрагментов** — от ручного редактирования распознанного текста мы намеренно отказались: расшифровка должна оставаться объективной и не подвластной человеку, что считаем важной частью диктофона. Для повышения качества удержание реплики показывает кнопку «Перепроверить»: она заново распознаёт окно за 1,5 с до и после этой реплики и подменяет текст и эмоцию только у неё, не удаляя соседние реплики. Полная повторная обработка записи — кнопка «Расшифровать ещё раз» / «Расшифровать на устройстве» на сведениях записи; задача восстанавливается после закрытия приложения и завершается в фоне.

## Статус проверки требований

Сопоставление реализации не означает независимую приёмку всех уровней. На русском `localLlmUsed` может быть false; обязательное участие LLM демонстрируется и проверяется отдельно по конкретной операции. Детектор наложений не разделяет одновременно говорящих людей на независимые дорожки. Сводка доказанных результатов и границ — [TEST_RESULTS](TEST_RESULTS.md), [LIMITATIONS](LIMITATIONS.md).
