# Архитектура решения

Актуальное поведение `dev`, сверено с кодом 8 ноября 2026. Требования — [конспект презентации](hackathon-2026-11.md), сценарии — [продукт](product.md), измерения — [TEST_RESULTS](TEST_RESULTS.md), границы доказанного — [LIMITATIONS](LIMITATIONS.md).

## Компоненты

| Каталог | Роль |
|---|---|
| `app/` | Android UI, запись/импорт, foreground-служба обработки, плеер, локальная библиотека и экспорт |
| `engine/` | Kotlin-ядро: подготовка аудио, маршрутизация моделей, интервалы спикеров, неизменяемые ASR-кандидаты, эмоции, LLM |
| `tools/`, `scripts/` | Подготовка весов и native runtime на компьютере, упаковка APK и расчёт метрик; Python на телефоне не требуется |

## Путь от аудио до результата

1. Импорт или запись → канонический mono PCM16 WAV, 16 кГц. Оригинал сохраняется; готовый канонический WAV не ресэмплируется заново.
2. Профиль фиксируется на задание: FAST или QUALITY; AUTO выбирает FAST строго при длительности больше пяти минут. QUALITY создаёт отдельную GTCRN-копию для ASR, FAST читает оригинал.
3. Nemotron 3 F32 определяет спикеров и интервалы по оригиналу; короткий Whisper tiny LID определяет один язык записи. Это отдельная задача, а не Whisper-расшифровка. ERes2Net извлекает голосовые отпечатки в обоих режимах.
4. Ядро строит общий план ASR-чанков до 30 с по интервалам Nemotron с контекстом. Пропущенные области явно записываются в `omittedRanges`; шкала исходного файла сохраняется.
5. Распознаватели выбираются по языку и режиму, см. таблицу ниже. RAW и SHA каждого реально полученного кандидата сохраняются. SDK копирует целый проверенный вариант, LLM не переписывает стенограмму.
6. `AcousticTurnTranscript` размещает слова по интервалам Nemotron, сохраняя их границы и перекрытия. Если размещение изменило бы последовательность слов, остаётся предыдущая сборка. Времена ASR не заменяют акустические интервалы.
7. Контекстные имена, эмоции и детектор наложения дополняют результат. В FAST основной диалог публикуется до фоновых эмоций. Строгий JSON ТЗ содержит только `speaker_id`, `start_ms`, `end_ms`, `text`; имена и эмоции хранятся отдельно и доступны в Markdown.

## Языковые маршруты

| Результат LID | FAST | QUALITY | Участие Qwen в выборе ASR |
|---|---|---|---|
| Успешно определён `ru` | GigaAM v3 E2E CTC INT8 | GigaAM v3 E2E RNNT INT8 | Сравнения нет: SDK `ONE_AVAILABLE` |
| `be` или определение языка не удалось | GigaAM CTC + Whisper Small Q5_1 | GigaAM RNNT + Whisper Large v3 Q5_0 | Выбор целого кандидата; равные тексты обходят LLM |
| Другой успешно определённый язык | Whisper Small | Whisper Large | Сравнения нет: единственный ASR |

Qwen3-1.7B Q4_K_M может определить имена при наличии представлений/обращений; без свидетельств этот запрос пропускается. Резюме и автозаголовок используют Qwen отдельно от ASR; участие LLM в конкретной записи видно по артефактам соответствующей операции.

FAST выполняет один лёгкий проход. Подробности: [быстрый](architecture/fast-pipeline.md) и [качественный](architecture/quality-pipeline.md) конвейеры, [русский маршрут](architecture/russian-gigaam-only.md).

## Ресурсы и восстановление

Одна пользовательская задача обрабатывается за раз. Внутри неё работают ограниченные очереди и постоянные модельные обработчики: модель загружается один раз на жизнь обработчика. Общий планировщик допускает совместимые стадии по CPU/RAM; Large Whisper и Qwen — эксклюзивно. Worker-процессы `:inference0..3` освобождаются после завершения; передаются пути и короткие управляющие сообщения.

Наблюдаемый бюджет дерева процессов приложения — 2 000 000 000 байт с резервом 128 МиБ; Android OS в него не входит. Задание, режим и результаты чанков сохраняются с SHA: после прерывания повторяются только недостающие/невалидные этапы. [Очередь и режимы](architecture/queued-audio-modes.md), [контракты движка](architecture/quality-engine.md), [фоновые эмоции](architecture/background-fast-emotions.md), [жизненный цикл native-процессов](architecture/native-child-lifecycle.md).

## Поставка, данные и приватность

Android 9+ (API 28), ARM64 или x86_64; сборка: JDK 17, SDK/Build Tools 35, NDK 28.2.13676358, CMake 3.22.1. Поставочный APK либо согласованный комплект split APK содержит модели заранее. На устройстве они извлекаются и проверяются по SHA-256 без скачивания. Обычная разработческая `assembleDebug` требует отдельной подготовки пакета: [установка](base-version.md#установка), [engine](../engine/README.md).

Аккаунта, API и сервера нет, разрешения `INTERNET` нет. Аудио, стенограммы и SQLite-профили с эмбеддингами хранятся локально. ID спикеров в JSON локальны для записи; узнавание между записями использует отдельные UUID и ERes2Net. Ручные исправления приоритетнее автоматики.
