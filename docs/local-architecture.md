# Полностью локальная архитектура

7 ноября 2026. Android-приложение выполняет распознавание, диаризацию, хранение и сопоставление голосовых образцов на устройстве. Backend, сетевой клиент, конфигурация подключения, очередь отправки и контейнерная публикация удалены. В APK нет разрешений INTERNET и ACCESS_NETWORK_STATE.

## Данные и идентификаторы

- Аудио: приватный `files/recordings/`; сохранённые файлы не отправляются автоматически.
- Полный текст: атомарные JSON-файлы `files/transcripts/`, названия в `.title`. Исходный ASR не заменяется саммари.
- Люди: SQLite `speaker-profiles.db`, таблица `profiles` с UUID и именем.
- Подтверждённая связь: `links(recording, revision, local_id, profile_id)`, где revision — SHA-256 канонического JSON. `speaker_1` одного файла не считается тем же человеком в другом файле.
- Голос: `embeddings(recording, revision, local_id, model_id, dimension, vector, speech_ms, windows, created_at)`; нормализованный Float32-центроид финального кластера, little-endian BLOB. Сохраняется компактный центроид, а не все окна или дополнительная копия аудио.

Переименование UUID меняет отображаемое имя во всех привязанных разговорах. Удаление профиля каскадно удаляет его связи; исходные записи и JSON остаются. Векторы записи отделены от именованного профиля: при снятии связи они перестают участвовать в образцах этого человека.

Новые локальные данные не зависят от прежнего серверного рабочего пространства. Уже сохранённые аудио и JSON сохраняются на месте. Данные, существовавшие только на удалённом сервере, автоматически не импортируются; старые локальные кеши не удаляются этой миграцией.

## Голосовые профили

Движок использует существующие окна и финальные метки кластеризации. Для каждого кластера рассчитывается нормализованный взвешенный центроид. При сборке реплик голосовой вектор сопоставляется с тем же кластером, который получил `speaker_N` по первому появлению, поэтому перестановка числовых меток не меняет человека.

`model_id` включает SHA-256 точных embedding-весов, версию sherpa и версию подготовки сигнала/агрегации. Одинаковая размерность векторов сама по себе не делает их совместимыми. При смене модели нужны новые образцы; старые сохраняются отдельно и не участвуют в сравнении другой модели.

Для сходства берутся только подтверждённые привязками образцы других записей с точно тем же model_id и размерностью. Короткие образцы менее 2 с отбрасываются. На профиль учитывается не более 20 последних образцов, вес одного ограничен 30 с. Сходство — cosine score, не вероятность личности. Значение показывается в диалоге выбора, а существующая привязка остаётся выбранной до действия пользователя. Имя автоматически не назначается.

Пример: `файл A/speaker_2 → UUID Анна`, затем `файл B/speaker_1 → тот же UUID` после подтверждения. Номер speaker и исходный текст при этом не переписываются. JSON-экспорт сохраняет контракт заказчика; Markdown использует подтверждённые имена. Сохранение профиля не требует повторного ASR.

## Ограничения

Диаризация может смешать людей, и тогда её центроид тоже загрязнён. Шум, микрофон, короткие реплики и манера речи меняют сходство. Порог автоматической идентификации не калиброван; такие назначения не включены. Отдельная проверка качества между разными сессиями ещё нужна. SQLite/векторная математика покрыты JVM-тестами, а качество голоса оценивается отдельно от тестов хранения.

Модели поставляются с APK после сборочной загрузки весов. Загрузка зависимостей на компьютере разработчика не является сетевой обработкой в приложении. Пользовательский экспорт через системное меню остаётся явным действием пользователя.
