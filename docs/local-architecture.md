# Полностью локальная архитектура

7 ноября 2026. Android-приложение выполняет распознавание, диаризацию, хранение и сопоставление голосовых образцов на устройстве. Backend, сетевой клиент, конфигурация подключения, очередь отправки и контейнерная публикация удалены. В APK нет разрешений INTERNET и ACCESS_NETWORK_STATE.

## Данные и идентификаторы

- Аудио: приватный `files/recordings/`; сохранённые файлы не отправляются автоматически.
- Полный текст: атомарные JSON-файлы `files/transcripts/`, названия в `.title`. Исходный ASR не заменяется саммари.
- Люди: SQLite `speaker-profiles.db`, таблица `profiles` с UUID, именем и единственной отметкой «Я». SQLite v2 сохраняет UUID и имена при обновлении базы с v1.
- Связь спикера: `links(recording, revision, local_id, profile_id)`, где revision — SHA-256 канонического JSON без вероятностей эмоций. `speaker_1` одного файла не считается тем же человеком в другом файле. `active_transcripts` указывает на текущие версии расшифровок. Старые хеши для существующих связей и образцов переносятся при индексации.
- Голос: `embeddings(recording, revision, local_id, model_id, dimension, vector, speech_ms, windows, created_at)`; нормализованный Float32-центроид финального кластера, little-endian BLOB. Сохраняется компактный центроид, а не все окна или дополнительная копия аудио.

Переименование профиля обновляет имя во всех связанных разговорах. Объединение в одной транзакции перепривязывает все локальные ID к выбранному UUID и переносит отметку «Я». Время речи вычисляется по объединению интервалов внутри каждой записи, чтобы после объединения пересекающиеся реплики не увеличивали его дважды. Реплики хранятся в исходных расшифровках.

Новые локальные данные не зависят от прежнего серверного рабочего пространства. Уже сохранённые аудио и JSON сохраняются на месте. Данные, существовавшие только на удалённом сервере, автоматически не импортируются; старые локальные кеши не удаляются этой миграцией.

## Голосовые профили

Движок использует существующие окна и финальные метки кластеризации. Для каждого кластера рассчитывается нормализованный взвешенный центроид. При сборке реплик голосовой вектор сопоставляется с тем же кластером, который получил `speaker_N` по первому появлению, поэтому перестановка числовых меток не меняет человека.

`model_id` включает SHA-256 точных embedding-весов, версию sherpa и версию подготовки сигнала/агрегации. Одинаковая размерность векторов сама по себе не делает их совместимыми. При смене модели нужны новые образцы; старые сохраняются отдельно и не участвуют в сравнении другой модели.

Автоматический мэтчер переносит правило исследовательского скрипта межсессионных ID. Он фиксирует первый подходящий голосовой образец каждого профиля из другой активной записи и сравнивает косинусное сходство. Политика применяется только к точному ERes2Net из штатной сборки. У обоих образцов требуется не менее 5 с речи, сходство от 0,80 и отрыв от второго кандидата от 0,08. Если два локальных спикера одной записи претендуют на один UUID, автоматическое назначение отклоняется. Отсутствие уверенного совпадения создаёт отдельный UUID. Ручная привязка и «Отдельный спикер» сохраняются как явное назначение.

Например, `файл A/speaker_2 → UUID Анна`, а при уверенном совпадении `файл B/speaker_1 → тот же UUID`. JSON-экспорт сохраняет локальный номер спикера и полный исходный текст. Markdown использует имена профилей. Для старых расшифровок без сохранённого голосового образца каталог создаёт отдельные профили, которые можно объединить вручную.

В экспериментальной ветке сопоставления схема SQLite v3 сохраняет происхождение связи: `manual`, `automatic` или `pending`. Новый отдельный UUID остаётся временным (`pending`): при следующем обновлении каталога или появлении финального голосового образца выполняется повторная проверка. Она может заменить только неподтверждённую привязку к автоматическому профилю, который не отмечен «Я» и не используется другой записью. Профили самой проверяемой записи исключены из кандидатов. Неуверенный результат сохраняет временный UUID без создания новых дублей на каждом обновлении.

Ручная привязка и разделение закрепляют обе стороны исправления; переименование, отметка «Я» и ручное объединение также защищают профиль от повторного назначения. Уточнение текста движком переносит происхождение связи. Миграция v1/v2 → v3 сохраняет старые связи как `manual`, поскольку прежняя схема не позволяет доказать их происхождение. Поэтому существующие дубли не объединяются автоматически. Порог 0,80, отрыв 0,08 и первый эталон не изменены; несколько эталонов и другие модели проверяются отдельным [экспериментом](research/speaker-matching-quality.md).

Если движок заменяет собственный промежуточный текст финальным, он сохраняет связь для тех же акустических меток Nemotron. Перенос выполняется после успешной условной замены файла и не применяется к стороннему импорту.

## Экспорт расшифровки

Отдельный `ReflectExportView` следует макету Reflect 167:395. `ReflectExportController` строит ограниченный предпросмотр и готовит полный файл в IO-очереди. `RecordingExport` используется и для предпросмотра, и для файла; ограничение применяется только к входу предпросмотра. JSON сохраняет все реплики и четыре исходных поля по ТЗ; Markdown содержит имена и все четыре оценки эмоций без округления. Имена добавляются в экспорт, не переписывая сохранённые расшифровки и версии связей. Имя из импортированной расшифровки используется при создании нового профиля, но совпадение имён не связывает глобальные ID. Переименование профиля отражается в Markdown; отметка «Я» остаётся внутри приложения.

Отправка использует `FileProvider` с временным разрешением только на выбранный URI; текстовые файлы помещаются в отдельный подкаталог `cache/exports`, аудио передаётся из `files/recordings`. Сохранение через `ACTION_CREATE_DOCUMENT` остаётся доступным. Внутренние голосовые векторы и UUID профилей не экспортируются: переносимый документ описывает участников конкретной записи, не переносит локальную биометрическую базу.

## Ограничения

Диаризация может смешать людей, а шум, микрофон, короткие реплики и манера речи влияют на сходство. Порог и отрыв консервативны и пока не откалиброваны на корпусе реальных записей Android. SQLite и векторная математика покрыты JVM-тестами. Качество голосовых совпадений проверяется отдельно от хранения.

Модели поставляются с APK после сборочной загрузки весов. Загрузка зависимостей на компьютере разработчика не является сетевой обработкой в приложении. Пользовательский экспорт через системное меню остаётся явным действием пользователя.
