# Vexto: базовая версия для Nuclear IT Hack

Инструкции актуализированы 8 ноября 2026. Опубликованный релиз при проверке — [v0.5.1](https://github.com/Droidje/vexto/releases/tag/v0.5.1); `dev` может содержать более новый код. Для воспроизведения результата нужны APK и модельный манифест именно его версии.

Требования: [конспект ТЗ](hackathon-2026-11.md). Обязательный сценарий: установить APK и модели, отключить сеть, импортировать локальный файл, получить расшифровку с говорящими и временем и сохранить JSON.

## Установка

### Один APK на телефоне

Скачайте [полный `vexto-offline.apk` со всеми моделями](https://distribute.droidje.com/vexto/download/vexto-offline.apk), откройте файл в «Загрузках» и подтвердите установку Android. При запросе разрешите установку приложений из источника, которым открыли файл. Все модели находятся внутри APK. Vexto проверяет и подготавливает их при первой расшифровке без сети. Перед скачиванием освободите около 13 ГБ, чтобы поместились скачанный файл, установленное приложение и рабочие копии моделей. Скачанный APK можно удалить после установки.

Постоянная ссылка не требует учётной записи GitHub. После успешного CI в `main` полный установщик автоматически публикуется в GitHub Packages, и этот же адрес отдаёт новую сборку. Поддерживается докачка; предыдущий файл остаётся доступен при ошибке нового выпуска. APK передаётся потоком через MGG без постоянной копии на сервере. [Архитектура публикации](architecture/phone-download.md). Разделённые подписанные APK в GitHub Releases остаются альтернативой для установки через ADB.

### Установка из разделённых APK

Нужен Android 9+ с ARM64 или x86_64, около 9 ГБ свободного места на устройстве (около 13 ГБ, если APK скачаны туда же) и [Android Platform Tools](https://developer.android.com/tools/releases/platform-tools). APK содержат все веса. При первой расшифровке Vexto проверяет их и готовит рабочие файлы в своём хранилище. В манифесте приложения нет разрешения `INTERNET`.

1. Скачайте `vexto.apk`, три `vexto-models-*.apk` и `SHA256SUMS` со страницы [последнего релиза](https://github.com/Droidje/vexto/releases/latest). Хэши можно сверить командой `shasum -a 256 -c SHA256SUMS` на macOS или `sha256sum -c SHA256SUMS` на Linux.
2. Подключите устройство с USB-отладкой и выполните в папке с файлами:

   ```sh
   adb install-multiple -r vexto.apk vexto-models-1.apk vexto-models-2.apk vexto-models-3.apk
   ```

3. Отключите сеть. В Vexto: «+» → «Прикрепить файл» → WAV → синяя стрелка. После обработки откройте экспорт расшифровки, выберите JSON и «Сохранить в файл».

Для разработчиков доступна [сборка и установка модели по отдельности](../engine/README.md). В версии из Releases установка отдельных весов не требуется.

### Подготовка именованного релиза

1. Возьмите `vexto.apk` из артефакта `signed-apk` успешного main CI нужного коммита. Подготовьте [точный офлайн-пакет](../engine/README.md) по манифесту этой версии.
2. Передайте пароль подписи через переменную `VEXTO_KEYSTORE_PASSWORD` и соберите три split APK тем же ключом, что подписал базовый APK.

   ```sh
   python3 scripts/build_model_splits.py --base-apk vexto.apk --pack-dir <quality-pack> \
     --output-dir splits --android-home "$ANDROID_HOME" --keystore <keystore> \
     --notices-dir tools/model-notices
   ```

3. Поместите все четыре APK в одну папку, создайте `SHA256SUMS` командой `shasum -a 256 *.apk > SHA256SUMS`, проверьте установку на чистом устройстве и загрузите пять файлов в именованный GitHub Release. После публикации GitHub Actions переносит проверенный комплект в GitHub Packages.

Для подготовки на GitHub создайте черновик релиза с целевым SHA из `main` и подпишите/прикрепите проверенный базовый `vexto.apk`. Вручную запустите workflow `Prepare offline model APKs` на `main` с тегом черновика. Workflow скачает закреплённые исходники, воспроизведёт F32 Nemotron, сверит полный пакет и прикрепит подписанные split APK. Публикация самого релиза выполняется отдельно.

## Состав

- Запись с микрофона, импорт и прослушивание аудио, экран хода обработки, лента реплик с переходом к месту записи, локальная библиотека.
- В действиях записи доступно удаление с подтверждением: удаляются аудио, связанный разговор и его служебные данные. Глобальные профили спикеров сохраняются. Во время обработки удаление недоступно.
- Nemotron 3 F32, ERes2Net, ASR по языку/режиму и GigaAM-Emo. После успешного русского LID используется GigaAM-only; `be`/сбой LID — GigaAM + Whisper; остальные языки — Whisper-only. Qwen выбирает только между двумя различающимися сохранёнными вариантами; контекстные имена требуют свидетельств. [Маршруты](ARCHITECTURE.md#языковые-маршруты).
- Быстрый профиль (CTC/Small по языковому маршруту, один лёгкий проход без шумоподавления, эмоции в фоне) и авто-выбор: записи длиннее пяти минут обрабатываются быстро. Голосовые отпечатки ERes2Net работают в обоих профилях.
- ERes2Net и каталог глобальных ID: автоматическое сопоставление только при уверенном совпадении, ручная привязка, объединение, переименование и отметка «Я».
- Полный экспорт JSON/Markdown и исходного звука. JSON сохраняет `transcript[]` и ровно четыре поля реплики: `speaker_id`, `start_ms`, `end_ms` и `text`. Имена и вероятности эмоций доступны в приложении и в Markdown. Внутренние голосовые векторы не экспортируются.

## Проверки

- Исторический контроль ниже выполнен на ARM64 AVD Android 15 с 4 ГБ RAM и без сети. Более поздние x86_64 APK-прогоны и текущий русский FAST приведены отдельно в [TEST_RESULTS](TEST_RESULTS.md); сборка ABI и фактический инференс не отождествляются.
- Проверки исходников: `./gradlew :engine:testDebugUnitTest :app:testDebugUnitTest :app:lintDebug` после подготовки нативного runtime, `python3 -m unittest discover -s tools/benchmarks/tests -v`.
- Для измерения выберите короткий диалог с эталонным текстом. Сравните сохранённый JSON с эталоном и засеките время от запуска обработки до результата. RTF — время обработки, делённое на длительность аудио. Убедитесь, что в режиме полёта Android не оставил включённой Wi-Fi-сеть.
- При отсутствии пакета или повреждении веса приложение сообщает о необходимости установить проверенный комплект. Уже сохранённое аудио остаётся в библиотеке.

**Исторический контроль двух-ASR версии:** на Android 15 ARM64 AVD (4 ГБ RAM, авиарежим, Wi-Fi выключен) приложение импортировало 24,83 с синтетического русского диалога, расшифровало его и сохранило JSON через системный диалог. В расшифровке 4 реплики, 2 спикера и 4 оценки эмоций для каждой реплики. Оба ASR дали по 3 кандидата; Qwen выбрал вариант для каждого. Скрипт `verify_quality_job.py` подтвердил строгий четырёхпольный JSON, отдельные метаданные и целостность артефактов (`quality_success=true`).

Конвейер занял **46,03 с (RTF 1,85)**. На этом примере — **1 ошибка на 52 слова (WER 1,9%)** после приведения регистра, удаления пунктуации и замены «ё» на «е». Для одного фрагмента границы слов оценочные. Наблюдаемый суммарный RSS процессов приложения — **1,843 ГБ**, с резервом 128 МиБ — 1,977 ГБ при лимите 2,0 ГБ.

## Сверка с ТЗ

| Требование | Статус и проверка |
| --- | --- |
| Android APK, локальный импорт, работа без сети | Базовый сценарий выполнен на ARM64 AVD. Для версии из Releases модели входят в установочный комплект. |
| Локальные ASR, диаризация, LLM и метки | Выполнено на описанном двух-ASR контрольном диалоге; в текущем русском GigaAM-only LLM подключается к отдельным операциям — имена из контекста, резюме, автозаголовок. Данные остаются на Android. |
| Просмотр и экспорт по схеме ТЗ | Выполнено: исходный текст, ID говорящего и времена в миллисекундах сохранены в JSON через системный диалог. |
| Комплект материалов (слайды 20–21) | Есть APK, исходники, инструкция, архитектура, ограничения и результаты проб. Есть локальное видео экспорта; для сдачи нужен один доступный проверяющим комплект APK, моделей, отчёта и сквозного видео от импорта до экспорта. |

Из дополнительных возможностей уже есть шумоподавление, поиск тихих границ фрагментов, пунктуация в выводе ASR, прогресс обработки, переход к реплике в аудио и ограничение памяти.

Приоритет перед сдачей — установка комплекта на чистое физическое ARM64-устройство, повтор обязательного сценария без сети и проверка доступности всех материалов по ссылке. Для продвинутых сценариев отдельно проверяются длинные записи, шум и одновременная речь; NNAPI-ускорение эмоций (с fallback на CPU) и повторная обработка фрагмента («Перепроверить») реализованы.

## Ограничения

- Сходство ERes2Net и эмоции модели — оценки, а не подтверждение личности или чувств.
- Расшифровка продолжается при сворачивании. Если Android остановил процесс, Vexto продолжает задачу после открытия с последнего сохранённого результата. За раз обрабатывается одна запись. Оценка эмоций выполняется в той же задаче обработки аудио.

Подробнее: [архитектура](architecture/quality-engine.md), [локальные данные и сопоставление спикеров](local-architecture.md).

При зависании локальной передачи базового APK можно вызвать `prepare-model-release.yml` с `tag` и `base_run` успешного main CI. Runner сам перенесёт подписанный `signed-apk` в черновик релиза; SHA исходного CI должна точно совпадать с targetCommitish релиза.
