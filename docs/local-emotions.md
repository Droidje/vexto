# Локальные эмоции отдельных реплик

Решение использует исследованный [GigaAM-Emo v1 INT8 ONNX](../tools/benchmarks/android/emo/README.md), уже включённый в APK. Аудио и результаты остаются на устройстве; manifest не требует INTERNET. Установка весов из assets также работает без сети.

## Контракт

- `none` означает отсутствие `emotion_probabilities`, а не neutral. После оценки сохраняются четыре вероятности `neutral`, `joy`, `sadness`, `anger`; преобладающая эмоция вычисляется из них. Формат JSON обратно совместим.
- ASR сохраняет окончательный текст до эмоций. Application наблюдает за сохранениями sidecar (включая импорт) и на старте сверяет записи с SQLite-очередью. Очередь работает независимо от Activity через persisted JobScheduler.
- Готовые задания берутся FIFO, строки — по порядку. После каждой строки сначала атомарно обновляется sidecar, затем курсор. Если процесс погиб между этими операциями, сохранённая оценка пропускается на повторе. Завершённая запись остаётся в очереди как маркер завершения: непригодные интервалы не вызывают бесконечный повтор.
- Новая версия текста/таймкодов/спикеров или изменение файла аудио создаёт новое задание. Перед сохранением проверяются SHA-256 базовых полей транскрипта, размер и время изменения аудио; проверка и merge выполняются под общим lock. Уже имеющиеся вероятности не перезаписываются. Изменение аудио с тем же размером и mtime этим контрактом не обнаруживается; приложение хранит оригиналы как неизменяемые файлы.
- Высокоприоритетные запросы ASR/диаризации отменяют emotion batch и ждут освобождения модели/PCM. Курсор сохраняется. Ошибки повторяются с задержкой от 30 секунд до 6 часов; проблемная запись не блокирует остальные. Вытеснение не считается ошибкой.

## Модель и ограничения

На вход поступает исходное mono PCM 16 кГц без АРУ, строго внутри таймкодов реплики. Окна до 8 секунд покрывают всю реплику; слишком короткие дополняются до 200 мс, результаты усредняются с весом по фактической длительности. Модель загружается один раз на batch записи и освобождается при завершении/вытеснении. Реплика без доступных сэмплов остаётся `none`.

Нативный ONNX-вызов не прерывается посередине. Восемь секунд аудио не означают восемь секунд максимального ожидания: задержка зависит от устройства. Android также может отложить JobScheduler из-за энергосбережения или остановить работу; немедленный запуск в фоне не гарантирован. После принудительной остановки пользователем обработка продолжится при следующем открытии приложения.

Выход модели — предположение по акустике, не проверенный эмоциональный факт. Калибровка уверенности и качество на пользовательских диалогах требуют отдельной размеченной оценки; пороги уверенности не выдуманы.

## Проверки

```sh
bash scripts/fetch_models.sh
./gradlew :engine:testDebugUnitTest :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
# Android 9+, эмулятор 4096 MB; выбор устройства через ANDROID_SERIAL
./gradlew :app:connectedDebugAndroidTest
```

JVM-тесты gate проверяют вытеснение, очистку ресурсов и отмену ожидающего запроса. Instrumentation проверяет SQLite после reopen, FIFO, checkpoint, stale CAS, сохранность ручных оценок и повтор после ошибок. Device smoke test запускает настоящий packaged ONNX через очередь и проверяет сохранение вероятностей; синтетический тон проверяет исполнение, не качество распознавания эмоций.

Проверено 7 ноября 2026: 41 JVM-тест и 8 instrumentation-тестов прошли на ARM64 Android 15 / 4096 MB, 1080×2400, 420 dpi, без активной сети. В native priority test допуск foreground после запроса занял 40 мс в одном прогоне (не SLA). Отдельный запуск приложения обнаружил существующий sidecar из трёх реплик и сохранил три набора вероятностей на локальном 28-секундном речевом файле. Эта проверка использует заданные тестовые интервалы и не измеряет качество ASR или эмоций.
