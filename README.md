# vexto

vexto — Android приложение для локальной записи и предварительного прослушивания аудио.

## Запуск Android приложения

Требуются JDK 17, Android SDK Platform 35 и Build Tools 35.0.0. Приложение работает на Android 9 (API 28) и новее.

```sh
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n com.vexto.reflect/.MainActivity
```

Пять экранов используют общую систему координат макета 393 × 852, исходные иллюстрации и иконки Figma. Пропорции сохраняются при масштабировании на другие размеры экрана. Для проверки сценария откройте меню «+», выберите «Записать сейчас», разрешите микрофон, сделайте запись и завершите её кнопкой с двумя полосками. На последнем экране можно прослушать запись, сохранить её локально или поделиться файлом через Android. Из меню можно также импортировать аудиофайл.

Таймер и длительность аудио берутся из текущей записи. После первого локального сохранения «Главная» показывает список разговоров с доступными аудио. Вкладка «Записи» группирует их по датам. Из обоих списков открывается экран разговора с плеером и транскриптом. Поле поиска фильтрует доступные данные: у локальных аудио есть название, у примеров Figma также есть участники и теги. Вкладка «Спикеры» показывает пустое состояние без данных об участниках.

На экране разговора можно импортировать и экспортировать локальный JSON в формате `{"transcript":[{"speaker_id":"speaker_1","start_ms":0,"end_ms":1000,"text":"Привет"}]}`. Долгое нажатие на реплику открывает копирование, отправку текста и воспроизведение с её метки. Меню разговора позволяет изменить название, а «Настройки» сохраняют размер текста, отображение меток времени и уменьшение движения. Автоматическая расшифровка пока не подключена.

Для просмотра списков с данными из Figma запустите debug-сборку командой `adb shell am start -S -n com.vexto.reflect/.MainActivity --ez reflect_preview true`. Долгое нажатие на вкладку «Спикеры» переключает заполненное и пустое состояния в режиме предпросмотра.

Чтобы включить отправку приглашений, передайте публичную HTTPS-ссылку через свойство Gradle `reflectInviteUrl`. Кнопка передаёт её в меню отправки Android.

## Рабочий процесс

- Рабочая ветка — `dev`, релизная — `main`.
- Небольшие фиксы — напрямую в `dev`; крупные изменения — ветки `feat/<тема>` / `fix/<тема>` через MR в `dev`.
- Релиз — MR из `dev` в `main`, после слияния публикуются образы.

## CI/CD

Три пайплайна GitHub Actions (`.github/workflows/`):

1. **[CI](.github/workflows/ci.yml)** — на PR в `dev` и push в `dev`. `smoke` (целостность репо) + `test` (слот под автотесты). Если коммиты PR уже прошли CI, после слияния в `dev` прогон не повторяется (дедуп-гейт). В слоте `test` — шаблон Gradle-шагов для будущего Android-стека.
2. **[Release Checks](.github/workflows/release-checks.yml)** — на MR в `main` (обычно из `dev`). Не повторяет тесты: гейт проверяет зелёный CI на head-коммите, затем выполняются только релизные проверки (слот).
3. **[Publish](.github/workflows/publish.yml)** — только после слияния в `main`: сборка Docker-образа и публикация в GitHub Packages (`ghcr.io/<owner>/vexto`, теги `latest` и SHA). `Dockerfile` — заглушка до появления настоящего кода.

Все пайплайны можно запускать вручную (`workflow_dispatch`).
