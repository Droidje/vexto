# vexto

vexto — Android-приложение для записи и офлайн-расшифровки разговоров с разделением спикеров, таймкодами и экспортом. Аудио, текст, профили спикеров и голосовые эмбеддинги сохраняются на устройстве. Приложению не нужны аккаунт, API или развёрнутый сервер.

## Запуск Android приложения

Требуются JDK 17, Android SDK Platform 35, Build Tools 35.0.0, NDK 28.2.13676358 и CMake 3.22.1 (пакеты Android SDK). Приложение работает на Android 9 (API 28) и новее. Перед сборкой скачайте проверяемые по SHA-256 веса и зависимости [офлайн-движка](engine/README.md).

```sh
bash scripts/fetch_models.sh --aar-only
# Далее подготовьте native runtime и офлайн-пакет по engine/README.md
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n com.vexto.reflect/.MainActivity
python3 scripts/install_quality_pack.py --serial <device> --pack-dir <verified-pack>
```

Модели нужно установить один раз с компьютера. После этого Android выполняет весь инференс без интернета; отдельный сервер запускать не нужно. Если комплект отсутствует или файл не прошёл проверку целостности, приложение сообщит, что нужно установить проверенный офлайн-пакет и повторить расшифровку.

Пять экранов используют общую систему координат макета 393 × 852, исходные иллюстрации и иконки Figma. Пропорции сохраняются при масштабировании на другие размеры экрана. Для проверки сценария откройте меню «+» и выберите «Записать сейчас». На экране ожидания нажмите микрофон и разрешите запись. Во время записи волна показывает уровень звука с микрофона, а пятно на сфере движется по кругу и меняет форму. Кнопка с двумя полосками ставит запись на паузу и сохраняет время, микрофон продолжает запись. Чтобы завершить запись и открыть прослушивание, нажмите кнопку с квадратом слева от паузы или микрофона. На экране предпросмотра можно прослушать запись или сохранить её для дальнейшей расшифровки кнопкой «Расшифровать в фоне». Из меню можно также импортировать аудиофайл.

Таймер и длительность аудио берутся из текущей записи. После первого локального сохранения «Главная» показывает список разговоров с доступными аудио. Вкладка «Записи» группирует их по датам. Из «Главной» открывается лента расшифровки с аватарами, именами и таймкодами. Воспроизведение и импорт JSON доступны из меню разговора. Из «Записей» открывается карточка аудио с плеером, датой, локацией, форматом, размером и доступным битрейтом. Карточка берёт дату и координаты из метаданных файла. Если метаданных нет, показывает дату сохранения и помечает локацию как неуказанную. Поле поиска фильтрует доступные данные: у локальных аудио есть название, у примеров Figma также есть участники и теги. Вкладка «Спикеры» показывает локальный справочник людей на этом устройстве.

После записи или импорта аудио нажмите синюю стрелку, чтобы сразу начать расшифровку. Откроется экран с этапами локальной обработки и общим прогрессом. «Завершить в фоне» возвращает на «Главную», пока приложение продолжает обработку. Если остаться на экране, готовая расшифровка откроется автоматически. Для уже сохранённого разговора откройте «Главная» → разговор → «Расшифровать на устройстве». В карточке разговора можно отменить текущую расшифровку. [Офлайн-движок](engine/README.md) использует GTCRN → Nemotron3 → GigaAM v3 E2E RNNT → WhisperLargeQ5 → Qwen3-1.7B → GigaAM-Emo. Whisper и GigaAM равноправны: LLM выбирает целый исходный вариант по ID, ядро проверяет SHA и сохраняет оба оригинала. ERes2Net используется для голосовых профилей, а не кластеризации диаризации. Для каждой обработанной реплики в JSON сохраняются ID спикера, таймкоды и `emotion_probabilities` в порядке: нейтральная, радость, грусть, злость.

Лицо на аватаре показывает наиболее вероятную эмоцию реплики: зелёное — нейтральная, голубое — радость, оранжевое — грусть, красное — злость. У старых и импортированных реплик без оценок остаётся зелёное лицо.

На экране разговора также можно импортировать локальный JSON в формате `{"transcript":[{"speaker_id":"speaker_1","start_ms":0,"end_ms":1000,"text":"Привет"}]}`. Кнопка экспорта открывает отдельную страницу «Экспорт расшифровки» по [макету Figma](https://www.figma.com/design/mNJLx5uVwFRaCwwgEgrd2D/Reflect?node-id=167-395): название, длительность, число реплик и уникальных ID спикеров, переключатель JSON / MARKDOWN / ЗВУК и прокручиваемый предпросмотр. «Поделиться файлом» отправляет файл через системное меню Android, «Сохранить в файл» открывает выбор места сохранения. Системная кнопка «Назад» и стрелка возвращают к расшифровке; выбранный формат восстанавливается при пересоздании экрана. Без расшифровки доступен только звук. Долгое нажатие на реплику открывает копирование, отправку текста и воспроизведение с её метки. Меню разговора позволяет изменить название, а «Настройки» сохраняют размер текста, отображение меток времени и уменьшение движения.

JSON и Markdown экспортируют **все** реплики, локальные ID, полный текст и интервалы с точностью до миллисекунды. JSON строго следует формату задания: `speaker_id`, `start_ms`, `end_ms` и `text`. Markdown дополнительно включает доступные имена и все четыре вероятности эмоций без округления. Импорт расширенного JSON с полями `speaker_name` и `emotion_probabilities` поддерживается, метаданные остаются внутри приложения. Предпросмотр ограничен первыми 30 репликами и 12 000 символами с явной пометкой о сокращении; файл этим ограничением не обрезается. Аудио экспортируется без перекодирования. Лимит импорта JSON — 8 МиБ и 20 000 реплик; экспорт не обрезается по размеру, поэтому файл с добавленными именами и отступами может превысить лимит повторного импорта. Голосовые эмбеддинги и внутренние UUID справочника не входят в переносимую расшифровку.

Для просмотра списков с данными из Figma запустите debug-сборку командой `adb shell am start -S -n com.vexto.reflect/.MainActivity --ez reflect_preview true`. Долгое нажатие на вкладку «Спикеры» переключает заполненное и пустое состояния в режиме предпросмотра.

## Локальные профили спикеров

Вкладка «Спикеры» собирает участников всех сохранённых расшифровок. В профиле видны число разговоров и реплик, суммарное время речи и список реплик. Нажатие на реплику открывает исходный разговор и запускает звук с её таймкода.

Меню «⋯» профиля позволяет переименовать его, объединить с другим профилем и отметить «Я». При объединении все реплики переходят к выбранному профилю, а отметка «Я» переносится вместе с ними. Новая отметка заменяет предыдущую. Долгое нажатие на реплику → «Привязать спикера» позволяет исправить совпадение, выбрать другой профиль или создать отдельного спикера.


При уверенном совпадении голоса в разных записях используется один глобальный UUID. При слабом совпадении, конкурирующих кандидатах или отсутствии голосового образца создаётся отдельный профиль. Markdown включает имена профилей; JSON сохраняет локальные ID и исходный текст по контракту.

[Локальная архитектура и ограничения сопоставления голосов](docs/local-architecture.md).

## Рабочий процесс

- Рабочая ветка — `dev`, релизная — `main`.
- Небольшие фиксы — напрямую в `dev`; крупные изменения — ветки `feat/<тема>` / `fix/<тема>` через MR в `dev`.
- Релиз — MR из `dev` в `main`, перед слиянием выполняются проверки релиза.

## CI/CD

Три пайплайна GitHub Actions (`.github/workflows/`):

1. **[CI](.github/workflows/ci.yml)** — на PR в `dev` и push в `dev`. `smoke` (целостность репо) + `test` (unit-тесты утилит и Android, синтаксис shell guard и сборка APK). Если коммиты PR уже прошли CI, после слияния в `dev` прогон не повторяется (дедуп-гейт). Python-тесты работают без моделей; Android JVM-тесты и сборка проверяют локальное хранение и отсутствие сетевых разрешений. CI использует `vextoSkipNative=true`; этот проверочный APK не предназначен для инференса. Для них скачивается AAR sherpa-onnx, без весов ML.
2. **[Release Checks](.github/workflows/release-checks.yml)** — на MR в `main` (обычно из `dev`). Не повторяет тесты: гейт проверяет зелёный CI на head-коммите, затем выполняются только релизные проверки (слот).
3. **[Publish](.github/workflows/publish.yml)** — только после слияния в `main`: сборка Docker-образа и публикация в GitHub Packages (`ghcr.io/<owner>/vexto`, теги `latest` и SHA). `Dockerfile` — контейнер-заглушка: артефакт Android (APK/AAB) собирается в CI, образ — для будущих серверных компонентов.

Все пайплайны можно запускать вручную (`workflow_dispatch`).

Автотесты временно приостановлены по запросу команды; CI собирает APK. Для возврата используется repository variable `VEXTO_RUN_AUTOTESTS=true`. Аудиоядро проверяется короткими офлайн-прогонами на AVD4096MB; [инструкция и выходные артефакты](engine/README.md#проверяемые-выходные-данные-и-быстрые-прогоны).

## Проверки

Python 3.10+, только стандартная библиотека:

```text
python -m unittest discover -s tools/benchmarks/tests -v
```

Android-проверки без ML-инференса и эмулятора:

```sh
bash scripts/fetch_models.sh --aar-only
./gradlew :engine:testDebugUnitTest :app:testDebugUnitTest :app:assembleDebug
```

Проверяются SQLite после повторного открытия, версии привязок, совместимость эмбеддингов, подтверждение профилей и отсутствие сетевых разрешений в манифесте. CI также выполняет `bash -n tools/benchmarks/android_memory_guard.sh`. Для настоящей расшифровки в APK предварительно нужны все веса: `bash scripts/fetch_models.sh`.

## Настройки агентов и Android-эмулятор

- Общие правила работы — в [`AGENTS.md`](AGENTS.md); проектные навыки — в `.agents/skills/`.
- Навык [`android-emulator`](.agents/skills/android-emulator/SKILL.md) описывает запуск и проверку Android через SDK и ADB. Требуется **4 ГБ RAM**; по умолчанию эмулятор запускается без окна (`-no-window`), видимое окно открывается по запросу. Для Pixel 7 сохраняется штатное разрешение 1080 × 2400 (420 dpi), размер окна регулируется масштабом.
- На каждом компьютере отдельно установить Android SDK и совместимый AVD; проверить `emulator -list-avds` и `adb devices -l`. Навык использует существующую установку, а не пути другого разработчика.
- Личные пути и параметры можно записать в `.agents/local/android-emulator.md`; временные скриншоты, логи и резервные копии — в `.agents/work/`. Обе папки игнорируются Git. SDK и образы AVD остаются в стандартных каталогах Android вне репозитория.

## Исследование локальных моделей

[Свежие сквозные прогоны APK](docs/research/audio-pipeline-refinement.md): работа всей связки офлайн на Android4ГБ, сохранность обоих ASR, проверяемый выбор Qwen, ресурсы и строгий JSON по ТЗ. Здесь отдельно приведены фактические замеры APK и ограничения проверки точности.

Текущий выбранный профиль качества: **Nemotron 3 Diarization F32-linear + GigaAM v3 e2e RNNT + независимый Whisper Large v3 Q5_0 + Qwen3 1.7B с выбором дословных кандидатов по ID**. Семь этапов сквозного WAV-прогона выполнены на Android: для записи 21.012 с полное время составило 140.092 с, наблюдаемый пик — 1 830 166 528 байт, с резервом 128 MiB — 1 964 384 256 байт при бюджете 2 000 000 000. Android OS в этот бюджет не входит; sampling не является жёстким memory cap.

[Методология и результаты конвейера](docs/research/pipeline-2gb.md) содержат принятые и отклонённые конфигурации, проверки возвращения голосов и ограничения. Проверено две короткие записи и синтетические повторения; корпусные WER/DER, восьмиголосный сценарий, длинный ASR и перенос метрик качества на новый APK ещё требуют проверки. Метаданные сохраняют точные исходные строки, их смысловая релевантность не доказана. В Android-ядре теперь оба ASR сохраняются на равных; Qwen выбирает целый вариант через проверяемый локальный инструмент. Исследовательские цифры выше относятся к прежним standalone WAV-прогонам и не заменяют замер APK.

- [Сквозной Android runner](tools/benchmarks/run_quality_pipeline.py) создаёт свежий prompt/pool на устройстве и извлекает приватные результаты после принятия всех этапов.
- [Runner с memory guard](tools/benchmarks/bounded_android_pipeline.py) исполняет подготовленные планы моделей и сохраняет замеры, ошибки и превышения.
- [Сборка Nemotron](docs/research/nemotron-android.md) и [сборка Whisper](docs/research/whisper-android.md) фиксируют исходники, инструменты, CPU/ABI и ограничения.
- [Агрегаты измерений](docs/research/results/pipeline-2gb-measurements-2026-11-06.json), [модельные и runtime артефакты](docs/research/results/pipeline-2gb-artifacts-2026-11-06.json) публикуются без записей и расшифровок.
- [Первичное исследование 4 ГБ](docs/research/android-models-4gb.md) и [исходный probe](tools/benchmarks/probe_android_models.py) сохраняют ранний baseline.

[Быстрые сравнения на открытых записях, Emo и шумоподавление](docs/research/quick-audio-features.md): короткие AMI train/test проверки с DER, опциональный GigaAM-Emo и полная стенограмма без саммаризации.

[Русские разговоры, Community-1 и полный NeMo MSDD](docs/research/russian-diarization.md): короткие русские пробы, сравнение INT8/FP32 segmentation, отдельные результаты Android и ноутбука. Там же — прямой DER production-диаризатора из dev APK на тех же файлах.
