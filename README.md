# Vexto

Vexto — Android-диктофон с локальной расшифровкой, разделением спикеров, таймкодами и экспортом. Аудио, текст и голосовые профили остаются на устройстве; аккаунт, сервер и интернет для обработки не нужны.

## Быстрый старт

1. Для установки прямо на телефоне скачайте [полный `vexto-offline.apk` со всеми моделями](https://distribute.droidje.com/vexto/download/vexto-offline.apk). Откройте файл в «Загрузках» и подтвердите установку. Сборка включает модели. На Android нужно около 13 ГБ свободного места для установки и первого запуска.
2. Откройте Vexto → Нажмите «+» → «Прикрепить файл» или «Записать сейчас» (для быстрой записи можно зажать +). В предпросмотре нажмите синюю стрелку для немедленной обработки либо «Расшифровать в фоне», чтобы вернуться к списку (расшифровка пойдет в фоне).
3. Откройте готовый разговор, нажмите значок «Поделиться» в верхней панели и экспортируйте JSON (в формате ТЗ) или Markdown (с именами и эмоциями реплик)
4. Исследуйте другие функции приложения: [Дополнительные функции](docs/features.md) — что добавили поверх ТЗ и зачем.

В настройках доступны «Авто», «Быстрый» и «Качественный». Авто выбирает FAST строго для записи длиннее пяти минут. FAST не использует GTCRN и не запускает повторный тяжёлый проход; основной диалог доступен до фоновой оценки эмоций. ERes2Net работает в обоих режимах. Таймкоды задаёт Nemotron, а не распознаватели текста.

После успешного определения `ru` текст распознаёт **только GigaAM**: CTC в FAST, RNNT в QUALITY. Whisper tiny остаётся коротким определителем языка. Для `be` и при сбое LID используются две ASR: GigaAM + Whisper (Small в FAST, Large в QUALITY); Qwen выбирает целый сохранённый вариант, если тексты различаются. Остальные определённые языки идут через один Whisper. RAW всех реально запущенных ASR сохраняются; отсутствующего второго результата на русском нет. [Текущая архитектура](docs/ARCHITECTURE.md), [русский маршрут](docs/architecture/russian-gigaam-only.md), [очереди](docs/architecture/queued-audio-modes.md).

Qwen3-1.7B может определить имена при наличии представлений/обращений, создать резюме или название отдельной операцией. Вызов LLM не обязателен для каждой расшифровки: `localLlmUsed` может быть false. Модель не заменяет полный текст саммари и не переписывает ASR-кандидатов.

Подготовка звука исключает промежуточный PCM-файл и повторный ресэмплинг готовых 16 кГц; для остальных частот доступен SIMD-фильтр. [Описание и короткий замер на Android](docs/architecture/audio-preparation.md).

## Возможности

**Core** — уровни ТЗ «средний» и «Ultra Pro Max»:

- Шумоподавление GTCRN и фильтрация пауз и неречевых фрагментов
- Устойчивое определение участников: диаризация Nemotron и локальные голосовые профили
- Пунктуация при распознавании плюс опциональный корректор RUPunct
- Прогресс обработки по этапам, продолжение в фоне и после закрытия приложения
- Плеер с переходом к реплике по таймкоду
- Экспорт: JSON строго по контракту ТЗ, Markdown с именами и эмоциями, звук
- Распознавание коротких ответов; полнота короткой речи и подавление звуков-паразитов зависят от записи
- Детектор перебиваний — собственная ML-модель со значком на реплике
- Устойчивость к тембру и манере речи (5 человек команды и 15+ записей из интернета)
- Наблюдаемый бюджет приложения 2 ГБ с резервом; для эмоций возможен NNAPI-backend с CPU fallback
- Повторное распознавание фрагмента кнопкой «Перепроверить»

**Другие** — самое полезное поверх ТЗ:

- Узнавание людей между разговорами по голосовым отпечаткам
- Вкладки «Записи» и «Разговоры», поиск по тексту расшифровок
- ИИ-итоги разговора и автозаголовки от локальной LLM
- Режим записи «Звонок» (Android 10+) и «Записать сейчас»
- Определение языка записи: 99 языков, собственная компактная модель
- Обученная голова детектора перебиваний и собственное преобразование Whisper tiny для определения языка без нового обучения
- Отметка «Вы» и статистика времени речи участников

Установщик автоматически публикуется после успешного CI в `main`; [адрес скачивания](https://distribute.droidje.com/vexto/download/vexto-offline.apk) остаётся прежним. [Как устроена публикация](docs/architecture/phone-download.md).

## Сборка из исходников

Требуются JDK 17, Android SDK/Build Tools 35, NDK 28.2.13676358 и CMake 3.22.1. Android 9+ (API 28), ARM64/x86_64. Сначала подготовьте native runtime и проверенный пакет по [engine/README](engine/README.md).

```sh
bash scripts/fetch_models.sh --aar-only
# Подготовка native runtime и весов — по engine/README.md
bash gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
python3 scripts/install_quality_pack.py --serial <device> --pack-dir <verified-pack>
```

Это разработческая сборка: пакет устанавливается отдельно с компьютера. Поставочный offline APK/согласованные split APK уже содержат модели; Android не скачивает их при запуске. [Установка](docs/base-version.md#установка).

## Проверки

Python 3.10+, только стандартная библиотека:

```text
python -m unittest discover -s tools/benchmarks/tests -v
```

Android-проверки без ML-инференса и эмулятора:

```sh
bash scripts/fetch_models.sh --aar-only
bash gradlew -PvextoSkipNative=true :engine:testDebugUnitTest :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

Проверяются SQLite после повторного открытия, версии привязок, совместимость эмбеддингов, подтверждение профилей и отсутствие сетевых разрешений в манифесте. Для расшифровки нужны нативный APK и [офлайн-пакет](docs/base-version.md#установка).

Конвейер проверен вручную на Nothing Phone 3a и realme C21; воспроизводимые измерения — в [TEST_RESULTS](docs/TEST_RESULTS.md).

## Исследование локальных моделей

[Русские аудиофайлы](testdata/audio/ru/README.md) включены в Git: пять FLEURS-записей с ASR-текстами, пять двухголосых RINCO-фрагментов с исходными Voice/Text-аннотациями, RTTM и JSON, а также интервью на 31:48 без эталонов для ручной проверки. Лицензии и протоколы приведены рядом с файлами.

[Сводка измерений](docs/TEST_RESULTS.md) отделяет текущий русский FAST от исторических двух-ASR прогонов. На Vexto_3 4 ГБ файл 346,048 с обработан за 132,374 с с Emo, основной диалог наблюдался примерно через 84,4 с, пик RSS — 1 341 997 056 байт. `localLlmUsed=false`, Whisper-чанков 0. Старые 140,092 с на 21,012 с относятся к прежней standalone-конфигурации, не текущему APK.

[Десять синтетических записей через production FAST](docs/research/synthetic-diarization-2026-11-08.md): ivkond WER 8,94%, BookMix DER 8,86%. [Аудио и разметка](testdata/audio/ru/synthetic-20261108/README.md).

[История исследования бюджета](docs/research/pipeline-2gb.md) и [сквозные прогоны 7 ноября](docs/research/audio-pipeline-refinement.md) сохраняют условия, SHA и ограничения. Неизменяемые RAW есть у реально запущенных источников; Qwen сравнивает только различающиеся пары. Android OS не входит в бюджет RSS, sampling не является жёстким cap.

- [Сквозной Android runner](tools/benchmarks/run_quality_pipeline.py) создаёт свежий prompt/pool на устройстве и извлекает приватные результаты после принятия всех этапов.
- [Runner с memory guard](tools/benchmarks/bounded_android_pipeline.py) исполняет подготовленные планы моделей и сохраняет замеры, ошибки и превышения.
- [Сборка Nemotron](docs/research/nemotron-android.md) и [сборка Whisper](docs/research/whisper-android.md) фиксируют исходники, инструменты, CPU/ABI и ограничения.
- [Агрегаты измерений](docs/research/results/pipeline-2gb-measurements-2026-11-06.json), [модельные и runtime артефакты](docs/research/results/pipeline-2gb-artifacts-2026-11-06.json) публикуются без записей и расшифровок.
- [Первичное исследование 4 ГБ](docs/research/android-models-4gb.md) и [исходный probe](tools/benchmarks/probe_android_models.py) сохраняют ранний baseline.

[Быстрые сравнения на открытых записях, Emo и шумоподавление](docs/research/quick-audio-features.md): короткие AMI train/test проверки с DER, опциональный GigaAM-Emo и полная стенограмма без саммаризации.

[Русские разговоры, Community-1 и полный NeMo MSDD](docs/research/russian-diarization.md): короткие русские пробы, сравнение INT8/FP32 segmentation, отдельные результаты Android и ноутбука. Там же — прямой DER production-диаризатора из dev APK на тех же файлах.

В быстром и качественном режимах Qwen может определить имена спикеров по представлениям и обращениям в диалоге: максимум один дополнительный запрос на запись с лимитом 10 секунд, без повторной загрузки уже работающей LLM. Неясные имена остаются «Спикер N», ручные имена имеют приоритет. [Подробности](docs/architecture/context-speaker-names.md).

В быстром режиме готовый диалог открывается до определения эмоций. GigaAM-Emo продолжает работу в фоне, внизу экрана видна малозаметная надпись «эмоции обрабатываются». После завершения оценки добавляются к тем же репликам без изменения текста, спикеров или таймкодов. Можно читать, слушать и экспортировать диалог, пока эта стадия выполняется. [Подробности](docs/architecture/background-fast-emotions.md).

## Оптимизация

Отдельные Android-прогоны укладывались в наблюдаемый бюджет приложения 2 ГБ с резервом; оптимизации и их условия ([все исследования и замеры](docs/research/optimization.md)):

- Каждая тяжёлая модель — в отдельном процессе `:inference` и выгружается после своего этапа; Large и Qwen эксклюзивны, совместимые стадии могут пересекаться по CPU/RAM-бюджету; учитывается сумма RSS процессов UID.
- Канонический WAV пишется напрямую, готовые 16 кГц не проходят ресемплер, для остальных частот — SIMD-фильтр (ARM64 NEON / x86_64 SSE2): подготовка аудио до 1,54× быстрее.
- Определитель языка — собственное преобразование Whisper tiny без нового обучения (102,8 → 23,3 МБ), работает параллельно с диаризацией, а не после неё.
- Длинные паузы вырезаются перед диаризацией по энергии кадров (−26% на измеренной записи); на длинных записях диаризация публикует стабильный префикс, и ASR не ждёт конца всей записи.
- Для русского языка после определения языка работает одна ASR GigaAM вместо двух — в отдельных прогонах 346-секундного файла получено 132 с против 476 с (примерно в 3,6 раза быстрее).
- Для эмоций реализован NNAPI-backend с CPU fallback; в быстром режиме эмоции считаются в фоне после публикации диалога.
- Переиспользуются DFT/mel-таблицы и кеш проверки весов; WAV-чанки создаются по требованию (−33% хранилища), голосовые отпечатки читают окна прямо из исходного WAV без полной копии.

## Ограничения

**Минимальные системные требования:** Android 9 (API 28) и новее, ARM64 или x86_64, от 4 ГБ ОЗУ, около 13 ГБ свободного места для установки. Сеть не нужна: все модели внутри APK, разрешение `INTERNET` в приложении отсутствует.

**Скорость.** Весь инференс выполняется локально на CPU телефона — это цена полной приватности без облака и аккаунтов. Для ускорения мы используем множество методов оптимизации и NPU (NNAPI-backend реализован для эмоций с CPU fallback). Для записей длиннее пяти минут автоматически включается быстрый профиль с лёгкими моделями.

**Перебивания.** Сейчас обрабатывается сам факт перебивания: реплика получает значок и пояснение, что одновременная речь может снизить точность. Полноценное разделение одновременной речи на источники — «кто именно что сказал» при наложении голосов — пока не реализовано.

**ИИ-итоги.** Малая локальная LLM (Qwen3-1.7B) иногда не очень точно формулирует саммари по диалогу.

**Эмоции.** Распознаются четыре основные эмоции: нейтральная, радость, грусть, злость.

**Узнавание спикеров.** Если акустические условия сильно различаются (другой микрофон, шум, дистанция), один и тот же человек из разных диалогов не всегда объединяется системой в одного спикера. Такой профиль можно объединить вручную — исправление сохраняется.

**Точность распознавания и диаризации.** Модели могут ошибаться в словах, именах и спикерах, меняя смысл; важные фразы следует сверять со звуком. WER/DER и ограничения — в [результатах тестов](docs/TEST_RESULTS.md). Если реплика распознана плохо, её всегда можно пересчитать кнопкой «Перепроверить» (удержание реплики) — заново распознаётся только она.
