# vexto

vexto — Android-приложение для записи и офлайн-расшифровки разговоров с разделением спикеров, таймкодами и экспортом. Аудио и текст сохраняются на устройстве. Серверную синхронизацию можно подключить в настройках.

## Запуск Android приложения

Требуются JDK 17, Android SDK Platform 35 и Build Tools 35.0.0. Приложение работает на Android 9 (API 28) и новее. Перед сборкой скачайте проверяемые по SHA-256 веса и AAR для [офлайн-движка](engine/README.md).

```sh
bash scripts/fetch_models.sh
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n com.vexto.reflect/.MainActivity
```

Пять экранов используют общую систему координат макета 393 × 852, исходные иллюстрации и иконки Figma. Пропорции сохраняются при масштабировании на другие размеры экрана. Для проверки сценария откройте меню «+» и выберите «Записать сейчас». На экране ожидания нажмите микрофон и разрешите запись. Во время записи волна показывает уровень звука с микрофона, а пятно на сфере движется по кругу и меняет форму. Кнопка с двумя полосками ставит запись на паузу и сохраняет время, микрофон продолжает запись. Чтобы завершить запись и открыть прослушивание, нажмите кнопку с квадратом слева от паузы или микрофона. На экране предпросмотра можно прослушать запись или сохранить её для дальнейшей расшифровки кнопкой «Расшифровать в фоне». Из меню можно также импортировать аудиофайл.

Таймер и длительность аудио берутся из текущей записи. После первого локального сохранения «Главная» показывает список разговоров с доступными аудио. Вкладка «Записи» группирует их по датам. Из «Главной» открывается лента расшифровки с аватарами, именами и таймкодами. Воспроизведение и импорт JSON доступны из меню разговора. Из «Записей» открывается карточка аудио с плеером, датой, локацией, форматом, размером и доступным битрейтом. Карточка берёт дату и координаты из метаданных файла. Если метаданных нет, показывает дату сохранения и помечает локацию как неуказанную. Поле поиска фильтрует доступные данные: у локальных аудио есть название, у примеров Figma также есть участники и теги. При подключении сервера вкладка «Спикеры» показывает справочник рабочего пространства.

После записи или импорта аудио нажмите синюю стрелку, чтобы сразу начать расшифровку. Для уже сохранённого разговора откройте «Главная» → разговор → «Расшифровать на устройстве». Экран показывает этап обработки и позволяет её отменить. [Офлайн-движок](engine/README.md) использует GigaAM v3 RNNT, Silero VAD и диаризацию на ERes2Net. Готовые реплики сохраняются с ID спикеров и таймкодами.

На экране разговора также можно импортировать локальный JSON в формате `{"transcript":[{"speaker_id":"speaker_1","start_ms":0,"end_ms":1000,"text":"Привет"}]}`. Кнопка «Поделиться» открывает экспорт аудиофайла, а при наличии реплик также JSON и Markdown с именами спикеров и таймкодами. Долгое нажатие на реплику открывает копирование, отправку текста и воспроизведение с её метки. Меню разговора позволяет изменить название, а «Настройки» сохраняют размер текста, отображение меток времени и уменьшение движения.

Для просмотра списков с данными из Figma запустите debug-сборку командой `adb shell am start -S -n com.vexto.reflect/.MainActivity --ez reflect_preview true`. Долгое нажатие на вкладку «Спикеры» переключает заполненное и пустое состояния в режиме предпросмотра.

Чтобы включить отправку приглашений, передайте публичную HTTPS-ссылку через свойство Gradle `reflectInviteUrl`. Кнопка передаёт её в меню отправки Android.

## Сервер и синхронизация

[Инструкция по запуску API](backend/README.md) описывает настройку токенов рабочих пространств, хранилище и команды проверки. Сервер хранит аудиофайлы, метаданные, версии расшифровок и справочник спикеров. Android выполняет распознавание на устройстве и передаёт готовый результат через API. Обновите API вместе с приложением, чтобы при автоматической отправке сохранилась уже существующая серверная расшифровка.

В Android откройте «Настройки» → «Подключение к серверу», введите базовый URL и токен рабочего пространства. Для Android Emulator в debug-сборке можно использовать `http://10.0.2.2:8000` при запуске сервера на компьютере. Для обычного подключения используйте HTTPS. Не передавайте токен в аргументах сборки и не добавляйте его в Git.

- Новые записи, результаты офлайн-движка и импортированные расшифровки сначала сохраняются на устройстве. При подключённом сервере отправка повторяется после временных сетевых сбоев. Ранее сохранённую запись можно поставить в очередь через «Отправить запись на сервер» в её меню. Сохранённая локально расшифровка отправляется вместе с записью.
- При открытии локальной записи Android загружает её актуальную расшифровку из рабочего пространства, если она доступна. Список аудио на устройстве по-прежнему основан на локально сохранённых файлах.
- Во вкладке «Спикеры» можно добавить, переименовать или удалить спикера. Долгое нажатие на реплику → «Привязать спикера» связывает её локальный ID со спикером из справочника для данной версии расшифровки. Исходные таймкоды, реплики и локальные ID сохраняются.

## Рабочий процесс

- Рабочая ветка — `dev`, релизная — `main`.
- Небольшие фиксы — напрямую в `dev`; крупные изменения — ветки `feat/<тема>` / `fix/<тема>` через MR в `dev`.
- Релиз — MR из `dev` в `main`, после слияния публикуются образы.

## CI/CD

Три пайплайна GitHub Actions (`.github/workflows/`):

1. **[CI](.github/workflows/ci.yml)** — на PR в `dev` и push в `dev`. `smoke` (целостность репо) + `test` (unit-тесты утилит модельного конвейера и синтаксис shell guard). Если коммиты PR уже прошли CI, после слияния в `dev` прогон не повторяется (дедуп-гейт). Тесты работают на Python 3.12 без скачивания моделей и запуска Android.
2. **[Release Checks](.github/workflows/release-checks.yml)** — на MR в `main` (обычно из `dev`). Не повторяет тесты: гейт проверяет зелёный CI на head-коммите, затем выполняются только релизные проверки (слот).
3. **[Publish](.github/workflows/publish.yml)** — только после слияния в `main`: сборка Docker-образа и публикация в GitHub Packages (`ghcr.io/<owner>/vexto`, теги `latest` и SHA). Workflow использует корневой `Dockerfile`-заглушку. Для сборки сервера используется [`backend/Dockerfile`](backend/Dockerfile).

Все пайплайны можно запускать вручную (`workflow_dispatch`).

## Проверки

Python 3.10+, только стандартная библиотека:

```text
python -m unittest discover -s tools/benchmarks/tests -v
```

CI дополнительно выполняет `bash -n tools/benchmarks/android_memory_guard.sh`. Для локальной проверки Android выполните `./gradlew :app:assembleDebug :app:lintDebug`. Команда тестов API приведена в [руководстве сервера](backend/README.md#docker-и-проверки).

## Настройки агентов и Android-эмулятор

- Общие правила работы — в [`AGENTS.md`](AGENTS.md); проектные навыки — в `.agents/skills/`.
- Навык [`android-emulator`](.agents/skills/android-emulator/SKILL.md) описывает запуск и проверку Android через SDK и ADB. Требуется **4 ГБ RAM**; по умолчанию эмулятор запускается без окна (`-no-window`), видимое окно открывается по запросу. Для Pixel 7 сохраняется штатное разрешение 1080 × 2400 (420 dpi), размер окна регулируется масштабом.
- На каждом компьютере отдельно установить Android SDK и совместимый AVD; проверить `emulator -list-avds` и `adb devices -l`. Навык использует существующую установку, а не пути другого разработчика.
- Личные пути и параметры можно записать в `.agents/local/android-emulator.md`; временные скриншоты, логи и резервные копии — в `.agents/work/`. Обе папки игнорируются Git. SDK и образы AVD остаются в стандартных каталогах Android вне репозитория.

## Исследование локальных моделей

Текущий выбранный профиль качества: **Nemotron 3 Diarization F32-linear + GigaAM v3 e2e RNNT + независимый Whisper Large v3 Q5_0 + Qwen3 1.7B с выбором дословных кандидатов по ID**. Семь этапов сквозного WAV-прогона выполнены на Android: для записи 21.012 с полное время составило 140.092 с, наблюдаемый пик — 1 830 166 528 байт, с резервом 128 MiB — 1 964 384 256 байт при бюджете 2 000 000 000. Android OS в этот бюджет не входит; sampling не является жёстким memory cap.

[Методология и результаты конвейера](docs/research/pipeline-2gb.md) содержат принятые и отклонённые конфигурации, проверки возвращения голосов и ограничения. Проверено две короткие записи и синтетические повторения; корпусные WER/DER, восьмиголосный сценарий, длинный ASR и интеграция модельного конвейера в APK ещё требуют проверки. Метаданные сохраняют точные исходные строки, их смысловая релевантность не доказана. Whisper остаётся отдельной альтернативой и не переписывает автоматически GigaAM.

- [Сквозной Android runner](tools/benchmarks/run_quality_pipeline.py) создаёт свежий prompt/pool на устройстве и извлекает приватные результаты после принятия всех этапов.
- [Runner с memory guard](tools/benchmarks/bounded_android_pipeline.py) исполняет подготовленные планы моделей и сохраняет замеры, ошибки и превышения.
- [Сборка Nemotron](docs/research/nemotron-android.md) и [сборка Whisper](docs/research/whisper-android.md) фиксируют исходники, инструменты, CPU/ABI и ограничения.
- [Агрегаты измерений](docs/research/results/pipeline-2gb-measurements-2026-11-06.json), [модельные и runtime артефакты](docs/research/results/pipeline-2gb-artifacts-2026-11-06.json) публикуются без записей и расшифровок.
- [Первичное исследование 4 ГБ](docs/research/android-models-4gb.md) и [исходный probe](tools/benchmarks/probe_android_models.py) сохраняют ранний baseline.

[Быстрые сравнения на открытых записях, Emo и шумоподавление](docs/research/quick-audio-features.md): короткие AMI train/test проверки с DER, опциональный GigaAM-Emo и полная стенограмма без саммаризации.

[Русские разговоры, Community-1 и полный NeMo MSDD](docs/research/russian-diarization.md): короткие русские пробы, сравнение INT8/FP32 segmentation, отдельные результаты Android и ноутбука.
