# vexto

vexto — Android-приложение для записи и офлайн-расшифровки разговоров с разделением спикеров, таймкодами и экспортом. Аудио, текст, профили спикеров и голосовые эмбеддинги сохраняются на устройстве. Приложению не нужны аккаунт, API или развёрнутый сервер.

## Быстрый старт

1. Для установки прямо на телефоне скачайте `vexto-offline.apk` из успешной [сборки установщика](https://github.com/Droidje/vexto/actions/workflows/phone-apk.yml). Откройте файл в «Загрузках» и подтвердите установку. Сборка включает модели. На Android нужно около 12 ГБ свободного места для установки и первого запуска.
2. Откройте Vexto → «+» → «Прикрепить файл» или «Записать сейчас». В предпросмотре нажмите синюю стрелку для немедленной обработки либо «Расшифровать в фоне», чтобы вернуться к списку.
3. Откройте готовый разговор. Нажмите «Поделиться», выберите JSON или Markdown и сохраните файл.

В «Настройках» выберите режим обработки: «Авто», «Быстрый» или «Качественный». Авто включает быстрый режим для записей длиннее пяти минут. В нём Whisper Small и GigaAM CTC сначала обрабатывают всю речь; расхождения, наложения, пропуски и подозрительные повторы отправляются на дополнительный проход Whisper Large / GigaAM RNNT. Шумоподавление отключено, а Emo работает в фоне после готовности текста. Голосовые отпечатки извлекаются в обоих режимах для узнавания спикеров между разговорами. Точные совпадения обходят Qwen, остальные варианты сравниваются через локальный инструмент. В качественном режиме остаются Whisper Large, GigaAM RNNT и GTCRN. Оба режима работают локально; таймкоды задаёт Nemotron. Выбранный целый ASR-вариант используется в JSON; оба RAW сохраняются. Подробности: [адаптивное ядро](docs/architecture/adaptive-audio-core.md), [очередь и режимы обработки](docs/architecture/queued-audio-modes.md).

Ссылка на APK из Actions действует три дня после сборки. [Инструкция установки](docs/base-version.md#установка) описывает также подписанные APK из Releases и установку через ADB.

## Сборка и запуск из исходников

Требуются JDK 17, Android SDK Platform 35, Build Tools 35.0.0, NDK 28.2.13676358 и CMake 3.22.1 (пакеты Android SDK). Приложение работает на Android 9 (API 28) и новее. Перед сборкой скачайте проверяемые по SHA-256 веса и зависимости [офлайн-движка](engine/README.md).

```sh
bash scripts/fetch_models.sh --aar-only
# Далее подготовьте native runtime и офлайн-пакет по engine/README.md
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n com.vexto.reflect/.MainActivity
python3 scripts/install_quality_pack.py --serial <device> --pack-dir <verified-pack>
```

Для этой сборки из исходников модели нужно установить один раз с компьютера. После этого Android выполняет весь инференс без интернета; отдельный сервер запускать не нужно. Если комплект отсутствует или файл не прошёл проверку целостности, приложение сообщит, что нужно установить проверенный офлайн-пакет и повторить расшифровку.

Пять экранов используют общую систему координат макета 393 × 852, исходные иллюстрации и иконки Figma. Пропорции сохраняются при масштабировании на другие размеры экрана. Для проверки сценария откройте меню «+» и выберите «Записать сейчас». На экране ожидания нажмите микрофон или большую сферу и разрешите запись. Повторное нажатие на сферу ставит запись на паузу или продолжает её. Во время записи волна показывает уровень звука с микрофона, а пятно на сфере движется по кругу и меняет форму. Кнопка с двумя полосками ставит запись на паузу и сохраняет время, микрофон продолжает запись. Чтобы завершить запись и открыть прослушивание, нажмите кнопку с квадратом слева от паузы или микрофона. На экране предпросмотра можно прослушать запись или запустить расшифровку кнопкой «Расшифровать в фоне» и вернуться к списку. Из меню можно также импортировать аудиофайл.

Вкладки и вложенные экраны перелистываются по горизонтали. При переходе через несколько вкладок видны все страницы между ними. Нижняя навигация, меню добавления и плавающие панели размывают контент под собой. На Android 12 и новее используется аппаратное размытие, на Android 9–11 — программное. Настройка «Уменьшить движение» и системное отключение анимаций убирают переходы и орбиту сферы. Волна продолжает показывать уровень микрофона. Переключатель уменьшения движения плавно показывает своё состояние в обоих режимах, если системные анимации включены.

Таймер и длительность аудио берутся из текущей записи. Волна в предпросмотре строится из аудио до двух минут; для более длинных или недоступных для декодирования файлов показана полоска воспроизведения. После первого локального сохранения «Главная» показывает вкладку «Разговоры» с поиском по номеру, участникам и расшифровке. У разговора свой номер «Разговор №m», связанный с исходным аудио. Вкладка «Записи» группирует записи по датам. Нажатие на запись открывает сведения об аудиофайле. Кнопка под сведениями переводит к готовой расшифровке со спикерами, таймкодами и воспроизведением. В списках записей и разговоров за сегодня видно время, за другие дни — дату и время. Из «Главной» открывается лента расшифровки с аватарами, именами и таймкодами. Касание или перетаскивание по волне перематывает аудио в предпросмотре, карточке записи и разговоре. В разговоре лента прокручивается к выбранной реплике, в том числе на паузе. Во время воспроизведения касание реплики перематывает к её началу. Плеер подсвечивает текущую реплику и ведёт ленту вслед за звуком. Импорт JSON доступен из меню разговора. Из «Записей» открывается карточка аудио с плеером, датой, локацией, форматом, размером и доступным битрейтом. Карточка берёт дату и координаты из метаданных файла. Если метаданных нет, показывает дату сохранения и помечает локацию как неуказанную. Библиотека использует только сохранённые на устройстве данные. После появления расшифровки в «Главной» виден фрагмент текста, а в «Записях» — статус и участники. Вкладка «Спикеры» показывает локальный справочник людей на этом устройстве.

В разговоре с готовой расшифровкой нажмите значок с искрами в нижней панели. Локальная Qwen выделяет суть разговора, его итог и важные факты. Длинный разговор обрабатывается по частям, затем модель объединяет результаты. Панель показывает выполненные шаги и примерное оставшееся время. Крестик и значок скрывают панель. Готовое резюме открывается вместе с разговором. При замене текста или обновлении формата резюме его можно создать заново.

Новый разговор получает номер. Когда приложение открыто и движок свободен, Qwen один раз пробует подобрать короткое название по расшифровке. Если модель уже загружена для резюме, Vexto может использовать её сразу. Ручное название задаётся в меню разговора и отключает автозаголовок. В нижней панели доступны настройки чтения и удаление разговора с подтверждением. Аудиозапись и её экспорт остаются в «Записях». В карточке спикера карандаш рядом с именем открывает переименование.

Vexto использует иконку из макета и отображается с заглавной буквы в Android. При завершившейся неудачной расшифровке разговор предлагает «Расшифровать ещё раз». Этот статус сохраняется при переоткрытии.

В меню «+» доступен режим «Звонок» для Android 10 и новее. После включения микрофона и системного подтверждения Vexto смешивает микрофон с доступным звуком приложений. Фоновая служба продолжает запись при сворачивании, в уведомлении доступны пауза и завершение. Файл сохраняется локально в WAV. Если Android остановил процесс, при следующем открытии приложение восстанавливает сохранённый фрагмент; для нового захвата потребуется повторное системное разрешение.

Android допускает захват воспроизведения MEDIA, GAME и UNKNOWN, если приложение-источник разрешило запись. Обычная телефония и потоки VOICE_COMMUNICATION этим API не захватываются. Во время звонка Android также может ограничить доступ другого приложения к микрофону. Поэтому наличие режима не гарантирует запись голоса собеседника во всех звонилках и конференциях. [Ограничения Android](https://developer.android.com/media/platform/av-capture).

Долгое нажатие «+» на главной сразу открывает запись и включает микрофон. В библиотеке синий процент показывает общий ход обработки. Экран «Обработать сейчас» разделяет реальный пайплайн на пять последовательных групп. Из карточки готовой записи кнопка «Перейти к транскрипту» открывает связанный разговор. Во время обработки на её месте отображается «Выполняется…».

Поиск разговоров сначала проверяет названия и участников. Если совпадений нет, нажмите «Искать в разговорах», чтобы увидеть цитаты из текста. Нажатие на цитату открывает разговор у соответствующей реплики. Новое имя разговора обновляется и внутри страницы, и в списке.

В разделе настроек «Корректор» доступен RUPunct_small INT8. Модель и токенизатор включены в APK и работают без сети. По умолчанию корректор выключен, можно включить для себя или всех спикеров. Пунктуация и регистр отображаются отдельным слоем, исходный текст и экспорт сохраняются. Корректор уступает место распознаванию и Qwen.

После записи или импорта аудио нажмите синюю стрелку, чтобы сразу начать расшифровку. Откроется экран с этапами локальной обработки. Процент меняется по мере выполнения этапов движка. При обработке в фоне текущий этап и его процент видны в списках и карточке разговора. Vexto обрабатывает одну запись за раз, в том числе когда приложение свёрнуто или экран выключен. При разрешённых уведомлениях Android показывает текущий этап. Если закрыть Vexto из списка недавних или принудительно остановить приложение, после открытия задача продолжится с последнего сохранённого результата. Прерванный этап без промежуточных результатов повторится. «Завершить в фоне» возвращает на «Главную», пока приложение продолжает обработку. Если остаться на экране, готовая расшифровка откроется автоматически. Для уже сохранённого разговора откройте «Главная» → разговор → «Расшифровать на устройстве». В карточке разговора можно отменить текущую расшифровку. [Офлайн-движок](engine/README.md) использует GTCRN → Nemotron3 и одновременно с диаризацией определяет язык записи. Русский и белорусский идут дальше без изменений: GigaAM v3 E2E RNNT → WhisperLargeQ5 → Qwen3-1.7B → GigaAM-Emo. Whisper и GigaAM равноправны: LLM выбирает целый исходный вариант по ID, ядро проверяет SHA и сохраняет оба оригинала. Для другого языка эта запись распознаётся только Whisper. GigaAM E2E и Whisper расставляют знаки при распознавании. Итог сохраняет пунктуацию выбранного ASR, отдельного прохода редактирования текста нет. ERes2Net используется для голосовых профилей, а не кластеризации диаризации. Для каждой обработанной реплики в JSON сохраняются ID спикера, таймкоды и `emotion_probabilities` в порядке: нейтральная, радость, грусть, злость.

Лицо на аватаре показывает наиболее вероятную эмоцию реплики: зелёное — нейтральная, голубое — радость, оранжевое — грусть, красное — злость. Если оценки ещё нет, приложение показывает отдельное серое лицо; зелёное означает, что модель выбрала нейтральную эмоцию.

На экране разговора также можно импортировать локальный JSON в формате `{"transcript":[{"speaker_id":"speaker_1","start_ms":0,"end_ms":1000,"text":"Привет"}]}`. Кнопка экспорта открывает отдельную страницу «Экспорт расшифровки» по [макету Figma](https://www.figma.com/design/mNJLx5uVwFRaCwwgEgrd2D/Reflect?node-id=167-395): название, длительность, число реплик и уникальных ID спикеров, переключатель JSON / MARKDOWN / ЗВУК и прокручиваемый предпросмотр. «Поделиться файлом» отправляет файл через системное меню Android, «Сохранить в файл» открывает выбор места сохранения. Системная кнопка «Назад» и стрелка возвращают к расшифровке; выбранный формат восстанавливается при пересоздании экрана. Без расшифровки доступен только звук. Долгое нажатие на реплику показывает поверх ленты «Перепроверить» и «Ещё». «Перепроверить» заново прогоняет кусок за 1,5 с до реплики и 1,5 с после неё в качественном режиме и подменяет текст и эмоцию только этой реплики, если результат непустой и не поглощает соседние. Соседние реплики не удаляются. Одинаковое слово на стыке остаётся только в перепроверенной реплике. «Ещё» открывает копирование, отправку текста, воспроизведение с метки и привязку спикера. Название исходного аудио можно изменить в карточке записи, а «Настройки» сохраняют размер текста, отображение меток времени и уменьшение движения.

JSON и Markdown экспортируют **все** реплики, локальные ID, текст и интервалы с точностью до миллисекунды. Фонетические знаки остаются в сохранённой расшифровке. На экране, при копировании реплики и в обоих файлах экспорта они заменяются обычной записью: ə, ɐ, ɜ и ˀ → «э», ɯ → «м», скобки только со вдохом ɥ → «вдох», жест `#пеньк-пеньк#` → «пеньк пеньк». JSON строго следует формату задания: `speaker_id`, `start_ms`, `end_ms` и `text`. Markdown дополнительно включает доступные имена и все четыре вероятности эмоций без округления. Импорт расширенного JSON с полями `speaker_name` и `emotion_probabilities` поддерживается, метаданные остаются внутри приложения. Предпросмотр ограничен первыми 30 репликами и 12 000 символами с явной пометкой о сокращении; файл этим ограничением не обрезается. Аудио экспортируется без перекодирования. Лимит импорта JSON — 8 МиБ и 20 000 реплик; экспорт не обрезается по размеру, поэтому файл с добавленными именами и отступами может превысить лимит повторного импорта. Голосовые эмбеддинги и внутренние UUID справочника не входят в переносимую расшифровку. Импорт аудио ограничен 1 ГиБ, расшифровка — четырьмя часами декодированного аудио.

## Локальные профили спикеров

Вкладка «Спикеры» собирает участников всех сохранённых расшифровок. Собственный профиль выделен бирюзовым и подписан «Вы» в списке и на странице профиля. Плашка рядом с именем показывает число полных минут речи по всем записям; пересекающиеся интервалы одного профиля внутри записи считаются один раз. В профиле видны число разговоров и реплик, суммарное время речи и список реплик. Нажатие на реплику открывает исходный разговор и запускает звук с её таймкода.

Меню «⋯» профиля позволяет переименовать его, объединить с другим профилем и отметить «Я». При объединении все реплики переходят к выбранному профилю, а отметка «Я» переносится вместе с ними. Новая отметка заменяет предыдущую. Долгое нажатие на реплику → «Привязать спикера» позволяет исправить совпадение, выбрать другой профиль или создать отдельного спикера.


При уверенном совпадении голоса в разных записях используется один глобальный UUID. При слабом совпадении, конкурирующих кандидатах или отсутствии голосового образца создаётся временный отдельный профиль. После появления образца неподтверждённая привязка проверяется повторно; ручные исправления сохраняются. Markdown включает имена профилей; JSON сохраняет локальные ID. В файле экспорта фонетические знаки уже заменены, сохранённая расшифровка хранит их как есть.

[Локальная архитектура и ограничения сопоставления голосов](docs/local-architecture.md).

## Рабочий процесс

- Рабочая ветка — `dev`, релизная — `main`.
- Небольшие фиксы — напрямую в `dev`; крупные изменения — ветки `feat/<тема>` / `fix/<тема>` через MR в `dev`.
- Релиз — MR из `dev` в `main`, перед слиянием выполняются проверки релиза.

## CI/CD

[Android CI/CD](.github/workflows/ci.yml) проверяет PR и push в `dev` и `main`. В каждом прогоне запускаются Python-тесты, Android JVM-тесты, lint и проверочная сборка без нативного движка. Отчёты доступны в артефактах Actions. PR в `main` дополнительно собирает полноценный APK с нативным движком для ARM64 и x86_64 и проверяет его состав.

После обновления `main` Actions подписывает проверенный APK и публикует его в GitHub Packages. Версии для установки с моделями выходят отдельными именованными релизами.

- [Установка одним файлом на телефоне](docs/base-version.md#один-apk-на-телефоне) с уже встроенными моделями.
- [Релиз v0.5.0](https://github.com/Droidje/vexto/releases/tag/v0.5.0) содержит один подписанный комплект с приложением и всеми моделями. Установка одной командой описана в [инструкции](docs/base-version.md#установка).
- [GitHub Packages](https://github.com/Droidje/vexto/pkgs/container/vexto-android) хранит проверочный APK из main по SHA и `nightly`, а полный комплект релиза — по тегам `v0.5.0` и `latest`. Для копирования файлов из образа используйте `docker pull`, `docker create <image> /unused` и `docker cp`.

Публикация использует Actions secrets `VEXTO_ANDROID_KEYSTORE` (PKCS#12 в Base64, алиас `vexto`) и `VEXTO_ANDROID_KEYSTORE_PASSWORD`. Для обновлений поверх предыдущих релизных сборок нужен тот же ключ. Старые debug-сборки подписаны другим ключом. Удаление debug-сборки удаляет её локальные данные.

## Проверки

Python 3.10+, только стандартная библиотека:

```text
python -m unittest discover -s tools/benchmarks/tests -v
```

Android-проверки без ML-инференса и эмулятора:

```sh
bash scripts/fetch_models.sh --aar-only
bash gradlew -PvextoSkipNative=true :engine:testDebugUnitTest :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

Проверяются SQLite после повторного открытия, версии привязок, совместимость эмбеддингов, подтверждение профилей и отсутствие сетевых разрешений в манифесте. CI также выполняет `bash -n tools/benchmarks/android_memory_guard.sh`. Для расшифровки нужны нативный APK и [офлайн-пакет](docs/base-version.md#установка).

Сценарий расшифровки верифицирован на реальных устройствах: Nothing Phone 3a (8 ГБ ОЗУ, 128 ГБ) и realme C21 (4 ГБ ОЗУ, 64 ГБ) вместе с эмулятором 4 ГБ. Качество расшифровки на всех трёх совпадает в рамках погрешности. По скорости Nothing сопоставим с эмулятором (качественный режим на 3% быстрее, быстрый на 7–8%), realme C21 медленнее примерно на 35% в быстром и на 16–19% в качественном режимах. Разница объясняется железом: эмулятору достались мощные ядра хоста, но не хватило памяти; у Nothing ядра не мощнее, но памяти больше, что полезно быстрому режиму; у realme памяти столько же, но ядра слабее. Nothing — средняя модель прошлого года и показывает хороший результат, поэтому приложение уверенно работает на средних телефонах и остаётся рабочим на слабых. realme C21 — бюджетная модель возраста около пяти с половиной лет, взятая как нижняя граница поддержки: минимальное устройство, на котором система ещё работоспособна.

## Настройки агентов и Android-эмулятор

- Общие правила работы — в [`AGENTS.md`](AGENTS.md); проектные навыки — в `.agents/skills/`.
- Навык [`android-emulator`](.agents/skills/android-emulator/SKILL.md) описывает запуск и проверку Android через SDK и ADB. Требуется **4 ГБ RAM**; по умолчанию эмулятор запускается без окна (`-no-window`), видимое окно открывается по запросу. Для Pixel 7 сохраняется штатное разрешение 1080 × 2400 (420 dpi), размер окна регулируется масштабом.
- На каждом компьютере отдельно установить Android SDK и совместимый AVD; проверить `emulator -list-avds` и `adb devices -l`. Навык использует существующую установку, а не пути другого разработчика.
- Личные пути и параметры можно записать в `.agents/local/android-emulator.md`; временные скриншоты, логи и резервные копии — в `.agents/work/`. Обе папки игнорируются Git. SDK и образы AVD остаются в стандартных каталогах Android вне репозитория.

## Исследование локальных моделей

[Русские аудиофайлы](testdata/audio/ru/README.md) включены в Git: пять FLEURS-записей с ASR-текстами, пять двухголосых RINCO-фрагментов с исходными Voice/Text-аннотациями, RTTM и JSON, а также интервью на31:48 без эталонов для ручной проверки. Лицензии и протоколы приведены рядом с файлами.

[Свежие сквозные прогоны APK](docs/research/audio-pipeline-refinement.md): работа всей связки офлайн на Android4ГБ, сохранность обоих ASR, проверяемый выбор Qwen, ресурсы и строгий JSON по ТЗ. Здесь отдельно приведены фактические замеры APK и ограничения проверки точности.

Текущий выбранный профиль качества: **Nemotron 3 Diarization F32-linear + GigaAM v3 e2e RNNT + независимый Whisper Large v3 Q5_0 + Qwen3 1.7B с выбором дословных кандидатов по ID**. Семь этапов сквозного WAV-прогона выполнены на Android: для записи 21.012 с полное время составило 140.092 с, наблюдаемый пик — 1 830 166 528 байт, с резервом 128 MiB — 1 964 384 256 байт при бюджете 2 000 000 000. Android OS в этот бюджет не входит; sampling не является жёстким memory cap.

[Методология и результаты конвейера](docs/research/pipeline-2gb.md) содержат принятые и отклонённые конфигурации, проверки возвращения голосов и ограничения. Проверено две короткие записи и синтетические повторения; корпусные WER/DER, восьмиголосный сценарий, длинный ASR и перенос метрик качества на новый APK ещё требуют проверки. Метаданные сохраняют точные исходные строки, их смысловая релевантность не доказана. В Android-ядре теперь оба ASR сохраняются на равных; Qwen выбирает целый вариант через проверяемый локальный инструмент. Исследовательские цифры выше относятся к прежним standalone WAV-прогонам и не заменяют замер APK.

- [Сквозной Android runner](tools/benchmarks/run_quality_pipeline.py) создаёт свежий prompt/pool на устройстве и извлекает приватные результаты после принятия всех этапов.
- [Runner с memory guard](tools/benchmarks/bounded_android_pipeline.py) исполняет подготовленные планы моделей и сохраняет замеры, ошибки и превышения.
- [Сборка Nemotron](docs/research/nemotron-android.md) и [сборка Whisper](docs/research/whisper-android.md) фиксируют исходники, инструменты, CPU/ABI и ограничения.
- [Агрегаты измерений](docs/research/results/pipeline-2gb-measurements-2026-11-06.json), [модельные и runtime артефакты](docs/research/results/pipeline-2gb-artifacts-2026-11-06.json) публикуются без записей и расшифровок.
- [Первичное исследование 4 ГБ](docs/research/android-models-4gb.md) и [исходный probe](tools/benchmarks/probe_android_models.py) сохраняют ранний baseline.

[Быстрые сравнения на открытых записях, Emo и шумоподавление](docs/research/quick-audio-features.md): короткие AMI train/test проверки с DER, опциональный GigaAM-Emo и полная стенограмма без саммаризации.

[Русские разговоры, Community-1 и полный NeMo MSDD](docs/research/russian-diarization.md): короткие русские пробы, сравнение INT8/FP32 segmentation, отдельные результаты Android и ноутбука. Там же — прямой DER production-диаризатора из dev APK на тех же файлах.

В быстром и качественном режимах Qwen может определить имена спикеров по представлениям и обращениям в диалоге: максимум один дополнительный запрос на запись с лимитом 10 секунд, без повторной загрузки уже работающей LLM. Неясные имена остаются «Спикер N», ручные имена имеют приоритет. [Подробности](docs/architecture/context-speaker-names.md).

В быстром режиме готовый диалог открывается до определения эмоций. GigaAM-Emo продолжает работу в фоне, внизу экрана видна малозаметная надпись «эмоции обрабатываются». После завершения оценки добавляются к тем же репликам без изменения текста, спикеров или таймкодов. Можно читать, слушать и экспортировать диалог, пока эта стадия выполняется. [Подробности](docs/architecture/background-fast-emotions.md).
